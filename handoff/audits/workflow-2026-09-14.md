## Bottom line (one paragraph)

The machinery **mostly fits** a solo browser-only project — the two-worktree
Planner/Builder split, the migration ask-gate, the `./plan` closeout automation, and
the failure-case-criterion discipline all earn their keep, and the project has been
actively *shrinking* imported cruft (START-HERE deleted, cloud preview deploy replaced
by Tailscale, push grant narrowed). The real problem is **not cruft, it is drift and
volume**: the same operational rules are stated in full in three, four, five places, so
when one changes the others rot — and that is exactly what happened to the merge gate.
DEC-035 (planning merges on its own testing) is now the live rule and `DECISIONS.md` +
`CLAUDE.md` + `WORKFLOW.md`'s Branching section were reconciled to it, but **at least
eight spots still teach the old DEC-009 "Emilio uses it before merge" gate** — six of
them inside `PLANNING.md` alone, plus all of `CLOSEOUT.md`'s preamble and one half of
`WORKFLOW.md` that contradicts its own other half. `DECISIONS.md` at 937 lines is the
single largest liability. The fix direction (not this audit's job) is consolidation:
one home per rule, everything else a cross-reference.

## 3. Fit-to-project

Classified one of EARNS-KEEP / COPIED-CRUFT / NEEDS-ADAPTATION. Honest headline: the
machinery is **mostly EARNS-KEEP**; genuine copied-cruft is thin because the project has
been retiring it as it's found.

**EARNS-KEEP**
- **Two-worktree Planner/Builder split** (`rules/WORKFLOW.md:178-208`, DEC-005). One
  human running two CC terminals against one repo is the literal setup; the isolation is
  what makes `plan publish`'s planning→main merge conflict-free (DEC-043 explains why the
  guard is not arbitrary, `:889-896`). Serves a solo browser-only app directly.
- **Migration ask-gate #2** (`CLAUDE.md:191-198`, `rules/WORKFLOW.md:164-176`, DEC-032).
  The single most-justified piece: `localStorage['workout-mvp-v8']` is the user's real
  irreplaceable history, no backend, no undo (`README.md:30-31`). "Treat a migration like
  surgery" is correctly sized for *this* data model, not imported.
- **`./plan closeout` automation** (`rules/CLOSEOUT.md:22-49`). Collapses an 8-step merge
  ritual into one idempotent, re-runnable command — exactly right for a solo dev who
  can't rely on a second person to catch a half-done merge.
- **Failure-case-criterion discipline** (`rules/WORKFLOW.md:80-92`). "A green happy path
  is the weakest evidence" earns its keep in a data-integrity app.
- **`[PLANNER]`/`[BUILDER]` tags** (`PLANNING.md:14-20`, `CLAUDE.md:16-20`). Cheap; solves
  a real "which terminal am I reading" problem.
- **The audit procedure itself** (`rules/AUDIT.md`). Read-only, diagnose-don't-treat,
  dated series — a sound fit for a codebase with no CI to catch drift.

**NEEDS-ADAPTATION**
- **Independent-reviewer subagent** (`log/DECISIONS.md:712-726`, `PLANNING.md:232-242`).
  Right *intent* (a second look before an autonomous merge of shared code), but the
  framing imports code-reviewer culture — "restore the lost **second perspective**,"
  "the **author grading itself**." For a solo app the mechanism (spawn a fresh-context
  subagent to read `git diff main..reqN`) is cheap and defensible; the *ceremony* around
  it (three paragraphs, "not a standing role," "planning-spawned not code-CC-spawned") is
  heavier than the payoff. Keep the tool, cut the doctrine.
- **6-status readiness taxonomy** (`rules/WORKFLOW.md:35-42`): `READY / NEEDS DECISIONS /
  BLOCKED ON / BUILT AND MERGED / SHELVED / WITHDRAWN`. Ticket-tracker-flavored for a
  solo backlog where `git` already knows most of it (the doc admits this at `:44`, "a
  hand-kept copy of something git already knows"). Lightweight, but more states than one
  person needs.
- **Two-section (Technical + Workflow) report mandate** (`CLAUDE.md:137-142`). Reasonable,
  but combined with `reports/req-NN.md` + terminal report + `DEC-`/`L-` + SHIPPED line,
  the per-req paperwork is thick for reversible UI tweaks.

**COPIED-CRUFT** (encodes an assumption this project lacks — quoted)
- **"Per-branch preview deploy (cloud)"** (`work/BACKLOG.md:174-181`): "Infra; sizeable
  (**CI/hosting** decision)." Assumes a CI/cloud-preview pipeline the project doesn't have
  and — per DEC-041 — decided it *doesn't want* (Tailscale `vite preview` replaced it for
  Emilio). Cruft, already ~80% retired; only the unmarked backlog stub remains.
- **The DEC-009 human-use "QA/PO" gate** language surviving in `CLOSEOUT.md:3-8`,
  `WORKFLOW.md:159-161`, `PLANNING.md:44-48`. Its shape — a person must "use it" before
  anything merges — is a team-QA/release assumption (L-006 even calls planning "QA + PO,"
  `log/LESSONS.md:78`). DEC-035 already dissolved it for a solo dev who delegates the
  merge to his own agent's testing; the residue is both stale (bucket 2) and mis-shaped
  for the one-user model.

The migration ask-gate is emphatically **not** cruft despite touching "persisted data,"
because the persisted data is real and irreversible — the brief flagged it to scrutinize;
it survives scrutiny.

## 4. Gaps

- **No backup discipline for the irreplaceable store.** The entire workflow rests on
  "`localStorage` has no backup and no undo" (`CLAUDE.md:192-193`,
  `rules/WORKFLOW.md:164-166`) yet nowhere instructs Emilio to *periodically export* his
  own real history. The app has Export (DEC-004, req-01 banner) but the workflow never
  makes "keep a backup" a standing rule — the one catastrophic single-user failure mode is
  unmitigated by process. [inferred] from absence across all machinery docs.
- **No pruning rule for the append-only logs.** `DECISIONS.md` is 937 lines and
  append-only by mandate (`log/DECISIONS.md:2`); the digest (req-67, `:18-49`) helps
  navigation but nothing caps or archives the body. `PLANNING.md:115-116` caps `NOW.md` at
  50 lines but no equivalent exists for DECISIONS/LESSONS. Growth is unbounded by design.
- **No cadence for the workflow-consolidation itself.** `NOW.md:14-16` raises exactly this
  ("~2,600 lines of workflow machinery … worth deciding whether to prune") as an open
  question, but there is no periodic "re-fit the workflow to the project" step — the audit
  (`rules/AUDIT.md`) targets *code*, not the machinery. This audit exists only because
  Emilio asked ad hoc.
- **`reference/` is near-empty** (`schema.md` + a stub README; `handoff/README.md:52-54`
  says "added as needed"). Migration behaviour — the highest-risk area — lives mostly in
  prose across README/DEC-032/DEC-035 rather than one authoritative `reference/migration.md`.
  A gap given how much machinery orbits the migration gate. [inferred] from the dir listing.
- **No definition of "done" for a design-unsettled (live) lane req.** DEC-037's
  Emilio+CC-live lane (`log/DECISIONS.md:778-780`) folds work in "when the report arrives"
  (`PLANNING.md:379-387`) but never says what closes that lane — how a live iteration
  becomes a merged, `DEC-`-recorded thing. The mechanical lanes are specified to the step;
  the taste lane is under-specified.

## 5. Volume / verbosity

Machinery ≈ 2,393 lines. Concentration and where length pays (or doesn't):

- **`DECISIONS.md` — 937 lines (39% of the total).** Mostly **load-bearing**: it's an
  append-only ledger and DECs are the source of truth the digest points at. But it carries
  dead weight it shouldn't need to re-read every skim: DEC-018/019 (`:375-394`) are marked
  dead/superseded yet fully present; several DECs bury a "Built (req-NN): …" paragraph
  (DEC-022 `:450-452`, DEC-023 `:480-486`, DEC-024 `:519-538`) that duplicates what the req
  doc + SHIPPED already hold. The digest (`:18-49`) is the model to lean on — the archive
  below it is where verbosity hides. **Verdict: structurally justified, ~150 lines of
  build-narrative could live in reports/SHIPPED instead.**
- **`PLANNING.md` — 442 lines.** The **worst length-not-paying-off** offender. It restates
  the loop (also in WORKFLOW), the /clear finding (also in DEC-009/037), the merge gate
  (also in DEC-035/CLAUDE), the re-check-by-kind rule *twice within itself* (`:85-89` and
  `:425-442`), and the git-command list *twice* (`:38-63` and `:304-331`). Roughly
  **80-120 lines are restatement or self-duplication.** Sections `:299-331` ("You run the
  git yourself") and `:38-63` are near-identical.
- **`WORKFLOW.md` — 291 lines.** Middling. Load-bearing on readiness/failure-criteria
  (`:30-92`); redundant on the loop (`:12-29`, also in PLANNING) and the migration gate
  (`:164-176`, also in CLAUDE). ~40 lines duplicative.
- **`CLAUDE.md` — 232 lines.** Mostly **earns it** — it loads every Builder turn, so being
  self-contained is the point. The one soft spot: `:200-221` restates the merge model that
  `:113-120` already gave. ~15 lines trimmable.
- **`CLOSEOUT.md` — 73, `AUDIT.md` — 136, `handoff/README.md` — 67, `NOW.md` — 43,
  `LESSONS.md` — 172.** These **pay for their length**. AUDIT is a procedure that's run
  verbatim; LESSONS is dense, each entry a real bug with a named cause (L-005/L-007/L-010
  are exactly the "measured, not recalled" evidence the project prizes); NOW is disciplined
  under its own 50-line cap. CLOSEOUT's only waste is the stale preamble (bucket 2), not
  length.

**Where length is NOT paying:** PLANNING.md's internal duplication and the merge-gate
restatements scattered across 5 docs. **Where it IS load-bearing:** the DEC archive as a
ledger, CLAUDE.md's self-containment, LESSONS' evidence, the AUDIT/CLOSEOUT procedures.
The 2,393 lines aren't inherently too many for a workflow this deliberate — but an
estimated **250-350 of them are restatement** that consolidation-to-single-home would
remove without losing a fact.
