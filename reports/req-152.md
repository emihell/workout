## Technical

**QA-1 — Back after leaving a workout (DEC-081, option A).**
- Cause: `go(p, { replace: true })` only rewrote the in-app visit stack. The browser change was always
  `location.hash = …`, which pushes. So every `replace: true` site still stacked a browser entry.
- Fix: `go()` now calls `location.replace(<href without hash>#<path>)` when `replace` is set (`src/route.js`).
- The three ways out to Today now pass `{ replace: true }`:
  - `finish.jsx` Save
  - `auto-complete.jsx` commit
  - `helpers.jsx` `abandonWorkout`

**Sites whose device/browser Back changed.** Each one used to leave an entry behind and now replaces it:
- `item.jsx:99, 110, 319, 331` — done / planned-done / skip → overview
- `item.jsx:559` → log
- `overview.jsx:212` → current item
- `replace.jsx:31, 49`
- `setup.jsx:59`
- `Exercises.jsx:174, 253, 326, 337` — after create / pick
- `workout-actions.js:66` — resume inside the same workout (`replace` only when already in it)
- The 3 new exits above

**QA-2 — rest pill vs the top row.**
- The pill keeps its position (fixed, top-centre) and its size.
- The 5 screens that host it (item log / done / set edit, overview, finish) carry `.ui-screen--rest`. That class
  always reserves `s2 + --ui-restpill-h + s2` = 62px above the first row, not only while resting, so nothing jumps
  each set. The new token `--ui-restpill-h` is 28 + 2×8 + 2 = 46px.
- Found while measuring: at 320px the pill wrapped to two lines (60px tall), because `left: 50%` caps a fixed
  box's shrink-to-fit width at half the viewport. This was pre-existing. Added `white-space: nowrap`, so the pill
  is 168×46 at every width.
- Cost: the top of those 5 screens sits about 30px lower than before (the first link moved from y 40 to y 70).

**QA-3 — Add set kg blank.**
- Cause: for an exercise with history, the kg seed is last time's set at the same index (`historySetPrefill`).
  An added 5th set has no index 4 in history, so it gets `''`. The in-session carry (DEC-002) was only computed
  for no-history exercises (`carryFor` returned null whenever `last` existed).
- Fix: `setLogSeed` / `initialSetFields` take an optional `historyHasSet`. When it is `false`, the carry (the last
  non-skipped working set logged this session) supplies the kg.
- New `historyHasSetAt` (`storage.js`) provides the flag. `carryFor` moved from `item.jsx` into
  `workout-log.js` as a pure `carryForSet`, so it can be tested.
- When `historyHasSet` is absent, behaviour is unchanged. The existing "carry ignored with history" tests stand
  untouched.
- Choice: I did **not** add the spec's "else the appended suggested weight" fallback. The live seed has never read
  `suggestedWeights` (history, carry and override only), and adding it would be a new prefill source. With nothing
  logged this session, an added set stays blank. Bodyweight stays blank.

**QA-4 — History detail "skipped".** `historyGroupMeta(item, count, { skipped })`. `detail.jsx` passes the count of
non-skipped sets (the header already counted this way, req-116), plus `skipped` when every set was skipped. Wording
kept: `WU set · skipped`, with role tag and WU marker unchanged. One visible side effect: a partly skipped
exercise now shows its **logged** count (2 of 4 skipped → "2 sets"; it used to say 4). That is the spec's criterion.

## Workflow

- **Planner's premise for (A) is off:** the in-app ‹ Back is a fixed link (`<Back to=…>`, `shared.jsx:43`), not
  the visit stack. As far as I found, the visit stack isn't read by any Back. (A) still holds on its own merits
  (every Back after these sites lands on a live screen), but DEC-081's "why" should be corrected.
- **Remaining, not fixed (out of this criterion):** after Save, the **second** Back reaches an item page pushed
  earlier in the workout (for example `…/item/<id>/log`), and it renders "Not found." because no workout is active
  any more. Only the first Back was in scope. A fix would redirect a dead in-workout route to the finished
  workout's Done view. Candidate for the backlog.
- **Rode along:** the pill's `white-space: nowrap` (the 320px wrap was pre-existing and would have broken the
  reserve). QA-3's fix also covers a normal set beyond last time's count (a routine that grew since last time), not
  only Add set. It is the same code path.
- **Spec item not built:** the "else the appended suggested weight" fallback (see QA-3).
- **Not passed:** Apply writing `[0]` for cardio. I didn't touch or reach that path.
- **Test edits:** none to existing tests.
