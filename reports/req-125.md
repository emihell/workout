# req-125 — typed-but-not-completed set values survive navigation and reload

## Technical

- `src/workout-log.js` — pure draft helpers: `setDraftKey(item, setType, workIndex)` → `<itemKey>|<wu|work>|<i>`
  (a warm-up is always 0); `setDraftFor(workout, key)` (null unless the key matches; a non-object / keyless draft is
  ignored); `setDraftFromForm`; `setDraftFromLoggedSet` (Previous: the same values `restoreFromLoggedSet` gave, effort
  mapped via `rpeOptionValue`); `formFieldsWithDraft({ seed, draft, weighted, durationTarget })` (the draft laid over the
  chain seed field by field, kg gated by `weighted`); `clearSetDraftPatch(workout, key)` (`{ setDraft: undefined }` only
  when the key matches, so the saved JSON has no field); `createSetDraftWriter` (300 ms trailing debounce, `flush(sync)`,
  `cancel()`, injectable timers). `finishedState` also strips `setDraft`.
- `src/ui/index.jsx` `SetLogForm` — optional `onChange(values)` called from each edit (weight / reps / effort /
  duration), not from an effect, so a mount or remount writes nothing. `initial*` props are still read only by `useState`.
- `src/views/workout/item.jsx` — the `restore` component state is removed. `setSeedKey = setDraftKey(...)` and it also
  keys the form. The draft is read once per key (`draftSnap`, updated during render when `setSeedKey` changes) and
  becomes `formInit`. `seed` stays the comparison base for `nextSeedOverrides`. Complete and Skip cancel any pending
  write and merge `clearSetDraftPatch` into the same `completeSet` patch. Previous writes `setDraftFromLoggedSet` for
  the set it returns to. `useSetDraftWriter` flushes on unmount and, through `flushSync`, on `visibilitychange:hidden`
  and `pagehide`. `flushSync` is needed because `saveState` runs inside the state updater, which React would otherwise
  defer until after the page has gone.
- Persisted data: one optional field on `activeWorkout`, no schema bump, no bulk rewrite. `migrateState` keeps it
  through the `...workout` spread (tested with a real reload round trip). A workout saved before this change loads
  without the field.

**Dependents**
- req-83 / req-108 `nextSeedOverrides`: it is still passed the chain `seed`. Holds (unit test).
- req-106 `setPreview`: unchanged, still shows the seed. Holds.
- req-116 `anythingLogged`: reads `sets` only. Holds.
- req-117: `canRemoveAddedSet` is unchanged. `removeSet` no longer resets `restore` because that state is gone. A draft
  for the current set survives Remove set, which is correct because its key still matches.
- `initialSetFields`, `setLogSeed` and `initialDurationFor` with `fromRestore`: the code is kept and its tests still
  pass. The app now always passes `fromRestore: false`. **No existing test was edited.**

## Workflow

- **(unconfirmed)** The start-of-exercise preview shows the seed, not the draft. The spec marked this; it was built
  as specced.
- **(unconfirmed)** When you re-complete a set after Previous, the req-83 comparison base is now the chain seed, not
  that set's own logged values. This follows the spec's point 4. The effect: if you logged set 1 at 45 (seed 40), went
  Previous, then completed it again at 45, the override still ends up at 45, as before.
- Choices not in the spec:
  - The debounce is 300 ms.
  - The key separator is `|`.
  - A draft is not cleared when a *different* set is logged; it is ignored and then stripped at finish.
  - Leaving a set mid-typing and completing another exercise keeps the first exercise's draft.
- Not verified: a real iOS background-reload. It was simulated through `pagehide` in headless Chrome only.
- Follow-up: the `fromRestore`/`restore` inputs of `initialSetFields`/`setLogSeed`/`initialDurationFor` are now unused by
  the app (tests only). Removing them later would need a test edit.
- Latent: the draft is read on mount. If a screen ever navigates straight from one log screen to another without an
  intermediate screen, the unmount flush could land after the new mount has read. No such path exists today: every
  exit goes through the overview or the editor.
