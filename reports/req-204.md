# req-204 — Home: next 3 workouts above, today at the bottom

Branch `req-204` (off `main` 48149e0). Code commits `ed01774` and `50f6b60` (a CSS fix).

## Technical

**What changed**
- **`schedule.js`:** new pure `upcomingWorkouts(schedule, routines, today, n = 3)` → `[{dateKey, week, weekday, slots}]`, nearest first, today excluded. Only slots whose routine is present and not archived count, and a date with 2 slots is one row. `weekRows` is deleted: its only caller was Home's "This week".
- **Home (`views/Today.jsx`):** the order is title (+ "Week x of y" in a longer loop) → "Workouts ›" → **"Coming up"** (3 rows, furthest first, hidden when empty) → today's block (unchanged) → the stale Continue row → "History ›". A row reads `Fri, Oct 16 · Push / Pull ›` and has no Start. `WeekRow`, `HistoryPeekRow`, the recent peek and "No history yet." are gone.
- **Dated day link:** each row links `/schedule/:week/:weekday?date=YYYY-MM-DD&from=%2F`.
  - `route.js` `parseRoute` reads `date` on `schedule-day` only, and only in YYYY-MM-DD shape.
  - `withFrom` appends `&from=` when the path already has a query. Before this, a path with a `?` produced a broken URL, so nothing relied on the old behaviour.
  - `schedule-day.js` `dayScreenDate` uses the link's date when it is that path's weekday and loop week. Otherwise it falls back to req-203's `homeDayDate`, so a link without a date behaves as before.
  - `ScheduleDay`'s `here` carries `?date=`, so `childLink` chains (add, slot, a done row's History) Back to the same dated screen. App's key includes the date.
- **Bottom-align (`ui.css`):** `.ui-screen--home` is a flex column whose min-height is the viewport minus `.ui-main`'s padding and the body's 8+8px UA margin. `.ui-home-bottom` (Coming up → History) has `margin-top: auto`. `.ui-row--today` is deleted (unused).
- No schema change. Nothing writes stored data.

**Choices the spec left open**
- **The date mechanism** is a `?date=` query plus `withFrom` learning `&`. req-203 avoided this because of `childLink`; making `withFrom` query-aware solved it.
- **A link date that doesn't fit** the path's weekday or loop week is ignored, and the screen falls back to the no-date rule.
- **Only the lower part is bottom-aligned.** The title and "Workouts ›" stay at the top, and the free space opens between "Workouts ›" and "Coming up" (see the screenshot).
- **"No history yet." was removed** with the peek it belonged to. Home now shows History ›, never that line.
- **Archived or missing routines** don't make a row, and they are dropped from a 2-slot day's names. The old week rows showed "Missing".
- **Scan bound:** the spec says to scan at most `loopWeeks × 7` days, but its own AC1 (Mon/Thu, today Wed → Thu, Mon, Thu) needs 8 days in a 1-week loop. The scan therefore stops after one loop when it finds nothing, and otherwise runs up to `n` loops, which always hold `n` hits. An empty plan still returns `[]` after one pass.
- **The min-height subtracts the body's UA 8px margin** as a literal 16px. The app never resets the body margin, and changing that app-wide was out of scope.

## Workflow

- **Found by the browser check and fixed in 50f6b60:** the first build (ed01774) had `scrollH` 860 on an 844 viewport. A short Home scrolled 16px because the body keeps the UA 8px margin. The min-height now subtracts it.
- **The spec contradicted itself on the scan bound** (`loopWeeks × 7` vs AC1). I resolved it in favour of the acceptance criterion; see Technical.
- **The spec matched the code.** No scope was added or dropped.
- **Possible DEC:** a day screen's date can come from its link (`?date=`), not only from `from=/` plus this week. `withFrom` is now query-aware.
- **Seen, not changed:** Start now on a future dated day is still the off-schedule `startOrContinue` (req-200), so the workout is today's, not tagged to that date.
