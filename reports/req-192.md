## Technical

### What changed
1. **Effort buttons log the set** (`src/ui/index.jsx` SetLogForm, `ui.css`).
   - The pinned bar has two tiers. The top is a quiet row: Previous (left) · Skip set (right). The bottom is a caption, "Log set — how did it feel?", and four buttons: **Easy · Medium · Hard · Failure**.
   - Each effort button calls `submit(value)`, which runs the old Complete path: kg error, then "Enter reps", then duration, then `onComplete` with rpe 2/3/4/5. Nothing is preselected (`initialEffort` now defaults to `''`, and the live form no longer passes one).
   - Where effort is hidden (warm-up, cardio) there is one primary **"Done"**, which logs with rpe null.
   - The buttons are `secondary` Buttons, 600 weight, with an ink outline. They sit in a 4-column grid, which becomes 2×2 below 360 px.
   - `.ui-main:has(.ui-setlog__actions)` reserves the taller bar's height. The bar now has a solid background.
2. **Labels** (`ids.js` RPE_OPTIONS / `rpeLabel`, plus Showcase and the SetLogForm defaults): Moderate → Medium and Max → Failure. Stored values are unchanged.
3. **Viewing a logged set** (`item.jsx`): its effort is the selected button (primary, `aria-pressed="true"`). Tapping another effort selects it and turns Next into Save. Save goes through the same `viewedSetSave` path as before. A logged set with no rpe shows nothing selected (was a default 3).
4. **Pill** (`views/workout/rest.jsx`): `WorkoutPill` takes `ownItemKey`, which only the log screen passes.
   - While resting on the current exercise's own screen, a tap writes `{ restEndsAt: null, restPausedRemaining: null }` (the old SkipRest write). The pill then reads "1:30 · skip" and its aria-label says "skip the rest".
   - On any other screen, a tap opens the exercise as before.
   - `SkipRest` is deleted. The exercise-actions row now renders only when Remove set applies.
5. **Set list** moves under the title (and the routine note), above the per-set note field and kg/reps.
6. **The routine's exercise note** (`item.notes`) shows read-only under the title (`p.ui-sub.ui-item-note`). "Add note" (per set) is unchanged.

No new persisted field. `progress.js` is untouched (its rpe reading is unchanged).

### Choices the spec left open (all `(unconfirmed)`)
- **Caption:** "Log set — how did it feel?". While viewing a logged set the caption reads "Effort".
- **Layout:** one row of four, 2×2 under 360 px. Unselected buttons are `secondary` (grey fill, ink outline, bold). The selected one, shown only while viewing, is `primary`.
- **"Done":** a full-width primary button. DESIGN §4 bans "Done" as a *navigation* label; here it commits, and the spec names it.
- **Enter key:** on a set that shows effort, Enter/Go in a field logs nothing, because there is no effort to log with. On a Done set, Enter logs as before.
- **Bar layout:** Previous stays top-left in both modes. Viewing gives Previous · Next/Save on top and the effort toggles below. The effort row is where the thumb rests.
- **Pill hint:** "1:30 · skip" replaces "set N/M" only while resting on its own screen. At GO it reads "GO · set N/M", and a tap there is a no-op.
- **Placement:** the routine note sits directly under the title, then the set list, then the per-set note field (when shown), then kg/reps.
- **Viewing a logged work set with no rpe:** nothing selected (was Moderate preselected). An untouched Save over a *skipped* set therefore writes no rpe. Before, it wrote the shown 3 (req-186 re-review fix 6). That follows from "no preselection".
