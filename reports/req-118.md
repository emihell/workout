## Technical

**What changed**
- New `src/routine-item-parse.js` (pure) exposes `parseKg`, `parseReps`, `parseDurations` and
  `parseRoutineItem({ sets, reps, kg, duration, timed })`, which returns `{ value, errors }`.
  - Kg splits on `/` only, and `,` is a decimal point. Reps and Duration split on `/` and `,`.
  - A bad token is an error at its 1-based position. It is never dropped.
  - `kg`/`s` suffixes are stripped.
  - Sets is authoritative. A longer list is an error; a shorter one repeats its last value. An empty field gives `[]`.
- `src/views/Routine.jsx` `ExerciseFields`: the submit handler now uses the parser instead of
  split/filter/`max()`, and `parseTargets` is no longer imported.
  - Save attempts to parse. If there are errors, Save does nothing and shows them.
  - After that first attempt, errors re-evaluate on every keystroke.
  - Each error renders as an inline `FieldError` (`role="alert"`) under its field, and that input gets `aria-invalid`.
  - Kg gets `inputMode="decimal"`.
- `src/ui/ui.css`: added `.ui-field-error` (grayscale, bold, `! ` marker) and a 2px ink border on
  `[aria-invalid]` inputs.

## Workflow

- **Choices left open by the spec, each (unconfirmed):**
  - Blank Sets falls back to the longest list, or 1.
  - An empty token (`8//8`, a trailing `/`) is an error at its position, not skipped.
  - Duration must be a whole number of seconds, and `0` is allowed.
  - Errors show only after the first Save, then update live.
  - Save stays enabled and refuses to save while there are errors.
  - Error wording: "N sets, M reps/kg values/durations given.", "Set N ("x") isn't a number.", "Set N can't be negative."
  - The spec already marks suffix stripping, Sets being authoritative and short Duration repeating as (unconfirmed).
