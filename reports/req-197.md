# req-197 — analytics by day and by build; Export analytics resets

Branch `req-197`, code commit `da17cf2`.

## Technical

- `src/analytics.js`: the shape is now `{ v: 2, days: { "YYYY-MM-DD": { screens, transitions, buttons, builds } } }`.
  The day is `dateKey(now)` from `schedule.js`, so it is the local date.
  - `recordScreen(name, now?)` and `recordButton(name, now?)` take an optional `now` so tests can inject it. `route.js` is unchanged.
  - New pure helpers: `applyScreenEvent`, `applyButtonEvent`, `dayBucket` and `parseAnalytics`.
  - `applyScreen` and `applyButton` now work on one day bucket.
  - `prevScreen` holds `{name, day}`. A transition counts only when `prev.day === day`.
  - `parseAnalytics`:
    - A v1 blob (no `v`, with at least one count) becomes `days["before-dates"]`. Its counts are unchanged and it gets `builds: {}`.
    - A corrupt or non-object blob, an unknown `v`, or a v2 blob with non-object `days` loads as empty.
    - Day buckets inside a v2 blob are normalised.
  - `exportAndResetAnalytics(download, now?)` runs `download(current)`, then `resetAnalytics()`, then `recordButton('export-analytics')`. If `download` throws, nothing is reset.
  - `sumDays(data)` returns all-days totals.
- `src/views/Settings.jsx`: Export analytics calls `exportAndResetAnalytics(downloadJson…)`. The message is now "Analytics downloaded. Counting starts again." The workout Export button is untouched.
- `vite.config.js`: the config is now a function of `{command}`. A new define, `__BUILD_ID__`, is the short sha on `vite build`. It is `"dev"` under `vite` (serve) and when git fails (`gitSha()` returns `'unknown'`). `__APP_VERSION__` is unchanged. `analytics.js` falls back to `'dev'` when the global is undefined (`node --test`).

## Workflow

- **Spec vs. code:** the spec says "the app has no build id today". In fact `vite.config.js` already defined `__APP_VERSION__`, the short sha from req-86, used by dev-notes. I added a separate `__BUILD_ID__` rather than reuse it, because the spec wants `"dev"` under `npm run dev` and `__APP_VERSION__` is the sha there. Reusing it would have changed dev-notes. Please correct the code-facts line in the spec.
- **Existing tests changed because the shape changed:**
  - `analytics.test.js`:
    - The pure tests use `emptyDay()` instead of `emptyAnalytics()`, because a bucket is now a day.
    - The export test's key assertion went from `['buttons','screens','transitions']` to `['days','v']`.
  - `req-191.test.js`: the button deltas read `sumDays(exportAnalytics()).buttons`, because the counts now sit in day buckets. Each delta assertion is unchanged.
  - `import-backup.test.js` and `safe-import.test.js`: their "analytics export is not a backup" payloads were rebuilt in the v2 shape. These tests are still rejection tests.
  - No guarantee test was weakened. The fail-silent and backup-isolation tests are kept as they were.
- **`(unconfirmed)` calls, built as the spec states them:**
  - No transition is counted across a day boundary.
  - The reset message is "Analytics downloaded. Counting starts again."
  - The export press is counted in the post-reset data.
- **Choices the spec left open:**
  1. The build-id mechanism: a separate `__BUILD_ID__` define keyed on vite `command`.
  2. A v1 blob with no counts at all is dropped rather than kept as an empty `before-dates`.
  3. `builds` counts screen events only, as specified. Button presses are not counted per build.
  4. The reset keeps the previous screen in memory, so the next move after Export counts its `settings>>X` transition in the new data.
  5. If the download throws, nothing is reset. Today, `downloadJson` throwing would also throw out of the button.
  6. A blob with an unknown `v` (not 2) loads as empty.
