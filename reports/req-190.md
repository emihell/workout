## Technical

**What changed**
- `src/plan-templates.js` (pure):
  - `startTodayWeek(week, today)` shifts the week so its first day is today's weekday and keeps the spacing.
  - `splitPicks` / `machinesPlan` handle the machines flow: "Workout", or "Workout A"/"Workout B", alternating in pick order. With A/B the days alternate A, B, A, B.
  - `emptyPlanDays` and `emptyDaySheetText` produce the sheet.
  - `templatePlan` handles `empty: 'same'`, which copies the first chosen day's picks.
  - `planIds` and `planToState` now run both flows through one normalized `{ routines: [{ name, picks }], week }`. The schedule week starts today. Only kept days count, so if day A is left out, B lands on today.
  - Writes still go only through `exerciseAddedState`, `restoreExerciseInState`, `routineAddedState`, `routineItemAdded` and `slotAddedState`. As before, the schedule is filled only when it is empty.
- `views/Plan.jsx`:
  - New `RoutineMachines`. The picker step uses `onPick`, so nothing is written. Then a days step: a 1–4 segmented control; for 2+ days the radios "Same workout every time" (default) and "Two workouts, A and B"; a preview of each workout with its days ("Today, Fri") and exercises; and Cancel/Save in `.ui-picker-bar`. If the schedule is not empty, Save goes to the existing Done screen.
  - The template Save now opens `askChoice` when a day is empty: [Leave it out] [Same as Full body A], plus Back. Back writes nothing and re-enables Save.
- `views/Routine.jsx` `RoutineNew`: the order is now "Pick your exercises" (primary), "Not sure? Use a plan", "Blank routine".
- `route.js` adds `/routines/new/machines[/days]`, which maps to `routine-machines`. `App.jsx` wires it up.
- `views/ExercisePicker.jsx`: `onPick` gets a second argument, the picker's own selection. A new optional `initialSelection` prop takes it back, so going Back from the days step keeps the ticks. Existing callers are unaffected.
- `ui/ui.css`: `html:has(.ui-picker-bar) { scroll-padding-bottom: dock + tap + 4·s2 }`. See AC6.

**Trigger files.** `state-reducers.js`: no. `store.jsx`: no (`applyPlan` passes the new `choices` shape through unchanged). `schedule.js`: no. No new persisted field and no schema change.
