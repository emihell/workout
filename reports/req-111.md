# req-111 — "last time" skips a workout where the exercise was entirely skipped (DEC-053)

## Technical

**What changed.** No stored record is rewritten; only how history is read.
- `src/storage.js` `lastSetsForExercise`: returns the newest finished workout with at least one non-skipped
  **working** set (`setType !== 'wu'`) of the exercise. If the exercise has never had a done working set, it
  returns the newest workout with any non-skipped set, so a warm-up-only history still seeds the warm-up.
  Otherwise it returns `null`. The returned `sets` still include skipped ones, and both readers already drop
  them. (Review loop-back: the first cut accepted any non-skipped set, so a workout where only the warm-up was
  done was "last time" and every work set prefilled blank kg.)
- `src/storage.js`: new `previousSameRoutineWorkouts(active, workouts, routines)` returns every prior
  same-routine workout, newest first. `previousSameRoutineWorkout` is now its head, so the auto-complete
  summary behaves the same.
- `src/beat-last-time.js`: `workSetsFor` drops skipped sets on both sides. `beatLastTimeWins(current, prior)`
  takes one workout or a newest-first list. For each exercise it compares against the first prior that has
  non-skipped work sets of it (`priorWorkSetsFor`).
- `src/views/workout/finish.jsx`: passes `previousSameRoutineWorkouts(...)` instead of the single prior.

**Dependents, and whether each still holds.**
- `item.jsx:151` (log-screen prefill, `hasHistory`, DEC-002 carry): holds, and now looks past skipped workouts (screenshot below).
- `historyPrescription` (`Routine.jsx:379`, routine editor add): holds. An all-skipped latest workout now gives the older one's prescription instead of `null`.
- `setPreview` tests in `workout-log.test.js` (use the real `lastSetsForExercise`): pass unmodified.
- `previousSameRoutineWorkout` → `auto-complete.jsx:38` `workoutSummaryStats`: same result (the req-84 tests pass). Out of scope and unchanged.
- `beatLastTimeWins` single-workout callers and tests: the single-prior form still works, and all req-96/98 tests pass unmodified.

- `./check` → `check: green — lint, 25 test file(s), and the build all passed.` (345 tests, 0 fail)
- `node --test src/storage.test.js src/beat-last-time.test.js` → `# tests 76 # pass 76 # fail 0`. The new suites are `req-111 lastSetsForExercise skips all-skipped workouts` (looks past / only-skipped → null / partial skip / warm-up done + work skipped passed over / warm-up-only history), `req-111 previousSameRoutineWorkouts` and `req-111 beatLastTimeWins — skipped sets` (no false win / 35 kg → heavier / skipped this time / empty list).

**Choices the spec left open.**
- Signature: `beatLastTimeWins` accepts a workout or a list (the spec gave this to CC). This kept the existing tests unmodified.
- Warm-up-only case (settled by Planner in review, not left open): (a) newest workout = warm-up done + all
  work sets skipped, older = 40×8 → returns the older one; work set 1 prefills 40, and `historyPrescription`
  gives `suggestedWeights [40,40]` with the older workout's warm-up. (b) the only history is a warm-up-only
  workout → returns it; the warm-up prefills from it, work sets are blank, and `historyPrescription` is
  `null` (no work sets; unchanged behaviour). In (b) `hasHistory` is true, so the DEC-002 kg carry does not
  run for the work sets.
