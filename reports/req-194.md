## Technical

### What changed
1. **New pure module `src/cardio-set.js`.** It has the parsers (`readDuration`, `readLevel`, `readDistance`, `cardioValues`), the formatters (`clockText`, `cardioBits`, `cardioFormText`) and the writers (`withCardioValues` deletes a blank key; `cardioPatch` sets it to undefined for merge reducers). It also has `lastDistanceUnit`.
2. **Live cardio form** (`ui/index.jsx`): a new `CardioFields` inside `SetLogForm`, behind a new `cardio` prop.
   - It shows Duration (clock text) with Start/Stop, then Level · Distance · m|km. The routine target ("Target 5-8 min") is a note under Duration and is never put in the box.
   - Start continues from the time already in the box, so the button reads "Resume" once a time is there. While running, the box is read-only and shows the live time. Stop writes the elapsed time into the box, which stays editable.
   - Done while the stopwatch is running logs the elapsed time at that moment.
   - Done with a blank Duration shows "Enter duration". An unreadable Level or Distance shows an inline error and logs nothing.
   - The cardio form applies only to a cardio exercise that isn't timed (`ex.type==='cardio' && !hasDuration`). The timed countdown is unchanged.
3. **Stored shape:** `durationSec` (whole seconds), `level`, `distance` and `distanceUnit` (only with a distance). Each is absent when blank. A new cardio set stores `reps: ''`. Old sets are not touched.
4. **Persistence of the stopwatch:** first built inside `setDraft.cardio.startedAt`; **superseded by review fix 1** — it is now its own `activeWorkout.stopwatch` field (see Review fixes).
   - The draft is cleared when the set is logged (`withLoggedSet`) and stripped at finish, as before.
5. **Display:** these places now show "12:30 · level 8 · 1.5 km":
   - History exercise lines (`formatSetLine`, new option `cardioFields`, plus any set that carries level or distance)
   - the done screen (`WorkoutItemDone`)
   - the log screen's set list (`loggedSetRowText`, new 4th param `cardio`)

   An old set (reps text, no durationSec) renders exactly as before. A timed hold still reads "30s".
6. **Set edit** (`SetEditForm`, new `cardio` prop) is used by the active set edit, History set edit and History add set. It shows Duration / Level / Distance + unit, all optional.
   - Reps shows only when the set has typed reps, so an old "5-8 min" stays visible and editable.
   - Save paths:
     - `activeSetPatch` and `liveSetEditPatch` (Previous → Save) use `cardioPatch`.
     - `historySetFields` passes `cardio` through.
     - `HistorySet` and `withHistorySet` apply it with `withCardioValues`, so no `cardio` key lands on a record.

### Choices the spec left open (all `(unconfirmed)`)
- **Distance unit:** m | km toggle. It starts on the unit of this exercise's last finished distance, else m.
- **Duration input:** clock text. "12:30" and "1:02:05" are read as clock times. A bare number is **minutes** ("20" → 20:00). "20 min", "90 s" and "20,5" (20.5 min) are also read.
- **Display format:** "12:30 · level 8 · 1.5 km", with the clock as m:ss (or h:mm:ss).
- **Duration is required on the live Done** ("Enter duration"). Level and Distance are optional. **Behaviour change:** before, the cardio box was prefilled with the target "5-8 min", so one tap on Done logged it as reps. Now the target is shown as a note only, so a time must come from the stopwatch or be typed. Prefilling "5-8 min" as a duration would invent a measurement. **Superseded in part by review fix 3:** a single-time target now prefills Duration.
- **Stopwatch:** superseded by review fix 1 — see Review fixes.
- **Level and Distance are not prefilled** from history (blank each set).
- **Set edit:** all cardio fields are optional. Reps is hidden on a cardio set without typed reps.

## Review fixes

These are from Planner's review loop-back. The reviewer found no blockers.

1. **The stopwatch is now its own `activeWorkout.stopwatch` field: `{ draftKey, startedAt, baseSec }`** (`workout-log.js`).
   - **Why:** another exercise's typing replaces the single `setDraft`, which used to drop a running stopwatch silently.
   - **Helpers:** `stopwatchFor`, `stopwatchOwner` and `startStopwatchPatch` are pure. `stopwatchSeconds` is in `cardio-set.js`.
   - **Load path:** `loadState → migrateState → workoutSnapshot`. Its snapshotted branch spreads `...workout`, so the field is kept (test).
   - **Cleared by:**
     - `withLoggedSet` on Done or Skip set of its own set (draftKey);
     - Stop (`patchActive({ stopwatch: null })`);
     - `finishedState`, which strips it.
   - **One at a time (my call): a second Start is refused.** That form's Start is disabled, with "The stopwatch is running on Rowing — stop it there first." I chose this because taking over would lose the first time silently, the same bug again.
   - **Stale stopwatches are taken over.** A stopwatch is stale when its set is no longer the current set of an exercise that isn't done, e.g. that exercise was skipped from the list or swapped.
   - **Start/Resume:** Start runs from 0:00. Only a time the stopwatch itself wrote (Stop sets `watched` in the draft) offers "Resume" from that time. A typed or prefilled time starts at 0:00.
   - **Draft:** `setDraft.cardio` now holds only the text fields plus `watched`.
2. **History prescription keeps the cardio time** (`history-queries.js` `historyPrescription`).
   - **Rule:** when `reps` is blank and the set has `durationSec`, the target is `durationTargetText`: whole minutes read "13 min" (the "5-8 min" style), else "12:30".
   - **Scope:** this applies to a non-timed cardio snapshot item, or to any set carrying level or distance. A timed exercise's seconds never become a target.
   - **Test:** through `pickerItem`: `Last time: 1 × 12:30` and `Last time: 1 × 13 min`.
3. **Duration prefill from a single-time target** (`targetDurationSec`).
   - "20 min" and "12:30" prefill Duration (shown as "20:00").
   - A range "5-8 min", a zero or a blank leaves Duration blank and required, with a "Target 5-8 min" note.
   - The stopwatch still overrides: Start runs from 0:00.
4. **A zero duration is refused:** "Duration must be more than 0." This covers a typed "0" or "0:00" and a Start then Stop at 0 s. It applies to the live form and to set edit.
5. **`formatSetLine`:** `cardio` plus a `durationSec` now renders the cardio form even without `cardioFields`.
   - **Side effect:** a *timed* cardio exercise's History line reads "0:30" instead of "30s". Timed non-cardio stays "30s".
