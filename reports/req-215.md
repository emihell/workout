# req-215 — New workout without days; "Days" row; "Use a plan" only with none

Branch `req-215` (from `origin/main` 200f98c). Built by a throwaway agent.

## Technical

**What changed**
- `src/schedule-days.js` (new, pure): `routineWeekdays(schedule, routineId)` returns the weekdays that have a slot in any loop week, Mon–Sun. `daysToggle(schedule, routineId, weekday)` returns `{ on, add, remove }`. If the day is on, the tap removes every slot this routine has on that weekday. If it is off, the tap adds one slot per loop week (`clampLoopWeeks`). `daysRowText` is `routineScheduledDaysText || 'Not scheduled'`. `hasActiveWorkout(routines)` ignores archived workouts.
- `src/plan-templates.js`: `machinesPlan({ …, schedule = true })`. `schedule: false` returns `week: []`. `planToState`'s `scheduled` now also requires `plan.week.length > 0`, so a plan with no week leaves an **empty** schedule untouched too: no anchor, no `loopWeeks`, no slot. Template weeks and default machines plans always have a week, so both existing callers behave as before.
- `src/views/Plan.jsx`: `RoutineMachines` freezes `later = hasActiveWorkout(store.routines)` when it mounts. When `later` is true, the `/days` step renders a new `MachinesName` screen: the picks, a Name box prefilled with `nextWorkoutName`, and Save. Save calls `store.applyPlan({ days: 1, split: 'same', picks, names: [name], schedule: false })` and then `go('/routines/<newId>')`. The first-time path (`MachinesDays`) is unchanged. `WeekdayChips` is now exported.
- `src/views/Routine.jsx`: `RoutineNew` hides "Not sure? Use a plan" and its sub-line when there is an active workout. In that case the primary start's sub-line reads "…then name it." A new `DaysRow` sits above Exercises in `RoutineDetail`: a `Row` labelled "Days" showing the days text, with a Change/Done button that opens `WeekdayChips`. Each chip tap applies `daysToggle` through `store.removeSlot` / `store.addSlot`. It is shown only when `nav.showDays && !routine.archivedAt`.
- `src/views/routine-nav.js`: new `showDays` option, default true. `views/workout/setup.jsx` and `views/history/recalc.jsx` pass `showDays: false`. `ScheduleSlot` keeps the default, so the row shows there.

## Workflow

- No deviations in scope. No schema change and no bulk write. The schedule is written only by `addSlot` / `removeSlot`. In a 2-week loop, one "on" tap calls `addSlot` twice (once per loop week, as §3 requires), and one "off" tap calls `removeSlot` for each of this workout's slots on that day.
- A "later workout" means ≥1 **active** (not archived) workout. A user whose workouts are all archived gets the first-time flow and sees "Use a plan".
- With ≥1 workout and an empty schedule, the new flow still writes no slot (`plan.week.length` guard). Before this change, `applyPlan` would have scheduled it.
- Open calls for Emilio (`(unconfirmed)` in the req, implemented as written): the first-time flow keeps its days step; a chip applies to every loop week and a day on in any week reads as on; after Save the user lands on the new workout's screen.
- Not verified in a real browser by this agent. The rendered tests use the repo's DOM harness against the real store.
