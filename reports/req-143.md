## Workflow

1. **Spec gap: merge-later to a queued `own-*`.** The spec's validator said `mergedInto` needs "a target that exists".
   A queued `own-*` doesn't exist in the library yet. I added `PENDING_ADDS` (the 29 queued own ids, ours) to
   `triage.js`. The validator accepts a pending target, and treats it as an ordinary target once it's written.
   **A batch that writes one of them should remove it from `PENDING_ADDS`.** 5 rows use it.
2. **Validator wording.** The spec said "hidden ⇒ neither common nor staple". I check `hidden ⇒ !common` only;
   `staple ⇒ common` already holds, so hidden ⇒ !staple follows. Checking staple directly added a second error line
   to req-140's unsanctioned `staple ⇒ common` fixture (Air_Bike is hidden now). This way that test stays unedited.
3. **Alias dropped.** I dropped "Kettlebell Thruster" on `own-thruster`: it broke req-140's promote-before-add test,
   which is unsanctioned (an own add may not share a key with a free-db name). "Standing Cable Chest Press" replaced
   it as the 20th sample.
4. **Behaviour changes for Emilio's list (unconfirmed):**
   - **112 of 133 merged free-db names now return "No matches"** when typed exactly (20 find the target first; Air Bike finds Fan Bike, by design), e.g. "Alternate Hammer Curl" and
     "Seated Dumbbell Inner Biceps Curl". This follows the alias rule (long phrasings get no alias).
   - **An owned hidden entry is non-staple, so it sits behind "Show more"** whenever a staple also matches. Example:
     someone who owns "Alternate Hammer Curl" searches "hammer curl" and sees Hammer Curl with **Add** first, and
     their own entry only after "Show more". That invites a duplicate. The live link (req-132) is where that gets
     fixed; I didn't pull the owned entry forward.
   - The owned exception is Search-only. `searchExerciseCatalog` has no UI caller and skips hidden entries without
     exception.
5. **Triage calls planning may want to revisit** (DEC-067 lens):
   - I merged 4 kettlebell variants into a dumbbell/barbell entry: single-leg deadlift → own-single-leg-rdl, thruster,
     overhead triceps extension, pistol squat. I judged them the same logged movement. DEC-067 §1 treats equipment as
     identity for promote/add, so planning may prefer hide.
   - Band variants of written lifts are **hidden**, not merged, for the same identity reason.
   - Stretches: I finished a small beginner set (hamstring, figure-four, supine twist, world's greatest, inchworm,
     arm circles, leg swings, pass-through) and merged-later the rest into the queued stretches. Partner-assisted
     stretches and foam rolling (13 entries) are hidden. Yoga pose (camel): hidden per DEC-067 §3.
   - Finished for "room for advanced": Tire Flip, Hang/Power Snatch, JM Press, Zercher Squat, and Sissy Squat.
6. **For a DEC-/L-:** a triage class that points at not-yet-existing ids needs a pending list, or the "target exists"
   rule can't hold. Worth recording with the batch procedure: "remove from PENDING_ADDS when written".
