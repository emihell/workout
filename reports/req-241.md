# req-241 — the log screen names what's next; a done set can be turned into a skip

## Technical

- **Next line** (`src/views/workout/item.jsx`, under the set list): `<p className="ui-sub">Next: {name}</p>` from
  `nextNotDoneItem(active, item)`. Hidden while `showUpNext` is true and when there's no next exercise.
- **Skip set in the done-set sheet**:
  - `SetEditSheet` (`src/ui/index.jsx`) takes an `onSkip` prop and shows a quiet block "Skip set" above Cancel/Save,
    but only when `onSkip` is set and the set isn't `skipped`.
  - `LoggedSetSheet` passes `onSkip` only for a set that isn't skipped. Its `skip()` makes the same writes as `save()`:
    one `updateActiveSet`, the `seedOverrides` patch when it changed, and set 1's `setupAfterSetOneEdit`. There's no
    confirm and no `onSaved` (a skip has no effort to re-apply).
  - This covers both places the sheet opens: the log screen's set list and the review.
- **`skippedSetSave`** (`src/views/set-values.js`, pure; not a trigger file):
  - The patch is the skip record, the same one Skip set writes: `weight 0, reps 'skipped', note 'skipped', rpe null`.
    A timed or cardio value (`CARDIO_KEYS`) becomes `undefined`, so it's absent once saved. `loggedAt` and the targets
    aren't in the patch, so they're kept.
  - Carry re-run (DEC-052): only the item's latest set of that type can be the carry's source, the same rule as
    `viewedSetSave`. It re-runs only when the carried kg equals this set's kg.
  - When it re-runs, the carry falls back to the latest remaining non-skipped set of that kind (the `carryForSet` rule).
    If there's none, the `weight` is dropped from the override key; a stale `reps` override passes through.
  - Otherwise it returns the SAME map.
- **Form re-seed**: the live form is now keyed by
  `formKey = setSeedKey + override?.weight`, and so is the draft snapshot. A carry change from the sheet (Skip set, or a
  kg Save) re-seeds set 2's form. The draft is read again with it, and `openLoggedSet` flushes the debounced draft
  writer first, so kg already typed into set 2 survives.

**Spec ↔ code, handled (no stop needed):** the spec says Skip set goes "through the same save path, so seed overrides
re-run as on Save". That isn't enough for AC 4 on its own:
- Feeding the skip into `viewedSetSave` → `nextSeedOverrides` writes the override `weight: ''`
  (`weightSeedString(0)`), so set 2 would prefill **blank**, not 30.
- Even with the right override, set 2's form was already mounted under `key={setSeedKey}` (a skip doesn't change the
  set index), so it would keep showing 40.

So `skippedSetSave` is its own carry rule, and the form key includes the carry. Both are needed: each mutation below
fails AC 4.

**Test edit (called out):** `src/req-125.test.js` "reads the draft only in the setSeedKey-keyed snapshot" pinned
`key={setSeedKey}` and `draftSnap.key !== setSeedKey`. It now pins `formKey` (its exact definition), the
`draftSnap.key !== formKey` check and `key={formKey}`. The other asserts are unchanged: 3 `setDraftFor(active, setSeedKey)`
reads, no `active.setDraft`.
