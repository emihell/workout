# req-117 — taps you can take back (audit F)

Branch `req-117`. Ready to look at, not merged. Touches `workout-log.js` and the history write path, so per DEC-057 the reviewer and the backup reminder come before merge.

## Technical

**What changed**
- `workout-log.js`:
  - `withOneMoreSet` now also increments `addedSets`, an optional snapshot-item field.
  - New `addedSetCount`, `withOneLessSet` (the exact inverse: pops the target, pops the weight only if one was appended, i.e. iff the last weight is non-null, decrements `addedSets` and drops it at 0), `canRemoveAddedSet` (warm-up logged, next set is one of the added ones, not logged) and `removeAddedSetPatch` (the shorter item plus `markItemDonePatch` when `plannedDone` holds again, else null).
  - `restoreFromLoggedSet` moved here from `item.jsx`. It now carries `durationSec` (not for a skipped set).
  - New `initialDurationFor`: the restored seconds, else the target.
- `item.jsx`:
  - The log screen shows a **Remove set** Button first in the exercise-actions row (Remove set · Skip exercise · Replace exercise), only when `canRemoveAddedSet`. On tap it calls `patchActive(removeAddedSetPatch)`. When the item is done again it goes to the overview (replace), the same as completing a last set (DEC-013).
  - The timed form takes `initialDuration` from `initialDurationFor`.
  - Done view: title and equipment now come before Add set (markup order).
- History add (`views/history/add-set.js`, new, pure, no imports):
  - `historyAddItemId`: the same item-id resolution as the old `addSetToWorkout`.
  - `historyAddSetPath` builds `/history/:id/set/new/:exerciseId/:itemId`, URI-encoded.
  - `historyAddSetDraft`: the old placeholder values, unsaved.
  - `withHistorySet`: appends the set, plus the "Added during history correction" snapshot item if it's new. Coercion is the same as HistorySet's Save.
- `route.js`: new `history-set-add` route (the `/set/new` picker and `/set/:index` are unchanged, and tested).
- `App.jsx` and `index.jsx`: wire the route to the new `HistorySetAdd` in `edit.jsx`. Save does one `updateWorkout` and then goes to the recalc preview (as a set edit does). Cancel and Back write nothing and return to the exercise page if the workout already has that item, else to the workout.
- `addSetToWorkout` is removed from `helpers.js`. Its two callers now navigate: the picker (`edit.jsx`), and the exercise page (`detail.jsx`, which the spec's scope list didn't name). In `detail.jsx` the control is now a `NavLink ›`, because it only navigates now (DESIGN §4).
- `SetLogForm` and `set-edit.jsx` needed no change.

**Persisted data:** one optional snapshot-item field, `addedSets`. There is no schema bump and no bulk write, and it is written only by Add set and Remove set on the active workout. `migrateState` → `workoutSnapshot` keeps it through `...rest` (tested with a v9 reload and with `{ legacy: true }`). req-120's legacy gate only fills empty targets and weights, and those are never empty on a bumped item (tested). A finished workout keeps the field, which is harmless: progression and recalc don't read it.
