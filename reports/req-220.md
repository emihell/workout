### Choices the spec left open (implementation)

- The preview compares **migrated** current data with the migrated file. Without this, a workout finished in this session
  (no `schemaVersion` until the next load) would read as "changed". Tested in `a just-finished workout … still compares
  equal`.
- `true` from an injected `ask` means the default, Keep. This keeps the existing `ask: () => true` callers meaningful.
- The AI file is named `workout-for-ai-YYYY-MM-DD.json`, so the user can tell it from a backup.

## Workflow

### Open calls (behaviour; mine; for Emilio/Planner to confirm)

1. **A kept workout whose routine the file removed:** under Keep, the device's own routine comes back **archived**. So
   does any exercise kept history or that routine uses. This mirrors `removeRoutineFromState` / DESIGN §3 ("referenced
   setup is archived, not deleted"); nothing is invented. When this happens the sheet says "Your history uses N items the
   file removes; Keep my history keeps them, archived." The no-conflict replace path does **not** do this. It stays
   byte-for-byte today's replace.
2. **Keep also keeps the device's `activeWorkout` and `draftWorkouts`**, never the file's. A file that would replace or
   drop the workout in progress counts as a conflict ("Workout in progress: …" line).
3. **Workouts the file adds:**
   - On a device with history, they are a conflict, and Keep drops them (an AI must not invent sessions; "Logged history:
     N logged workouts added" says so).
   - On a device with no history there is nothing to keep, so there is no choice and the file is restored as before.
   - A merge of another device's history needs Replace everything.
4. **Wording (unconfirmed, as the req says):**
   - the how-to lines (`AI_HOWTO`);
   - the sheet title "This file changes your logged history";
   - "Keep my history takes the workouts, exercises and schedule from the file and keeps your logged history on this
     device as it is. A copy of your current data downloads first.";
   - the preview lines ("Workouts: 1 changed", "Logged history: 1 logged workout changed"). These say "Workouts" for
     routines, as the app's screens do.
5. In the unreadable state there is no preview: there is no readable data to compare against, and the req-157 question
   stays as it is.
