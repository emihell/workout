    `routineItem`, `schedule`, `scheduleSlot`, `scheduleMove`, `workout` (plus the live-only `seedOverrides`, `setDraft`,

  - `ASSISTANT` brought current:
    - prompt: read history first; "Never invent completed workouts or sets"; progress by changing the routine's
      `suggestedWeights` and `targets`.
    - `howTheAppWorks.sets`: the set shape, incl. `loggedAt` and the cardio/timed fields.
    - `howTheAppWorks.history`: effort per exercise (2/3/4, 5 legacy, null), missed reps, the progress.js rule (≤2 and no
      missed reps → up one step; missed or ≥5 → down; Hard 4 keeps; bodyweight moves reps; cardio/timed/range hold;
      n/a → keep), and `loggedAt`.
    - exercises text: `hasDuration` / `durationSec` / `libraryId`.
    - samples: `lightestWeight`, `hasDuration`, `durationSec` and `libraryId: 'Leverage_Chest_Press'` (a real library id)
      on the exercise; `durations` on the items; `moves` in the schedule; `import.sampleSets` with one working set and one
      cardio set (`durationSec`, `level`, `distance`, `distanceUnit`, `loggedAt`).
    - `enums.effort` and `enums.distanceUnits` added.
    - import instructions: the app previews; return `workouts` exactly; never add workouts or sets.
  - `undocumentedFields(state)` returns every stored field not in `FIELDS`, as "entity.field".
  - `importPreview(current, incoming)` counts added/changed/removed per collection, by id. Before comparing, the current
    data goes through the same `importedState` as the file: migrate, drop the stopwatch, default the anchor. Records are
    compared as key-order-independent JSON. `importedState` was extracted from `applyBackup`, with no behaviour change.
    `conflict` is true when any of these hold:
    - a logged workout changed or was removed;
    - the file adds workouts and the device already has history;
    - the workout in progress would be replaced or dropped.
  - `keptHistoryState(incoming, current)` is Keep my history. It takes the file, but keeps the device's `workouts`,
    `draftWorkouts` and `activeWorkout`: the same objects, so `workouts` is saved byte-identical. Removed setup that kept
    history uses comes back too (`setupKeptForHistory`, see open call 1).
  - `previewLines`: the preview as lines of text. `summaryOf` was extracted from `applyBackup`.
  - `commitBackup(payload, setState, { keepHistory, current })`: Keep builds its state inside the updater from the
    **latest** state. `applyBackup` still runs first, outside the updater (req-115).
- **`src/import-backup.js`** `importWithBackup`, in order:
  1. Validate.
  2. Build the preview (`null` in the unreadable state).
  3. Ask with `ask(message, preview)`.
  4. Turn the answer into a mode (`importMode`).
  5. The copy / download steps, unchanged.
  6. `store.applyBackup(payload, { keepHistory: true })` or the plain replace.

  - Otherwise: the existing confirm, with the preview lines above "Replace all data on this device?".

- **`src/views/Settings.jsx`** adds an "Export for your AI" button row under Back up now / Restore, always visible, with
  the 3-line how-to (`AI_HOWTO`). The banners are "Saved for your AI — <file>" after an export and "… Your logged history

### Choices the spec left open (implementation)

- The preview compares **migrated** current data with the migrated file. Without this, a workout finished in this session
  (no `schemaVersion` until the next load) would read as "changed". Tested in `a just-finished workout … still compares
  equal`.
- `true` from an injected `ask` means the default, Keep. This keeps the existing `ask: () => true` callers meaningful.
- The AI file is named `workout-for-ai-YYYY-MM-DD.json`, so the user can tell it from a backup.

## Workflow

### Open calls (behaviour; mine; for Emilio/Planner to confirm)

1. **A kept workout whose routine the file removed:** under Keep, the device's own routine comes back **archived**. So
   does any exercise kept history or that routine uses. This mirrors `removeRoutineFromState` / DESIGN §3 ("referenced
   setup is archived, not deleted"); nothing is invented. When this happens the sheet says "Your history uses N items the
   file removes; Keep my history keeps them, archived." **Superseded by review round 1:** the restore now runs on every
   write path, not only on Keep.
2. **Keep also keeps the device's `activeWorkout` and `draftWorkouts`** (since round 1, drafts count as logged history in the preview), never the file's. A file that would replace or
   drop the workout in progress counts as a conflict ("Workout in progress: …" line).
3. **Workouts the file adds:**
   - On a device with history, they are a conflict, and Keep drops them (an AI must not invent sessions; "Logged history:
     N logged workouts added" says so).
   - On a device with no history there is nothing to keep, so there is no choice and the file is restored as before.
   - A merge of another device's history needs Replace everything.
4. **Wording (unconfirmed, as the req says):**
   - the how-to lines (`AI_HOWTO`);
   - the sheet title "This file changes your logged history";
   - "Keep my history takes the workouts, exercises and schedule from the file and keeps your logged history on this
     device as it is. A copy of your current data downloads first.";
   - the preview lines ("Workouts: 1 changed", "Logged history: 1 logged workout changed"). These say "Workouts" for
     routines, as the app's screens do.
5. In the unreadable state there is no preview: there is no readable data to compare against, and the req-157 question
   stays as it is.
