# req-249 — three refusals: wrong node, wrong machine, behind origin

## Technical

1. **`check`, wrong node** (`check`, top). The first gate, above the `WORKOUT_SKIP_CHECK` bypass and lint: it reads
   `node --version`, then asks `server/config.mjs` for `NODE_FLOOR_TEXT` and `nodeVersionOk(<that text>)` in one
   `node --input-type=module -e` call. The floor stays in one place (req-235). Below the floor it prints
   `check: node v22.14.0 < floor v22.16.0 — run: nvm use` and exits 1. With no node on PATH it exits 1 with
   `run: nvm use`.
2. **Server scripts, wrong machine** (`server/lib.sh` `require_server_machine`). If `$DATA_DIR` doesn't exist it prints
   `<script>: not the server machine (no <DATA_DIR>) — nothing done` on stderr and exits 1. It's called right after
   `lib.sh` is sourced in `deploy`, `doctor`, `ops`, `backup` and `restore`, before any write, build, git or node call.
   Only `deploy` passes `--first-deploy-ok`, so `WORKOUT_FIRST_DEPLOY=1` lets a first-setup deploy through and says so.
   `start`/`stop` aren't guarded: they already refuse without the live copy, and `start` is what creates the data dir
   on a first setup.
3. **`plan save`, behind origin** (`plan`). `fetch_origin_and_warn` now also sets `PLANNING_BEHIND`. `cmd_save` refuses
   (exit 1, before the NOW.md check and `git add -A`) when it's > 0. The two "Look first" lines come from the
   existing warning, then
   `plan save: refusing — local planning is N commit(s) behind origin/planning; nothing committed.`
   `status`/`next` behave as before. A `main` that's behind still only warns in `save`, because the spec names
   `planning` only.

**Tests:**
- New `server/req-249.test.mjs` (13 tests, in `./check`). They use temp dirs only, with a stub `node` on PATH, so a
  script that gets past its guard records its arguments instead of running anything. Deploy is given a non-existent
  `WORKOUT_DEPLOY_REF`, so past the guard it stops at its ref check. The tests cover:
  - each of the 5 scripts with no data dir: exact message, exit 1, nothing run, no live/`.new`/data dir;
  - each of the 5 with the data dir present: passes the guard;
  - `WORKOUT_FIRST_DEPLOY=1`: lets deploy through, and none of the other 4;
  - `./check` with a node shim reporting v22.14.0 (exit 1, exact message, empty stdout) and one at the floor.
- `scripts/plan-guards.test.sh` gets a behind-origin scenario: a bare fake origin and a second clone push one commit to
  `planning`. Then `save` refuses with no commit and nothing staged; after a ff-merge `save` commits; `status` at
  1 behind still exits 0 and warns.
- Mutation checks (temporary, reverted):
  - `require_server_machine` always returning 0 → `# fail 6` in req-249.test.mjs.
  - The `plan save` refusal turned into `if false` → `plan-guards: 2 FAILED`.

`server/README.md` gets a two-line note on the guard.

## Workflow

- **Choices the spec left open:**
  - The node check runs above the `WORKOUT_SKIP_CHECK` bypass, read literally as "first thing". So a skip on the wrong
    node now refuses too. That also lets the test run `./check` with `WORKOUT_SKIP_CHECK=1` safely: if the guard broke,
    the run would print SKIPPED instead of recursing into the full gate.
  - `restore` is guarded in every form, including the `--to <dir>` drill.
  - `ops` is guarded for every subcommand, including read-only `counts` and `plan preview`.
  - `WORKOUT_FIRST_DEPLOY` must be exactly `1`.
  - `main` behind origin still only warns in `save`.
- `scripts/plan-guards.test.sh` still isn't wired into `./check`. That's unchanged and its header says so.
- Nothing touched `handoff/`, launchd, tailscale or the live paths, apart from the two guarded refusals above.
