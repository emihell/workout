# req-156 — warm-up/cardio sets stop saving a hidden effort; a render-test harness for views

Branch `req-156`. The fix is in one commit. No persisted-data change: rows already saved with `rpe: 3` are untouched,
and there is no bulk write. `workout-log.js` and `store.jsx` are not touched, so the reviewer rule (DEC-057 §1)
doesn't fire.

## Technical

**1 — F-TRUST-2, the hidden effort.** The fix is at the source, the two forms, so every save path gets it:
- `ui/index.jsx` SetLogForm: on Complete, `effort: showEffort ? effort : null`. The live log's `completeSet` already
  maps a falsy effort to `rpe: null`. Before, the unseen `initialEffort` 3 ("Moderate") was sent.
- `views/set-edit.jsx` SetEditForm: `rpe: showEffort ? rpe : ''`, which `set-values.js` maps to `rpe: null`. This
  covers the active set edit (`WorkoutSetEdit`, Effort hidden for warm-up/cardio). Editing an old warm-up with rpe 3
  there now saves null, the value the user sees, instead of writing the invisible 3 back. That is a single edit the
  user makes, not a bulk write.
- **History edit / add set: no change needed, and none made.** History always *shows* Effort (it's clearable), so
  what it saves is what the user sees. The add-set draft starts at `rpe: null`, so a History warm-up saved as-is
  stores null (render test below). I did **not** hide Effort in History for warm-up sets. That would be a visible
  UI change the spec didn't ask for.
- Traced: the only other rpe writes are `skipSet` and the skipped placeholders (`rpe: null` already), and
  `workout-log.js:133` (`rpe: null`).

**2 — F-TEST-1, the render harness** (`src/test-support/`):
- `jsx-loader.js`: Node module hooks. *resolve* tries `.js`/`.jsx`/`index` for extensionless relative imports
  (as Vite does). *load* compiles `.jsx` with rolldown's `transformSync` (automatic runtime). rolldown ships with
  Vite, so this adds no dependency.
- `render.js`: registers the loader, puts a **happy-dom** `Window`'s globals on `globalThis`, and renders with
  the real `react-dom/client` under `act`. It gives a test `render()` → `{ text, button, input, click, type,
  unmount }` and `importJsx()`. Events are real: a test clicks "Hard" and "Complete" the way a user does.
- **New devDependency: `happy-dom@20.14.5`** (7 small deps; `npm install` reported 0 vulnerabilities). It's
  used in place of the deprecated `react-test-renderer`, which stays for the 3 existing tests that use it (I didn't
  migrate them; out of scope).
- **Wired into `./check`** with no script change: `./check` already runs every `src/**/*.test.js`, and a test
  file imports the harness itself. So plain `node --test` renders `.jsx` too, with no flag to forget.
  `test-support/*.js` aren't `*.test.js`, so they don't run as tests. They aren't imported by the app, so they
  aren't in the build.
