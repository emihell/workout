## Technical

- `scripts/dec_index.py`: the shared parser and the generator. Everything from `## Decision index` to the end of DECISIONS.md is
  generated, and everything above it is kept byte for byte. Each line is `- DEC-NNN · date · title · status`, grouped under
  `### decisions/DEC-001-050.md` etc. It refuses (exit 2, file:line, nothing written) on a malformed `#… DEC` heading, an entry
  with no date, a duplicate id, an entry in the wrong range file, text before a range file's first entry, or any other `## `
  heading in a range file. `--check` writes nothing and exits 1 when the index is stale.
- `scripts/dec_split.py`: cuts at entry headings. It proves the result from the files it wrote: byte equality, each heading
  in exactly one file, and the index equals the generator's output. It refuses a second run.
- `scripts/check_handoff.py`: new check 5 (`dec-ref`, `dec-index`, `dec-digest`, `dec-log`), all `fail`. It reads git objects
  like the other checks, and (a) is one `git grep` at the ref (0.05 s). It works on both layouts: before the split, the
  entries are read from DECISIONS.md and (b) is skipped. With no DECISIONS.md at the ref (other tests' fixture repos), it
  runs no DEC checks.
- `plan save`: before `git add -A`, if `git status -- handoff/log/decisions/` shows any change, it runs `dec_index.py`. A
  refusal there stops the save before anything is staged. The `plan help` line is updated.
- `scripts/check_skills.py`: resolves DEC ids against DECISIONS.md plus `log/decisions/*.md`.
- `.claude/skills/review/SKILL.md:14`: now says to grep the index in DECISIONS.md, then read the range file. The range dir is
  not in backticks, so check_skills' path check passes before and after the split.

Choices the spec left open (for `log/DECISIONS.md`):
1. **Status vocabulary.** `> **SUPERSEDED in part** …` (DEC-006, DEC-009) becomes `superseded in part by DEC-035`. Check (c)
   does not count it as superseded, because those entries are partly live. A chained marker (DEC-018: "by DEC-019, then
   DEC-024 and DEC-036") names the first DEC in the marker. `> **Reason corrected by DEC-082 §1**` (DEC-081, DECISIONS.md:1452) is not a
   marker word, so that entry stays `live`.
2. **Date.** The date comes from the heading's date-bearing paren group, so DEC-154's "the 2026-10-30 barbell session" is not
   taken as its date. If the heading has none, it comes from the first body line: DEC-036..044 all have "Decided 2026-09-13".
   The title is the heading minus that paren group.
3. **Addendum headings.** `## DEC-NNN follow-up …` is the one non-entry `## DEC` heading allowed. It stays with the entry above.
4. **Allowlist.** It adds the req-271 spec itself (it cites DEC-777 and DEC-999 as examples). It is written as numbers, so
   check_handoff.py doesn't cite them. Range-file names (`DEC-051-100.md`) are not counted as citations.
5. **Where the tests live.** They are in `src/req-271.test.js` (node spawning python3, the src/req-233 precedent), so `./check`
   counts them. The plan-save cases are in `scripts/plan-guards.test.sh`, which is manual, like its other save cases.
