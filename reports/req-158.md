# req-158 — stop recording two persisted fields nothing reads

Branch `req-158`. The fix is in one commit (`05bb20b`), plus this report. **Persisted schema** (reviewer before merge).
There is no schema-version bump, no migration change for legacy input, and no rewrite: stored `legacyRecommendations`
entries and old workouts' `progression` stay exactly as they are. `workout-log.js` is touched, so DEC-057 §1 fires.
`store.jsx` is not touched.

## Technical

**1 — `legacyRecommendations`** (`model.js` `migrateRoutine`). A baseline is now recorded only when
`legacy`:
```js
if (legacy && !recorded && (item.targets?.length || item.suggestedWeights?.length)) {
```
- **Legacy input** is recorded and read exactly as before.
- **v9 input** gets no new entries. The map is copied through (`{ ...source.legacyRecommendations }`), so stored
  entries are kept untouched.
- Only legacy code reads the map (`model.js` baseline, and `workoutSnapshot` ×2, all behind `legacy &&`), so v9
  behaviour doesn't change.

**2 — `workout.progression`** (`workout-log.js` `finishedState`, the one reducer both the manual and the auto
Finish go through). A new finished record has **no `progression` key**:
- the reducer no longer writes the argument;
- it also strips the `progression: null` that `store.startWorkout` puts on the active workout.

Old workouts are untouched: nothing in migration or save changes them. Nothing reads the field; the req-158 test
greps `src` for `.progression` and finds nothing.

**Choices the spec left open:**
1. **I made the change in the reducer only.** `finish.jsx` and `auto-complete.jsx` still compute
   `buildFinishProgression` and pass it, and `finishedState` ignores it. That keeps the diff to one place and leaves
   the tests that pin the call sites (`overview.test.js`, `workout-note.test.js`, `req-152`) alone. The callers'
   computation is now dead. **Follow-up (debt):** drop it and `autoFinishArgs`'s second argument.
   `buildFinishProgression` itself is still tested, and `progressionForItem` is still used by History recalc.
2. **`store.startWorkout` still writes `progression: null` on the active workout** (untouched, so the store rule
   doesn't fire). It never reaches a finished record. Remove it in the same follow-up.
3. A stale comment in `history/detail.jsx` ("workout.progression is still persisted") was reworded.
