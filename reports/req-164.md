  unchanged). `progress.js` imports `isSkippedSet` and its duplicate `isSkipped` is deleted.
  `scripts/check-cycles.mjs` (Tarjan over every static relative import in `src/`, tests excluded) is the receipt.
- **Split (step 2), code moved verbatim:** 636 code lines before and after, 0 lost, 0 added (a line-multiset
  comparison).
  - `src/persistence.js`: keys, load/save, the signals, the unreadable copies.
  - `src/history-queries.js`: "last time", previous workouts, summary stats, grouping, `routinesUsingExercise`,
    `isFirstRun`, `durationLabel`.

- **Importers, my call:** **all 16 app importers now import the owning module**, and `exerciseById`/`routineById` come
  from `model.js`. `storage.js` is a **pure re-export for one release** (4 lines, no code), so the 18 test files that
  import it stay unedited. Delete it once those move.
- **Store reducers (step 3).** All of store.jsx's inline updaters are pure functions in `state-reducers.js` (22 of
  them, e.g. `startedWorkoutState`, `slotAddedState`, `activeSetRemovedState`, `setLoggedState`). The bodies are the
  inline code lifted out. Ids (`uid`) and the clock (`now`) are made in the store and passed in, so each reducer is
  deterministic. `uid` is time plus random with no counter, so generating an id eagerly changes nothing observable.
  `grep -c "setState((s) => ({" src/store.jsx` → 0. Behaviour tests are in `req-164.test.js`.
- **Step 4.** `applyProgressionToRoutines` keys by `routineItemId` only. Its one caller passes `progressionFromWorkout`,
  which always sets it.
