## Workflow

Open choices, all `(unconfirmed)`:
- **Order of the two steps:** stored `'Alt A/B'` adds A first (the spec's 2.5/5 example). The legacy `'Alt 4/5'` with no
  lightest is the one exception (from 9, +5 first, as the spec requires). With a lightest weight set, `'Alt 4/5'` adds 4 first
  (10 → 14 → 19), matching the boxes as shown (4, 5). A user who wants 9, 14, 18 types 5 / 4 with lightest 9.
- **New two steps, no lightest:** count from 0 like a single step (`'Alt 2.5/5'` → 2.5, 7.5, 10). Alternative was hold.
- **Lightest 0 is an error** ("must be more than 0 kg"); spec listed only abc / negative / >250. 250 itself is allowed.
- **Field name / form:** `lightestWeight`, stored as a number; cleared → `null`. Labels "First step (kg)" / "Second step (kg)".
- **Detail line wording** "Two steps 4/5 kg" / "Lightest 10 kg" — the spec named only the editor; I renamed it too for consistency.
- **Hidden for cardio** in both editors; the exercise detail line still shows a cardio exercise's stored step (unchanged).
- Help line shown whether or not Two step sizes is on.
- In the full editor, switching Type to cardio drops any unsaved step edits on Save (fields hidden ⇒ not saved).

Concern for planning: no screen previews the series the settings produce; with the order rule above, a line like
"Weights: 10, 12.5, 17.5 …" under the fields would make it inspectable (CLAUDE.md "reasoning made visible"). Not built — a
user-visible behaviour, so it is Emilio's call.
