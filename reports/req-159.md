# req-159 — `plan qa` + a scripted smoke test that gates deploy

Branch `req-159`. Tooling only: no `src/` change, no persisted-data change. Touches `plan`, `check`,
`.github/workflows/deploy.yml`, new `scripts/qa.mjs`, `scripts/smoke.mjs`.

## Technical

**`scripts/qa.mjs`** (node builtins only; `capture.mjs`'s build/serve recipe, extracted and extended)
- `start <ref> [--seed f] [--node-modules d]`: `git archive <ref>` → temp dir, symlinked `node_modules`, `vite build`
  (GITHUB_PAGES unset, base `/`) into another temp dir. The seed goes into `index.html` as an inline script that
  writes it under `workout-mvp-v8` **only when the origin holds no v9 and no v8 doc**, so the first load runs the
  real legacy migration and later loads keep what the app saved. A detached static server runs on a free
  `127.0.0.1` port. State lives in `$TMPDIR/workout-plan-qa/state.json`. One qa server at a time: a re-run replaces it.
- `stop` kills the server and deletes the build. `status` shows what's running.
- Exports `buildRef`/`injectSeed`/`serveDir`/`resolveRef` for the smoke test.

**`./plan qa <ref>` / `--stop` / `--status`**: runs `qa.mjs` from this checkout (or, if absent, the code worktree's),
always with the **code worktree's** `node_modules`. Usage text updated.

**`scripts/smoke.mjs`**: builds HEAD (or `--ref`) in-process, or uses `--url` against a `plan qa` server.
- Each run gets a fresh browser context, so the seed runs.
- The clock is **shifted, not frozen**, to Mon 2026-09-21 10:00 local (db.json's Upper Body day). "Today's routine" is
  therefore date-independent, and timers still run.
- Native `confirm/alert/prompt` are replaced with recorders (plus a `page.on('dialog')` backstop); any call fails the
  step. Page errors fail it too.
- The steps, all real clicks or keys, each waiting for the screen it expects:
  1. Today, then Start (the primary button).
  2. Chest Press: select the kg field, Backspace, type `22,5`, Complete.
  3. ‹ Exercises, then Lat Pulldown, then Skip exercise and "Tap again to skip" (the in-app two-tap).
  4. Finish, then Save.
  5. Check the stored doc: exactly one logged Chest Press set with `weight === 22.5`. Lat Pulldown's sets are all
     skipped **and** it is in `completedItemIds`, because after Finish every unlogged set reads skipped, so the marker
     is what shows it was skipped explicitly.
  6. Browser Back ×4. A MutationObserver tripwire catches even a one-render "Not found."
  7. Reopen the app, then History, the month, the workout row (both exercise lines checked), and Chest Press's sets
     page shows `22.5`.
- Exit 0 green, 1 red (prints the step, the reason and `#root`'s text), 2 setup error. A run of 0 steps refuses to
  pass (L-020).
- Headless has no background-tab timer throttling, and there's one foreground page. The loop leaves exercises undone,
  so the req-84 auto-complete countdown never mounts. Both points are written in the header comment.

**`./check --smoke`** widens the gate with the smoke test. Any other argument is still ignored, as before.
**deploy.yml**: `node scripts/smoke.mjs` runs after `./check` and before the Pages build. A red step stops the job, so
nothing publishes. The two scripts are added to `paths`.

## Workflow

- **Finding on main, not fixed (outside scope):** after **Skip exercise**, the screen flashes `‹ Back / Not found.` for
  one render. Cause: `WorkoutItemLog` returns `<MissingItem />` when the item is marked done
  (`src/views/workout/item.jsx:116`) until the `replace` redirect to the overview lands. My first smoke version clicked
  during that render and failed on it. The smoke now waits for its controls and reports the flash as a `note:`
  without failing on it, because the spec only requires Back to never render it. The likely fix is to render `null`
  there instead of "Not found.". That's user-visible behaviour, so it's Planner's call: a req, or a follow-up to
  req-153.
- **Choices the spec left open:**
  - The clock is shifted to a Monday, so the run is independent of the date.
  - The seed is inlined into `index.html` (only when the origin is empty), not stored on disk.
  - `--smoke` is a flag on `./check`; plain `./check` doesn't run it.
  - The logged set is the warm-up. It's the first set the form offers, so that is the natural "log a set".
  - For History, the smoke reopens the app because in-workout screens hide the dock and the Back landing varies.
- **Not verified:** the GitHub Ubuntu runner itself. Chrome comes from puppeteer's `npm ci` download, which isn't
  cached by `setup-node`'s npm cache (it may add ~10 s per deploy) [inferred]. The first real deploy of this branch's
  merge is the receipt.
- **Worth an L-/DEC-:** the throwaway-commit trick (`GIT_INDEX_FILE` + `hash-object -w` + `commit-tree`) makes a
  deliberately broken build of any ref without touching a worktree. It's reusable for any "prove the gate goes red"
  criterion.
