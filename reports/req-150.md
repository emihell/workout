## Ready to look at

   whatever the effort, and the reason says why:
   - a target that isn't a single whole number (a range "8-12", AMRAP, a duration like "60 sec", any other text);
   - any set of an assisted exercise (kg = assistance).

   proves it. No new rule is added (DEC-075).

## Technical

**Change** (`src/progress.js`, one function plus three exports; nothing else touched):
- `unreadableTarget(value)`: a non-empty target that isn't `/^\d+$/` after trimming.
- `isAssistedExercise(exercise)`: `libraryId` ∈ {own-assisted-pull-up, own-assisted-dip, Band_Assisted_Pull-Up}, or the
  name matches `/assisted/i`.
- `HOLD_REASONS`.
- In `recommendNextPrescription`, a logged set that is assisted or has an unreadable target sets
  `weights[index] = actualWeight` and returns before any rule. Its target stays in `nextTargets`.
- `reason` = the old reason, plus the hold note(s) when any set was held. With nothing held, the reason is
  byte-identical to main.

**Choices the spec left open** (behaviour, so please confirm):
1. **Empty or missing targets keep main's behaviour.** They aren't text; "not set" is judged by effort as before.
   Holding them would have changed blank-reps items, which the spec doesn't mention.
2. **Duration targets ("60 sec", "60s", "5-8 min") hold.** This follows the spec's "any non-numeric text". On main, a
   *weighted* set with a duration target moved on effort alone. Bodyweight duration sets already held on main, so
   they're unchanged.
3. **A plain number means a whole number only.** "10 reps" or "12+" now hold, where main parsed out 10 / 12. The
   routine editor stores numeric reps as whole numbers, and the seed data has no such forms.
4. **Mixed items.** In `["10","AMRAP"]`, the numeric sets still move and the AMRAP set holds. `action` comes from the
   moved sets, and the reason reads e.g. "Load up. Target isn't a single number — kept as is."

**A fourth wrong answer this fixes:** main's parser strips non-digits, so an en-dash range "8–12" read as **812**.
Every set counted as missed and the load dropped. It now holds (test).

**"Visible" reason: not on a screen today.** The reason is persisted in `workout.progression[].reason` (and in
backups). But no screen shows it since req-96 removed the "Next time" surface. So it's inspectable, not visible in the
UI. Adding a surface is out of scope; flagged for req-149 / req-144.
