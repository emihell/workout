# req-108 — a changed reps value no longer carries; weight still does

Branch `req-108` (off `main` @ 36a2802). DEC-052 + amendment.

## Technical

**What changed**
- `src/workout-log.js` `setLogSeed`: reps are always `target || ''` unless restoring (Previous).
  `override.reps` and `carry.reps` are never read. Weight priority is unchanged: override → no-history
  carry (DEC-002 kg) → history.
- `nextSeedOverrides`: only records a changed **weight**. A `reps` already stored on an override (an
  active workout saved before req-108) is spread through untouched, never deleted or rewritten, and never
  read. Returns the same map by identity when weight is unchanged. The now-unused `repsSeedString` /
  `sameReps` helpers are gone.
- `src/views/workout/item.jsx` `carryFor`: returns `{ weight }` only. Comments updated.

**What depends on these, and whether it still holds**
- `initialSetFields` → the live form (`item.jsx`) and `setPreview` (req-106) both go through `setLogSeed`,
  so the form and the preview agree. The req-106 "right mechanism" test passes unchanged, and a new test
  checks the same with a weight override plus a stale reps override.
- `seedOverrideKey` wu/work separation, exercise isolation, and "until changed again" for weight: the
  existing tests pass unchanged.
- `store.jsx` (`seedOverrides: {}` on start, dropped on finish): not touched, and `store.test.js` passes.
- Restore (Previous) still wins over everything (existing tests).

**Edited tests (the behaviour is reversed on purpose; no test was deleted)**, all in `src/workout-log.test.js`:
1. `setLogSeed (req-02)` › "carry (main)…kg + reps both prefill" is now "…carried kg prefills, reps from the
   target". Carry reps is now 12 and target 10, so the test can tell them apart. Before, both were 10, so
   it would have passed either way.
2. `setLogSeed (req-02)` › "reps carry overrides the per-set target" is now "a carried reps value never
   overrides the per-set target". It expects `'10'` instead of `'8'` and also asserts the kg still carries.
3. `req-83 setLogSeed override` › "reps override replaces the target" is now "failure case — a stale reps
   override is ignored". It expects `{4, '8'}` instead of `{4, '6'}`.
4. `req-83 setLogSeed override` › "a weight override never lands on a bodyweight set": the expected reps
   changed from `'6'` (from the override) to `'8'` (the target).
5. `req-83 nextSeedOverrides` › "changing only reps records reps" is now "changing only reps records
   nothing". It asserts the same map comes back by identity.

**New tests:** no-history carry 12 with target 15 → `15`, and with no target → `''`, with kg still
carrying. A stale override holding weight+reps → weight kept, reps from target. Weight+reps change →
only weight recorded. A stale stored reps is passed through, not rewritten. A new `req-108 per-set reps`
suite runs the real seed → log → `nextSeedOverrides` loop: targets 10/8/6 with 9 logged on set 1 gives
8 and 6, with and without history; 20→22 kg gives 22 kg with reps 8; push-ups 15 with 12 logged gives
15. A req-106 preview-consistency test with `seedOverrides[k].weight`.
