## Technical

- `schedule.js` — `toLocalDate`: a `YYYY-MM-DD` string is a local day. Used by `dateKey`, `mondayOf`,
  `addDays`, `slotsOn`, `nextDateForSlot`. Timestamps and Dates behave as before. New `defaultAnchor`,
  `withDefaultAnchor(schedule, now)` (same object back when an anchor exists), `planDateFor(date, now)`.
- `current-workout.js` (new, pure) — `isCurrentWorkout(w, now, todayKey)`: started today OR `0 ≤ elapsed ≤ 6 h`.
  `otherTodayOccurrences(todays, active, todayKey)`: filters by `occurrenceId(slot.id, todayKey) !== active.occurrenceId`.
- The current rule is used in three places: the Today hero, `startOrContinue` (`workout-actions.js`) and
  `staleInProgressWorkouts` (`storage.js`). The signature `(state, todayKey = today, now = new Date())` stays
  compatible with existing callers. Wake-lock is unchanged.
- `loadState` — `withDefaultAnchor(migrated.schedule)`. If that defaulted the anchor, it saves once
  (`|| anchorDefaulted` added to the existing save condition). `migrateState` is untouched.
- `exchange.js` — `applyBackup` defaults the anchor. The template gets `anchor: '2026-08-24'`, and the schedule
  help text says what `anchor` means.
- `overview.jsx` — the preview date is `planDateFor(date)`, not `toISOString().slice(0,10)`.
- `Today.jsx`:
  - `loop = clampLoopWeeks(...)`.
  - Both `Done` rows use `weekdayDate`.
  - `StartButton` passes `occurrenceId(slot.id, date)`.
  - New `TodayHero({workout, others, date})`: today's date once, then `HeroRoutine` (in progress + Continue),
    then each other occurrence as a `TodayRoutine` (Start/Done), spaced with `__routine`.
  - `TodayWorkouts` is unchanged.
