# req-155 — decimal leftovers from req-154's review

Branch `req-155`. The fix is in one commit. Not a persisted-data change: no schema bump, no migration, no bulk write.

## Technical

**1 — a trailing separator on a kg is the whole number.**
- `kg-input.js`: the pattern is now `DECIMAL_NUMBER = /^(?:\d+(?:\.\d*)?|\.\d+)$/` (`KG_NUMBER` stays as an alias).
  So `22,` and `22.` → 22, since `normalizeKgText` turns `22,` into `22.`.
- Still refused: `2,5,5`, `abc`, negatives, a bare `.` or `,`, and `22,,`.
- All four set-save sites and the routine editor Kg share this pattern, so it applies everywhere.
  `parseKg('20/22,')` now gives `[20, 22]`. Before req-154, main read `22.` as 22 too.

**2 — typed durations.** New `src/seconds-input.js`, which takes the pattern and the negative check from
`kg-input.js`. `readSeconds`:
- trims and drops an optional `s` suffix;
- reads the first `,` as a decimal point;
- rounds half up (`Math.floor(n + 0.5)`): `30,5` → 31, `30,4` → 30.

This is Planner's call, which the spec marks unconfirmed. **Emilio should confirm the rounding.**

| site | before | now | blank |
|---|---|---|---|
| timed set, `SetLogForm` submit (`ui/index.jsx`) | `Math.max(0, Number(duration) \|\| 0)` → `30,5` = 0 s | `secondsToSave(duration, 0)`; unreadable → inline error, Complete refused | 0 s (as before) |
| timer readout + Start (`DurationTimer`) | `Number(seconds) \|\| 0` → `30,5` showed 0s, Start ran 1 s | `readSeconds(seconds).value ?? 0` → shows 31s | 0 |
| exercise default, `ExerciseEdit` (`Exercises.jsx`) | `Math.max(1, Number(t) \|\| DEFAULT)` → `30,5` silently kept the default | `defaultDurationToSave`; unreadable → inline error after the first Save, Save refused | the default (as before) |

- `item.jsx` completeSet now passes the form's whole seconds through as they are. The old
  `Number(durationSec) || 0` there only ever got a number.
- Kept as before: at the exercise default, `0` (and `0,4`, which rounds to 0) still saves the app default, and at
  least 1 s. That's the existing `|| DEFAULT` behaviour; I left it alone because it isn't a comma issue.
- Out of scope: the routine editor's multi-set Duration, where `,` separates sets (DEC-058 §6).
