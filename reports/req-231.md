## Technical

### Scripts (`server/`, runbook `server/README.md`)

- `lib.sh`: shared defaults (the live paths, port 8100, label `com.workout.server`). Each can be overridden by env for a
  throwaway.
- `deploy`: backs up `deploy-<sha>` (if a DB exists) → `git archive main` → `<live>.new` → `npm ci --ignore-scripts` +
  `build:server` → deletes `node_modules` (the server needs none at run time; measured: the throwaway ran without it) →
  stops if running → swaps (old copy kept as `workout-live.prev`) → restarts if it was running. A failed build leaves
  live unchanged. `WORKOUT_DEPLOY_REF` exists for throwaway tests (I deployed `req-231`).
- `start` / `stop`: refuse unless run from the live copy (realpath equal to `WORKOUT_LIVE_DIR`, no `.git`). `start`
  writes and bootstraps two LaunchAgents: the server (`RunAtLoad`, `KeepAlive`, `ThrottleInterval 10`, absolute node
  path, env baked in, log in `<data>/logs/server.log`) and `.nightly` (`StartCalendarInterval` 01:00, runs
  `ops-cli.mjs backup --nightly`). `stop` boots both out **and removes the plists**, so a stopped server stays off across
  login.
- `backup <reason>` / `backup --nightly`: node:sqlite `backup()` (the online API) → `.partial` → converted to a
  standalone file (`journal_mode=DELETE`) → `integrity_check` → renamed `backups/workout-<local stamp>-<reason>.db`.
  `nightly` is reserved for `--nightly`. Rotation keeps the newest 7 nightlies and never deletes other backups.
- `restore <backup> --to <dir>`: integrity check, then a copy into a new or empty dir outside every worktree. Live is not
  touched.
- `restore <backup> [--yes]` into the data dir: refused while the agent is loaded or the port answers. Prints both
  counts and changes nothing without `--yes` (exit 2). With `--yes`: backs up `pre-restore` → copies → `markRestore`
  → swaps the file in.
- `doctor`: listen addresses (lsof), health, `serve status --json` (`:8446` proxies exactly `127.0.0.1:8100`; funnel on
  **any** port is a FAIL), data dir realpath with no `.git` in any ancestor, modes 700/600, the live copy (no `.git`,
  `DEPLOYED`), both agents loaded, last backup ≤ 26 h. Exit 1 on any problem.
- Logic is in `server/ops.mjs` (tested); `server/ops-cli.mjs` is the CLI. The scripts need Node ≥ 22.16 for
  `node:sqlite backup`. The server's own floor (22.13) is unchanged.
- **Node quirk** `[measured, Node 26.8.2]`: `backup()`'s promise only settles when something else wakes the event loop.
  With a 3 s timer pending, a 2-page backup took 3.08 s. Under the test runner it hung until killed. Worked around with a
  10 ms interval while it runs (`ops.mjs copyDb`).

### DEC-133 option a (store/db)

- New table `restores(user_id, rev, at)` (`CREATE TABLE IF NOT EXISTS`, schema version stays 1, same pattern as
  `pruned_revisions`). This is a persisted-schema addition. Planner specified it (DEC-133 round 5) and no live DB exists.
  Existing v1 DBs gain the table on open, with no rows rewritten.
- `putState`: on a no-base merge after a restore, the device's workout wins only if `activeIsRestoredCopy`. That means
  the server's `activeWorkout` deep-equals the one in the newest marker's revision. With no marker (a hand copy), the
  req-230 behaviour is kept. If the marker's revision is gone, the server's copy is kept.
- `pruneRevisions` never prunes a revision a marker names.

### Cookie isolation (req-229 latent)

`tailscale serve` makes `:443/:8443/:8444/:8445/:8446` one host to the browser. The fix (`server/app.mjs`):
- the cookie is now named **`__Host-workout_session`**. The browser refuses that name unless the cookie is Secure,
  `Path=/` and host-only, so no other service can plant a more specific path or a parent-domain variant;
- `readCookies` reads **every** value sent under the name, and the session is whichever one is valid. A planted value sent
  first no longer displaces ours. Logout deletes each one.
- Residual risk: those services still *receive* the cookie. All of them are this Mac's own processes, tailnet-only. A
  separate hostname would need another tailnet node, so I didn't do it.
- Side effect: any test device logged in under the old name is logged out. Nothing is live, so nothing is lost.

### Stale test device (req-230 latent): **clear the origin's whole site data**, then log in, then Import with **Replace everything**

The epoch (rev ids) does **not** protect against this. Pinned in `src/sync/engine.test.js`, describe "req-231 — a device that
synced with a test server":
- a stale `workout-sync-v1` + same username → its test session gets a 401 → re-login → normal sync → base unknown →
  no-base merge **keeps** the one-sided test records in the real account;
- only `workout-sync-v1` cleared → first login onto the empty (rev 0) account **uploads the device's test data** as rev 1,
  its feedback notes go up as well, and an Import with "Keep my history" keeps the test workouts;
- site data cleared → login → Import (Replace) → the server holds exactly the export, with no test record and no note.
- **Found on the way** `[measured]`: "Keep my history" keeps the *device's* finished workouts, not the file's. On a cleared
  phone it imports **0 workouts** (first test run: `actual: []`). The go-live Import must be **Replace everything**.
  This is existing app behaviour, so I left it unchanged.

## Workflow

- **Fixed after the receipts:** that deploy run left `…deploy-2272fbe.db.partial-wal/-shm` beside the backup (the copy
  kept WAL mode and was read). Fixed in `copyDb` (`journal_mode=DELETE` before the check). The backup test now asserts no
  side files, and it fails without the fix (checked). The receipts above were made before this fix. It changes no counts
  or behaviour, only the litter.
- **Planner's calls I made (implementation, reversible):** the `__Host-` cookie plus reading every value (over a separate
  hostname); `stop` removes the plists (stopped stays stopped across login); a separate `.nightly` LaunchAgent (not a timer
  inside the server); backups are standalone files named in local time; doctor FAILs on funnel on *any* port and on a
  backup older than 26 h; `restore` into the data dir requires `--yes` and prints both counts (BACKEND rule 5's "ask with
  counts"); with no restore marker, the req-230 behaviour is kept.
- **For go-live (Planner + Emilio), from the stale-device finding:** on the phone, clear the website data for the `:8446`
  origin → log in → Import with **Replace everything** (not Keep my history). Then compare counts. Candidate for a DEC/L-.
- **`.nvmrc` says 22**, and the scripts need ≥ 22.16. `start` checks the node it bakes into the plist and refuses an older
  one. If launchd's node is nvm's, a later `nvm uninstall` of that version breaks the agent. `doctor` would then show health FAIL.
- `tailscale` isn't on PATH on this Mac. The scripts fall back to `/Applications/Tailscale.app/Contents/MacOS/Tailscale`.
