## Technical

- `plan`: new `DEPLOY_PATHS_RE` (`src/`, `public/`, `server/`, `index.html`, `vite.config.js`, `package.json`,
  `package-lock.json`, from CLOSEOUT.md step 4) and `deploy_line`. It diffs the merge commit against its first parent
  and prints the DEPLOY line or `no deploy needed` as the **last** line of `cmd_closeout` (step 8, after the push and the
  reviewer warning). It only runs after a successful push because `set -e` exits on a failed push. The diff goes into a
  variable before `grep -q`: piping into it can SIGPIPE `git diff`, and under `pipefail` that would read as "no match".
- Open choice: a re-run where the req was fast-forwarded has no merge commit. It then prints `deploy — no merge commit
  found; check CLOSEOUT step 4 by hand` instead of guessing.
- `append_shipped_stub`: the stub is three lines, `What: _Stub — …_`, `Gate: _Stub — …_`, `Report: _Stub — reports/req-N.md
  (+ deploy: doctor live copy line)._`. The closing "Still yours" step 1 now says to fill the What / Gate / Report lines.
  Open choice: the Gate placeholder leaves out the word "reviewer" on purpose. `shipped_names_reviewer` greps "reviewer"
  from "Gate" onward, so an unfilled stub would otherwise pass the DEC-057 reviewer check. A test pins this.
- `check_handoff.py`: new `check_shipped_size`, severity `warn` (exit stays 0). The entry date is the last `YYYY-MM-DD`
  in the `## req-N` heading. It counts only entries dated strictly after `2026-10-30`, and counts non-blank body lines up
  to the next `#` heading or `---`.
- Tests: plan-guards gets 2 closeout scenarios, check-handoff gets 3, plan-ledger gets 5. One test was edited:
  plan-ledger's old `_Stub — Planner:` assertion now checks the three new lines, and "no stub over a filled entry" now
  greps `_Stub`. That is the same check under the new text, not a weaker one.

## Workflow

- Side effect of the stub: `--no-reviewer` appends its note to the entry, which makes 4 body lines. A closeout with
  `--no-reviewer` will therefore trip the new size warning unless Planner folds the note into the Gate line. It is only a
  warning, so I left it alone; Planner can decide.
- Seen, not changed: on this branch `python3 scripts/check_handoff.py` exits 1 with `[fail] status: req-252 — tagged
  not-yet-merged, but 2938a29 already merges it`. Any req branch whose commits are subjected `req-N:` does the same,
  because the status check counts a direct code commit as landing. It was exit 0 before my first commit. It clears once
  the doc flips at closeout.
- Followed the run's extra rules: nothing under `./server/` was run, and `plan closeout` ran only inside the scratch
  repos.
