## Technical

- **`catalogItemToExercise` fix** (`exerciseCatalog.js`): `logAs: 'cardio'` → `type: 'cardio'`. `logAs` `time` /
  `weight-time` → `hasDuration: true`. Nothing else changes. Library Search's Add uses the same function, so it gets
  the fix too.
- **`src/routine-picker.js`** (pure, JSX-free):
  - `ownRecentFirst(exercises, workouts)`: non-archived exercises, ordered by the newest finished workout
    (`finishedNewestFirst`) with a non-skipped set of them; never-done after, A→Z.
  - `staplesByMuscle(catalog)`: listable staples in `MUSCLE_GROUPS` order, each under its first `muscleGroups` entry,
    A→Z by shown name.
  - `looseOwnMatch(exercises, entry, workouts)`: `libraryItemMatch` plus a word-subset match on normalized names
    (the shown or free-db name). Live beats archived; among several, the most recently done, then A→Z.
  - `pickerItem(workouts, exercise)` → `{ source, item, label }`, from one source only:
    - **history:** `historyPrescription` minus `warmup`, plus `role: 'main'`, `warmup: null`, `durations: []` (what
      the per-exercise form writes after req-179). A missing `restSec` stays missing.
    - **starting:** reps 3 × '10', 90 s; timed 3 × `durationSec` (default 30 s), 90 s; cardio 1 set, no target,
      rest 0. `suggestedWeights: []` always.
- **`views/ExercisePicker.jsx`**: the reusable component, for req-181. Props: `onAdd([{ exerciseId, item }])`,
  `cancelTo`, `createTo`, `ownFilter(exercise)`, `libraryFilter(entry)`, and `loadCatalog` (a test hook).
  - The own list renders at once. The library part shows "Loading…" or "Could not load." while it loads or if it fails.
  - Empty search shows the staples by muscle, each group under a section header. Typing searches with
    `searchCommonFirst` and a "Show N more" button.
  - Library rows you already have (a live `libraryItemMatch`) are not shown.
  - Each row is a checkbox. A selected row shows its plan line.
  - A library tap that `looseOwnMatch`es one of your exercises opens an inline row instead: "Use your 'X'?" with
    **Cancel / Add as new / Use mine**. For an archived match it adds "It's archived; using it restores it."
  - "Add N" creates library records, restores archived ones, then calls `onAdd` in tap order. The Cancel / Add N row is
    `position: sticky` above the dock (`.ui-picker-bar`).
- **`RoutineExercisePick`** (`Routine.jsx`) now wraps the picker: `onAdd` → `addRoutineExercise` per item → `nav.base`.
  The same screen serves the routine, schedule-slot, workout-setup and history-recalc flows; all four use the same
  store and routine.
- **`.cursor/rules/history-prefill.mdc`**: new paragraph naming the starting-plan exception (DEC-097 §4) and that it
  never sets a kg.
- **Test edit:** `req-122.test.js:89` pins the number of `<Actions>` rows: 15 → 17 (the picker's question row and its
  Cancel / Add N row). The justification is in the test comment.
