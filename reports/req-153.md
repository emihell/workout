# req-153 — Back and guard leftovers (req-24 / req-152)

Branch `req-153`. Not a persisted-data change.

## Technical

**1 — no duplicate entry, so no dead first Back** (`src/route.js`).
- The in-app visit stack can't tell what's beneath the current entry: a device Back pushes onto it rather than
  popping. So every browser entry now records the path beneath it in `history.state.below`.
  - A new entry (from a `go()` push or a plain link) is stamped when its `hashchange` arrives, from `oldURL`.
  - The page's first entry is stamped `below: null` (`installEntryStamps`, called by `useHashRoute`).
- `go(p, { replace: true })`:
  - Target is the entry beneath → `history.back()` onto it.
  - Otherwise → `history.replaceState` (keeping `below`) plus a dispatched `HashChangeEvent`.
  - `go()` without `replace` still pushes.
- Found in the browser, missed by my first fake: Skip's `go()` and the log screen's "marked done → overview" effect
  both replace in the same tick. That called `back()` twice and walked off the app (to the tab's previous page).
  Now, while a step-back is in flight, a repeat replace to the same target is a no-op, and any other `go()` is
  applied on arrival.
- Two safety nets:
  - A 400 ms timer (`BACK_TIMEOUT_MS`) settles a back that never arrives, so navigation can't get stuck.
  - If the landing isn't the target (an entry stamped wrongly, for example before this shipped), the target is
    replaced in.

**2 — old in-workout page after Save** (`NotInWorkout` in `helpers.jsx`; the decision is `inWorkoutFallback` in
`workout-paths.js`, which has no JSX so it can be unit-tested). With no active workout for a known routine, the
screen redirects with replace to `/workout/<id>`. With the item-1 change, that replace usually steps back onto the
overview entry beneath it. An unknown routine, or an active workout whose item or set is missing, still shows
"Not found.".

## Review fixes (on top of 10c1a99)

### Technical

**Fix 1 — stamp only real pushes** (`route.js`). A traversal onto an unstamped entry used to record `oldURL`, which
is the entry *above*, as `below`. Now only a real push sets `expectPush` (with the path it leaves), and the next
`hashchange` consumes it. A real push is:
- a `go()` push;
- the initial `#/` redirect;
- a primary click on an in-app `#` link to a different path, caught by a capture-phase `click` listener on
  `document`.

The flag is valid for 1 s. Entries reached by Back/Forward are never stamped: a missing stamp is safe (a plain
in-place replace), a wrong one isn't.

**Fix 2 + 3 — a slow back never undoes a tap; a leaving screen can't navigate after it.**
- Every `go()` requested while a step-back is in flight is now **dropped**, not queued. The only realistic sources
  are the leaving screen's effects (item 3) and duplicate same-target replaces (already a no-op). The arriving
  screen's effects run after arrival, so they aren't affected. So no queued push exists for a late back to undo.
- It settles on `popstate` **or** `hashchange`.
- On `BACK_TIMEOUT_MS` (raised from 400 to 1000 ms) it unlocks navigation and replaces the target in place, then
  watches `popstate` for `LATE_BACK_MS` (10 s):
  - The late back lands with no push since → it lands on the entry beneath, which is the same screen.
  - The user pushed a screen in between → the late back popped it, so `history.forward()` restores it.

**Measured in Chrome (item 2 run below):** a link tap (a fragment push) fires `popstate` too, with 1 event per
push. So a `popstate` on an entry that isn't stamped yet (a fresh push is stamped only on its `hashchange`) is
ignored as "not our back". Every entry we step back onto is stamped. Without this, a link tap after a timeout
would read as the late back. The fake browser now fires `popstate` on a push like Chrome, and a probe with the
check disabled fails fix 2b (below).

**Pins restored** (`req-152.test.js`): `leaveWorkoutToToday()` directly follows `finishWorkout` /
`abandonWorkout` (order pinned), and `detail.jsx` renders rows through `historyGroupRowMeta`. Both are source
pins, justified in a comment: node can't load .jsx.

- **Test edits in req-153.test.js:**

    behaviour, and fix 3's test asserts the opposite.
  - "a back that never arrives" was rewritten with `mock.timers` (the timeout is now 1000 ms).

  iframe's own entries into the top-level page. The run had already hit Save, so the dev data had 2 workouts. It
  was restored byte-identical from a snapshot kept in `sessionStorage` (which survives the tab navigation). The
  re-run stops at the iframe's first entry.
- **Accepted edge:** a link tap in the ≤1 s window while a step-back is in flight fires a push `popstate` on an
  unstamped entry, which is ignored, so it doesn't settle early. The later `hashchange` then settles, and since
  the landing isn't the target, the target is replaced in over the tapped screen. That needs a tap inside the few
  ms a back normally takes.
