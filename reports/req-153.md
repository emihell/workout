## Re-review fix — the Finish exits landed on the overview (regression on 1b5e3bd)

**Cause (confirmed):**
1. Save / Abandon on Finish runs the store write, then `leaveWorkoutToToday()`. `location.replace` moves the URL
   to `#/` immediately, but the router only hears of it on the async `hashchange`.
2. Meanwhile the still-mounted finish screen re-renders with no active workout, so it renders `NotInWorkout`.
3. That component's effect replaced Today with `/workout/<id>`.

The dropped step-back code had been swallowing this.

**Fix:**
- `inWorkoutFallback` takes `currentPath` (the browser's path when the redirect would run). It returns `'redirect'`
  only if that path is still one of this routine's in-workout sub-routes (`/workout/<id>/…`).
- Anywhere else it returns `'left'`: render nothing, because the router is about to show where the user went.
- `NotInWorkout` re-evaluates this inside its effect, not just at render.
- An old `/workout/<id>/finish` (or item page) reached by Back or by URL is still on its sub-route, so it still
  redirects. A bogus id still shows "Not found.".
- Auto-complete isn't affected: its summary lives in the overview (`Workout`), which doesn't use `NotInWorkout`.
- `route.js` is still identical to `main`.
