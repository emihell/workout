## Technical

- **Hook** (`.githooks/pre-commit`): the header comment and the refusal now point to `./plan save "message"` from the planning worktree. No line tells you to hand-set `HANDOFF=1`. The `$HANDOFF` bypass itself is unchanged.
- **Grants**:
  - `plan doctor` has one canonical list of 12 grants. `git commit:*` and `git reset:*` are gone, and the `./plan save|status|publish|closeout:*` forms are added next to the `../workout-codebase/plan` forms.
  - Doctor builds the exact `printf … > '<grants file>'` paste line from that list and prints it on every `FIX: grants` (missing file, drift, unreadable).
  - README §Setup step 5 has the same JSON plus a one-line note. `src/req-272.test.js` fails if README and doctor ever disagree.
- **Ratchet** (`scripts/check_handoff.py`, check 6):
  - The table is `scripts/doc_limits.json`, in the form `{ "docs": { path: { "ceiling", "reason" } } }`. It has 17 docs, each with ceiling = its current line count.
  - What fails: a doc over its ceiling; an empty or whitespace `reason`; a raised ceiling whose reason is unchanged from the base table; a listed doc that is missing; a missing or unreadable table; a bad ceiling; a row for an excluded path.
  - What warns: a doc 10 % or more under its ceiling gets "tighten to N".
  - The check runs in the full `check_handoff` run, so `plan status` and the warnings from save and publish show it.
  - New flags: `--only doc-limits`, `--base REF` (the table a raise is compared against; the default is `REF^`) and `--worktree` (reads the working tree, compared against HEAD's table).
- **plan save** runs `--only doc-limits --worktree` after the NOW.md guard and before `git add`. On a fail it refuses with nothing staged; warnings print and do not block.
- **plan publish** runs `--ref planning --base main --only doc-limits` after `./check` and before the merge. On a fail it refuses and nothing is merged. The rest of the drift check is still a warning only.
- **Ceilings, measured with `wc -l` on this branch** (main `93947ed`; README is 145 + 1 line from this req): PLANNING 393, WORKFLOW 344, BACKLOG 241, PAGES 192, schema 159, DESIGN 149, README 146, AUDIT 143, CLAUDE 128, CAPABILITIES 118, EVIDENCE 118, COACH 111, BUILDER 102, CLOSEOUT 80, GOALS 59, BACKEND 40, coach/LESSONS 29. Since the spec was written, WORKFLOW went 342→344 and BACKLOG 226→241. **If planning changes any of these docs before this merges**, re-measure. Over a ceiling, `plan publish` refuses. Under one, you get a "tighten" warning, and you set the number in the table to match.
- **Choices the spec left open**, for log/DECISIONS:
  1. **Where the table lives.** It is `scripts/doc_limits.json`, as the spec suggested. Because `plan save` refuses anything outside `handoff/`, I let that one path through `plan save` (`grep -vx scripts/doc_limits.json`). That way Planner can raise a ceiling in the same save as the growth. Any other `scripts/` file is still refused (tested). Without this exception, Planner could not raise a ceiling at all. The other option was a table inside `handoff/`, which I can't create.
  2. **What counts as "a raise with a reason".** The reason must be non-empty, and a raise must change the reason compared with the base table. Otherwise the old "baseline" text would pass any raise.
  3. **The 10 % tighten threshold:** the warning fires when `ceiling − count ≥ 0.10 × ceiling`.
  4. **Which docs are covered:** the spec's 17. `handoff/CLAUDE.md` stands in for the root `CLAUDE.md`, which is a symlink to it. Root `README.md` is included as the spec listed it. Since it is not in `handoff/`, raising its ceiling is a code commit. `handoff/README.md` (64 lines) is not covered because the spec didn't list it.
  5. **A missing table fails everywhere**, including fixture repos. So each test fixture gets a one-doc table (next section).
- **Test edits** (fixtures only; no assertion was weakened): `src/req-271.test.js`, `scripts/check-handoff.test.sh`, `scripts/check-lanes.test.sh` and `scripts/plan-guards.test.sh` now each write a one-doc `scripts/doc_limits.json`. Without it, AC5 turns every fixture red. I checked: check-lanes went red before the fixture edit ("a warning must not fail the run (rc=1)").
