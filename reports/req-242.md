# req-242 — a workout's exercise row opens its editor; the editor can change the exercise

Branch `req-242` from `main` 3c1c360.

## Technical

**What changed**
- `src/views/Routine.jsx` — `RoutineDetail`: each exercise row is now `Row to={nav.item(id)}`, so name and meta line are one link.
  In Reorder mode the row has no `to` (plain row with Up/Down, the name still a link, as before). `RoutineExerciseEdit`: a
  **"Change exercise ›"** link above Remove → `nav.change(itemId)`. New `RoutineExerciseChange`: the Add picker
  (`ExercisePicker`) with `max={1}`, primary button "Change", "In this workout" marks as Add, Cancel/Back → the item editor.
  On pick → `store.changeRoutineExercise(routineId, itemId, exerciseId)` → back to the item editor. `RoutineScreens` routes
  `screen === 'exercise-change'`.
- `src/routine-item-change.js` (new, pure) — `changedRoutineItem` / `routineItemExerciseChanged(routine, itemId, exerciseId, workouts)`:
  history → `historyPrescription`'s sets, targets, kg, rest (a rest history lacks keeps the item's), `durations: []` (as Add's
  `pickerItem`); no history → `{ ...item, exerciseId, suggestedWeights: [] }`. Item id, notes, role, warmup always kept.
  Unknown item / same exercise → routine unchanged.
- `src/store.jsx` — one new method `changeRoutineExercise` (+ one import line), via existing `routinePatchedState` with `s.workouts`.
  Nothing else in the store touched (req-241 in parallel).
- `src/views/routine-nav.js` — `change: (itemId) => ${base}/exercise/${itemId}/change`.
- `src/route.js` — `/routines/:id/exercise/:item/change` → `routine-exercise-change`; `parseRoutineNested` → `screen: 'exercise-change'`
  (so the scheduled-workout, workout-setup and history-recalc flows get it too). `src/App.jsx` renders the top-level route.

**Choices the spec left open**
- Primary button reads **"Change"** (disabled until a pick). Copy — Emilio may want different.
- Picking the item's own exercise is a no-op (no re-prescription from history).
- No-history case also keeps the item's per-set seconds (`durations`) along with reps; history case sets `durations: []` exactly as Add does.
- History with no recorded rest keeps the item's rest (Add would store 0).
- "Create exercise" link is not offered in the Change picker (its create flow returns to the routine, not this item).
