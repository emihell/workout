## Technical

  - The meta line comes from `offerText(offer)` in `routine-update-offer.js`: "You lifted 32.5 kg · routine says

  - At mount it captures `offered`, the items with an offer.
  - If there are any, the interval never starts and there's no "Finishing in" text. A primary **Finish** button
    calls the same `commit()`, which keeps `committedRef`, so a double tap commits once.
  - The offer list shows the `offered` items, so tapped rows keep their confirmation.
  - With no offers, nothing changes.
- **Plan (§4–5)**, `Plan.jsx` and `plan-templates.js`:
  - A picked row's text is the exercise and its meta is "{slot} · {plan line}". Unpicked rows read "{slot}" /
    "Choose"; skipped rows read "{slot}" / "Skipped".
  - The pure `carriedFills(days, fills)` fills each unset slot from the latest earlier day whose same slot key holds a
    pick (itself possibly carried).
  - An explicit pick or skip is never overwritten, and a skip is never carried.
  - The view keeps only explicit choices in state; the screen and Save both read `carriedFills`.
  - `PLAN_SKIP` moved to `plan-templates.js`.
