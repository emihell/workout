Branch `req-207` off `main` 389efeb. Code commits `f46c4fb` and `ffeeabe` (a CSS fix found by the browser check).

## Technical

**What changed**
- `plan-templates.js` (pure):
  - `machinesPlan({ days, split, picks, names?, weekdays? })`. With `weekdays`, the week is those days in Mon–Sun order, and A/B alternates over them. It returns `fixedDays: true`, so `planToState` does not apply the start-today shift. Without `weekdays` the output shape is unchanged.
  - `names[r]` sets the names. An empty name falls back to the old "Workout" / "Workout A/B". The UI always passes names.
  - New `nextWorkoutNames(routines, count)` and `nextWorkoutName`: N is the smallest integer ≥ 1 not used by an active (non-archived) workout. A second name takes the next free number after N.
  - New `mondayFirst` and `WEEKDAYS_MON_FIRST`.
- `views/Plan.jsx` `MachinesDays`:
  - After the days count, 7 Mon–Sun chips (`aria-pressed` toggles). They are preselected with the template days shifted to start today (DEC-105).
  - "Pick N days" shows, and Save is disabled, until exactly `days` are ticked.
  - The preview follows the ticked days.
  - The name box(es) sit just above Save: "Name", or "Name A"/"Name B", prefilled "New workout #N"/"#N+1". An emptied box saves its prefill.
- `store.jsx` (reviewer-trigger): one line in `addRoutine`. `name.trim() || 'Workout'` became `name.trim() || nextWorkoutName(state.routines)`, plus that import. Nothing else changed.
- `views/Routine.jsx`: `RoutineNewForm` takes an optional `defaultName`, which prefills the box. An emptied box saves the default instead of showing the empty-name error. Blank workout passes it, and so does `ScheduleDayAdd`'s no-workouts form.
- `views/Schedule.jsx` `ScheduleDay`: each slot row gets **Change day**. It opens an `askChoice` sheet listing the weekdays Mon–Sun, with the current day marked "(now)". Choosing a day runs `removeSlot(slot.id)`, then `addSlot({ week, weekday, routineId })`, then goes to the new day's screen, keeping `from` and the date. There is no confirm. Choosing the current day, or Cancel, writes nothing.
- `views/schedule-day.js`: pure `changeDaySheet` (copy and choices) and `changedDayPath` (same loop week; a dated screen keeps its Mon–Sun week).
- `ui.css`: `.ui-row--wrap` lets the day row's three buttons wrap below the name. `.ui-seg--days` adds the chips' top gap.
- No schema change and no new stored field.

**Choices the spec left open**
- **Chips show only on an empty schedule.** Otherwise the plan's days are not written ("Your schedule already has days…"), so there is nothing to pick.
- **The A/B second name is the next free number after N, not literally N+1.** For example, with #1 and #3 taken you get #2 and #4.
- **Change day leaves out a weekday that already has this workout in that loop week**, so the sheet can list fewer than 7 days. This avoids a duplicate slot, which Add workout also refuses.
- **Sheet copy:** "Move {name} to which day?" / "It moves for every week. Your history is kept." In a longer loop the second line is "It moves in week N of M."
- **Name prefills are fixed when the days step opens.**
- **The empty-name fallback** inside `machinesPlan` stays "Workout"/"Workout A/B", which `req-201.test.js` asserts. The UI never reaches it.
