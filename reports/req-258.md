## Technical

- **`src/dates-tz.test.js`:** the guard now counts the declared cases in `dates-tz.cases.js`: every line matching `^\s*it(?:\.(?:skip|only|todo))?\(`, which is 10 today. It then asserts `^# tests N$`, `^# pass N$` and `^# fail 0$` on each zone's child run. A skipped or `only`-filtered case is counted as declared, so it still trips the guard. A new test also fails if no `it(` is found. That is how a renamed API would be caught (L-045). Adding a case needs no second edit.
- **`check`:**
  - A second reporter writes TAP to `mktemp "$TMPDIR/workout-check-tap.XXXXXX"`.
  - `trap 'rm -f "$tapfile"' EXIT` removes it on every exit path, including `fail` and the watchdog. The watchdog subshell does not inherit the trap, so it can't delete the file early.
  - The terminal reporter is `spec` when stdout is a TTY and `tap` otherwise. I measured that this is what Node 22 picks by default (piped → `TAP version 13`), so terminal and CI output are unchanged.
  - After a green run, any line `^(not )?ok N - *.test.(m)js` turns the gate RED and names the file. So does a missing `# tests` line, or one that reads 0.
  - The green line now reads `N test(s) in M file(s)`.
- **Spec choice: reading the count instead of a literal.** "Reduced to 1 case" means 1 case *runs* while the file declares 10 (skip, or an early exit). If someone actually deletes 9 cases, the declared count drops with them, and the guard rightly passes.
- **Does part 2 catch a file that runs some of its tests and then exits 0?** No. That case was out of scope and listed as "not observed", but I observed it. The evidence:
  - The diffs in subtest names are cuts in the middle of a file, with no `not ok` and exit 0. In one run `storage.test.js` stopped after its `req-85` suite. In others `req-220.test.js` stopped after item 1's 4th test, and `req-139.test.js` lost 6 tests. Each run cuts a different file.
  - [measured] Raw `node --test` with check's flags came up short in 1 of 12 runs (2182). Without `--test-force-exit` it gave 6/6 complete counts. Those runs exit 1, because `req-203.test.js` and `req-220.rendered.test.js` then hit the 60 s file timeout: they hold a handle open, which makes force-exit load-bearing.
  - [inferred] Under parallel load, `--test-force-exit` ends a child before its TAP stdout has flushed to the parent. macOS pipes are async in Node.
  - A fix needs a per-file expected count, or a way to keep the child's output. Planner should spec it.
- **Also seen:** the first two `WORKOUT_TEST_LIMIT=5` runs had stdout redirected to a file. They measured 66 s from start to the shell returning, on both branch and main. Every later piped run ended at 10.6 s. I did not dig into it, since it is the same on main.
