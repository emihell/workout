## Technical

Five skills, 19–26 lines each. Each is an ordered checklist whose steps name their source (`handoff/rules/*.md` §section,
L-/DEC- ids) instead of restating it:

| skill | invocation | sources it points at |
|---|---|---|
| qa-branch | model + `/qa-branch` | WORKFLOW §Requirement lanes, L-033, L-036, `scripts/smoke.mjs` (page setup to copy) |
| review | model + `/review` | WORKFLOW READY check 5 (DEC-057 §1) and §Reviewing a branch, L-031, L-036 |
| closeout | model + `/closeout` | CLOSEOUT.md (§Preconditions, §Assistant, §Done when, §Fallback), DEC-035, L-032 |
| spec | model + `/spec` | WORKFLOW §Readiness, §Requirement lanes, §Requirements, §Write the doc…, §Before READY, L-032, L-035 |
| workflow-audit | `/workflow-audit` only (`disable-model-invocation`, like `audit`) | AUDIT.md companion paragraph, the newest `handoff/audits/workflow-*.md` as template |

Content that exists in no rule file, and so belongs in the skill:
- review: the output format (severity, `file:line`, failure scenario, receipt, a literal `No blockers.`), and keeping the
  latent list for re-check (L-036).
- qa-branch: puppeteer's absolute import path for scratchpad scripts, and the per-item "value read back" receipt.
- closeout: the `gh run list` / `gh run watch --exit-status` CI check.

Choices the spec left open:
- The trigger list isn't copied into review. Step 1 compares `git diff --name-only` against READY check 5, so the list
  can't drift.
- closeout is model-invocable. Planner runs it as a Claude session and can't type `/closeout` itself.

**`scripts/check_skills.py`** makes both criteria mechanical:
1. Every pointer resolves: paths, L-/DEC- entries, and each §section as a heading in the rule files.
2. No run of 8 consecutive words in a skill body appears in `handoff/**/*.md`, `CLAUDE.md` or `README.md`. A run
   containing a path counts as a pointer and is skipped.

`scripts/check-skills.test.sh` is the self-test that proves it fires. It isn't wired into `./check` (following the
`check-handoff.test.sh` precedent).
