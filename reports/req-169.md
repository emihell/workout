## Workflow

- **Finding for Emilio (load path, not changed: ask-gate #2).** `workoutSnapshot` rebuilds a workout's snapshot from
  its top-level `routineId`. A hand-edited or imported workout with only `snapshot.routineId` therefore **loses its
  routine link on every load** (`snapshot.routineId` becomes undefined; the name stays). Normal data always has
  `routineId`, so this only affects hand-made imports. Fixing it (deriving `routineId` from `snapshot.routineId`) is a
  migration change, which is his call.
- **My mistake, fixed in the next commit:** the first work commit went in with 2 failing tests (the `r-snap` case). I
  had reasoned from a repro that migrated first, so it was the migration that erased the reference, not the impact
  check. `ccf9455` measured it, reverted the routine side to `routineId` only, and pinned the shape.
