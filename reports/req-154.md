# req-154 — a comma kg ("22,5") is saved as 0 on the live log and as null in History

Branch `req-154`. First commit `317f526` is `audits/2026-09-24.md`, copied unchanged from Planner's scratchpad. The fix
is `30e9b1a`. **No persisted-data change**: no schema bump, no migration, no bulk write.

## Technical

**One shared parse: `src/kg-input.js`** (pure, no imports).
- `normalizeKgText`: trim, drop a `kg` suffix, read the first `,` as `.`.
- `readKg`: returns `{ empty }`, `{ value }` or `{ error }`.
- `kgError`: the form's inline message.
- `kgToSave(text, emptyValue)`: what a save writes.
- The number shape is the routine editor's `KG_NUMBER`, moved here. The routine editor (`routine-item-parse.js`)
  and the weight step (`weight-step.js`) now go through `normalizeKgText`, so there is no third or fourth copy of
  the comma rule. Their behaviour is unchanged: their existing tests pass untouched, and `parseKg('20/22,5')` and
  `parseWeightStep('2,5 kg')` are re-asserted in req-154.test.js. The weight step keeps its own, deliberately looser
  pattern.

**Per-site coercion: `src/views/set-values.js`** (pure, so `node --test` can import it). A kg that can't be read
returns `null`, meaning "don't save".

| site | before | now | blank kg |
|---|---|---|---|
| live log `item.jsx` completeSet | `Number(weight) \|\| 0` → **0** | `liveSetWeight` | 0 (as before) |
| active set edit `item.jsx` WorkoutSetEdit | `Number(weight)` → NaN | `activeSetPatch` | 0 (as before) |
| History edit `history/edit.jsx` HistorySet | `Number(weight)` → NaN/null | `historySetFields` | `''` (as before) |
| History add `history/add-set.js` withHistorySet | `Number(weight)` → NaN/null | `historySetFields` → null patch | `''` (as before) |

**Per-site behaviour for unreadable text (my call, spec §3): an inline error at all four sites.** None of them keeps
the field empty instead. Both forms had room for an error:
- `SetLogForm` (live log) and `SetEditForm` (the other three) check `kgError` on Complete/Save.
- On an error they show `<p className="ui-field-error" role="alert">` (the routine editor's style) under the kg
  field, and don't call `onComplete` / `onSave`.
- The next kg edit clears the error.
- The callers' `null` return is a backstop behind that.

Message: `Can't read 'abc' as kg — use a number like 22,5.` (`kg can't be negative.` for a negative).

**A second comma bug rode along (same site).** `nextSeedOverrides` (the req-83 kg carry to later sets) got the
*typed* text and compared it with `Number()`. With no earlier seed, `22,5` compared equal to the empty seed, so it
never carried. `item.jsx` now passes the parsed kg (`logged: { weight: loggedWeight, reps }`). In the browser run
below, the next set's field read `22.5`.

**Choices the spec left open:**
1. **A negative kg is now refused** on the log and in History. Before, `-5` was saved as −5. This matches the
   routine editor ("can't be negative") and no exercise type uses a negative load. `1e1` and `22.` are refused too
   (before: 10 and 22), because they're the routine editor's shape.
2. **Active set edit with the kg hidden** (bodyweight/cardio): the patch leaves the stored weight as it is instead
   of re-reading it. Before, it wrote `Number(set.weight)`, which was 0 for those sets anyway.
3. **Duration is out of scope.** It's whole seconds, and DEC-058 §6 says `,` there separates sets, so it isn't a
   decimal field.
