# req-200 — Home shows this week; a day opens its schedule screen

Branch `req-200` (off `main` f067725).

## Technical

**What changed**
- **`schedule.js`:** new pure `weekRows(schedule, workouts, today)` → 7 `{dateKey, week, weekday, slots, done}`, Mon–Sun of `today`'s calendar week. `done` = any workout finished that date (by finish date, never slot id — review F2). The finish-date filter is inlined rather than importing `completedOnDayKey`: `history-queries.js` imports `schedule.js`, so the import would be a cycle. `remainingInLoop` deleted (its only caller was the upcoming rows; no test used it).
- **Home (`views/Today.jsx`):** title → (Week x of y) → "Workouts ›" → today's block (unchanged) → the stale Continue row(s) → **"This week"** (SectionHeader + 7 link rows) → recent → History. `UpcomingRow` and the upcoming list/"Nothing scheduled." are gone. A week row reads `Sun, Oct 11 · Upper Body` (or `· Rest`), value `Today` and/or `Done ✓`, no Start; tap → `/schedule/:week/:weekday?from=/`. Today's row gets `.ui-row--today` (label bold, `ui.css`).
- **Stale Continue (review F6):** pulled out of the 2-row recent peek (where an old one fell off) and always rendered right under today's block. The recent peek is now finished prior-day history only.
- **`ScheduleDay` (`views/Schedule.jsx`):** takes `from` (App passes `route.from`). Back = `from || '/schedule'`. Title `Saturday` / `Saturday · week 2 of 2`. Each slot row: **Start now** (hidden for a missing or empty routine, as `routineStartable`) + Remove. "Add routine ›" uses `childLink`, so day → add → day keeps `?from=/`. "Whole plan ›" → `/schedule` when the loop > 1 week. `ScheduleDayAdd` takes `from` (the day screen as entered) for its Back and post-add `go`.
- No schema change. Slot edits use `removeSlot`/`addSlot` unchanged.

**Choices the spec left open**
- **Start now = `startOrContinue(store, routine.id)`** — the off-schedule start the Workouts list's Start uses, not a slot-tagged one. The day screen reached from `/schedule` has no date, and tagging today's workout with another day's slot id would claim an occurrence that isn't one. Effect: the workout is today's (performedOn today); Saturday's row does not turn Done unless something finishes on Saturday (by date, as specced).
- "Whole plan ›" is hidden when Back already goes to `/schedule` (it would duplicate Back).
- Today's row: value "Today" plus bold label; Done and Today combine as `Today · Done ✓`.
- Week rows are one line (`weekdayDate · names`), not the two-line `WorkoutInfo` stack, to keep them compact.
- Section header text: "This week".
- The stale Continue row sits between today's block and the week (spec: "stays with it").
- A missing routine on a slot reads "Missing" in the week row (as the Schedule screen does).
