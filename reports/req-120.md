## Workflow

1. **Contradiction in the spec.** The spec sets the default to `legacy:false` and says every other test passes
   unmodified. But `model.test.js:66–84` calls `migrateState(source)` with no options, on a v5-shaped fixture
   (`programs`, no `schemaVersion`), and asserts that the baseline refills. I stopped rather than choose. Both fixes
   were measured green (`# pass 450  # fail 0`) and then reverted:
   - **(A)** A third test edit at `model.test.js:79`: `migrateState(source, { legacy: true })`. The fixture is
     legacy by the spec's own `applyBackup` rule.
   - **(B)** Change the default to infer legacy from the input: `schemaVersion != null ? !== 9 : sessions/programs
     present`. No test edit is needed. The merging callers still pass the flag explicitly, and v9-shaped input
     still defaults to never-invent.
   - I lean towards (A). It keeps the spec's explicit safe default, and the test's input really is legacy.
2. **Two named test edits** (`skip-replace.test.js`): :297 "guard is load-bearing" and :449 "control: own logged
   set still backfills". Both now assert `[]` on a v9 reload. This is a reversal driven by DESIGN §1/§3, not a
   weakening: the backfill they proved no longer exists on v9. What they used to prove moved into two new legacy
   tests, so nothing is lost.
3. **Unconfirmed:**
   - how a backup with no version is classed
   - the `legacy:false` default
   - no cleanup of values already backfilled on v9
   - the no-snapshot branch keeping its logged-set reconstruction
4. **Follow-up:** for a v9 user, any routine item with empty lists that the old baseline used to refill will now
   show empty. That is the intent, but it is visible (req-118 depends on it).
