69 exports = 70 named − `lastLoggedSetIndex`. Private helpers went with their only user: `skippedSet`,
`pushSkippedUnloggedSets`, `prescribed` and `stopwatchItemKey` → items, `weightSeedString` and `sameWeight` → set-seed, `pillItem` → progress.

**Why `itemLoggingState` and `itemIsMarkedDone` moved to items (a choice the spec left open).** The spec's table has two
cycles. (1) items ↔ progress: `canRemoveAddedSet` and `removeAddedSetPatch` (items) call `itemLoggingState` (progress), and
progress needs `itemKey`, `setsForItem` and `workCountFor` (items). (2) progress ↔ timers: `workoutPillState` needs
`restRemaining` (timers), and `stopwatchOwner` (timers) needs `itemLoggingState` and `itemIsMarkedDone` (progress).
Moving the two single-item questions down to items breaks both, and items becomes a leaf (only `set-rules.js`).
`itemIsMarkedDone` sits next to `markItemDonePatch` / `reopenItemPatch`, which write the same mark. I kept `pillItem` in
progress with both its users (`workoutPillState`, `workoutPosition`), so it needs no new export.

**How.** A script (kept outside the repo) cut the file at top-level declarations. Each block took every comment paragraph above it,
so the stopwatch section comment went with `stopwatchFor`. The script wrote each module and rewrote every importer's
`workout-log` import into one import per owning module. It regenerated from `main` with the cumulative module list per
commit, so every intermediate `workout-log.js` imported only from modules already extracted, and none of those imported it back.
`isAddedMidWorkout` / `isSkippedSet` importers now import `set-rules.js`, merged into an existing set-rules import where one was
there. `views/workout/item.jsx` imported `'../../workout-log'` (no extension); its new imports use `.js`.
