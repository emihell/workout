**Boundary change from the spec (a choice it left open): `SetEditSheet` → `set-log-form.jsx`, not `sets.jsx`.** It
uses `CardioFields` and `EMPTY_CARDIO`, which the spec keeps private to set-log-form. Keeping it in `sets.jsx` would have meant
exporting those two privates for one sibling. It is also the edit-mode twin of `SetLogForm` (same fields, same kg/duration gate).
This leaves `sets.jsx` with 3 components, not 4.

restRemaining), `set-seed.test.js` (8 describes, incl. "durationTargetFor / setTargetFor", which also calls

**How.** I wrote the scripts outside the repo, as in req-270. They are in the session scratchpad (`split.mjs`, `splittest.mjs`, `c1-bodies.mjs`,
`c2-imports.mjs`, `c3-load.mjs`, `qa-walk.mjs`). They parse with `rolldown/parseAst`. A block is a top-level declaration plus the comment lines
above it, so section headers (`// ---- Controls ----`, `// ---- Molecules … ----`) go with the next declaration. The scripts
regenerate from `main` with the cumulative module list per commit. A module imports only the specifiers its blocks read, and
`export ` is added only where a sibling reads a private. New intra-folder imports use explicit `.js`/`.jsx`. App importers of
`ui` stay on `ui/index.jsx`. The 3 app screens still come through the `views/workout/index.jsx` barrel, which now takes `WorkoutItemDone` from `./review.jsx`.
