# req-129 — planning tooling fixes

Branch `req-129`. Tooling only: `plan`, `.githooks/pre-push`, `scripts/`, `package.json`. No app code, no stored data.

## Technical

1. **Nested worktrees skipped** (`plan` `worktree_is_nested` + `find_worktrees`). A worktree whose path sits under
   another listed worktree's path (`<code>/.claude/worktrees/agent-*`) is never a candidate. It's a path-prefix test
   against the other `git worktree list` entries, so no directory name is hardcoded and the branch-keyed design stays.
   If two non-nested non-planning worktrees exist, the last one still wins, as before (out of scope).
2. **Pre-push exemption** (`.githooks/pre-push` `never_moved`). A `req-*` tip found on main's new first-parent spine
   is exempt only when every reflog entry for that branch starts with `branch: Created from `. Any other entry (commit,
   merge, reset, rebase) means the branch moved, so the push is refused. An empty or missing reflog also refuses.
3. **Closeout reviewer warning** (`plan` `reviewer_warning`, step 4c; repeated after the final "Still yours" list
   because publish's `./check` output scrolls it away). It diffs `merge^1..merge`, drops `*.test.*` files, and matches
   `REVIEWER_TRIGGER_RE` (`src/` store*, model, storage, progress, workout-log, migrat*, load*, exchange, import-backup).
   Then it reads `reports/req-N.md` from the merge commit and greps it for `reviewer` (case-insensitive). It never blocks. If there's no merge
   commit (a FF'd re-run), it doesn't run.
4. **`npm run shot`**: `--click "<text>"` (repeatable, in order). It prefers an exact trimmed-text match among visible,
   enabled `button, a, [role=button], summary, label`, and otherwise takes the one element that contains the text.
   None found, or an ambiguous partial match, gives exit 1 with no PNG. `--scroll-bottom` scrolls the window and every
   scrollable container. **`scripts/capture.mjs`** (`npm run capture -- --base <ref> --head <ref>`) is req-122's
   `shots.mjs` + `compare.mjs`, made repo-relative:
   - builds each unique sha from `git archive` into a temp dir with a node_modules symlink, so no worktree is registered;
   - uses the same 23 screens, a frozen clock, and `--seed` (default `src/db.json`);
   - builds the active-workout seed through the UI on the base build and writes it to `<out>/active-seed.json`;
   - exits 0 if all identical, 1 if any differ, 2 on an error or on 0 screens compared.

## Workflow

- **Choices the spec left open:**
  - The exemption refuses on *any* non-creation reflog entry, not only `commit:`. This is stricter than the wording.
  - The trigger set adds `exchange`/`import-backup` (the backup load path) and excludes test files.
  - The reviewer match is a bare case-insensitive `reviewer`, so a report saying "no reviewer" also silences the
    warning. That follows the spec's wording, but it's loose. It could be tightened to `Reviewer:` if wanted.
  - The capture builds from committed refs only; uncommitted work needs a commit first.
- **Known limit (pre-push):** a branch made with `git branch req-N <sha-with-unmerged-commits>` and then FF'd has a
  creation-only reflog, so it's exempt. It's unusual, but a possible `L-`.
- **Sandbox note:** this agent's isolation refused compound/`source` shell commands, so `find_worktrees` was checked
  only through the fixture self-tests. It wasn't run against the live `git worktree list`.
