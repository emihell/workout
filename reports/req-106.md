# req-106 — start-of-exercise set preview

## Technical

- `src/workout-log.js`:
  - `setPreview({ item, ex, weighted, hasHistory, historyFor, seedOverrides })` returns one entry
    per set (WU first), each built by calling `initialSetFields` with restore/carry null, the
    set's history (`historyFor` = the view's `historySetPrefill(last, …)`), its target, and the
    `seedOverrides[exerciseId::setType]` override. That is the form's own seed path, so the two
    can't drift. Timed work sets carry `durationSec` in place of reps.
  - `setPreviewText` formats a line.
  - `durationTargetFor` is the req-85 duration rule, moved out of `item.jsx`.
  - `setTargetFor` is the target rule, moved out of `item.jsx` for the same no-drift reason.
    `WorkoutItemLive` now calls both helpers, with unchanged semantics.
- `src/views/workout/item.jsx`: renders `<ul class="ui-setpreview">` under `SetLogForm` while
  `logging && state.logged.length === 0`. Completing or skipping set 1 pushes a set, so the
  preview disappears. It's read-only, with no handlers.
- `src/ui/ui.css`: `.ui-setpreview` uses caption size, `--ui-ink-2`, tabular numbers and normal flow,
  and relies on `.ui-main`'s dock-clear padding.
- Import cycle: `workout-log.js` now imports `DEFAULT_DURATION_SEC` from `model.js`, which already
  imports `workout-log.js`. It's safe because the constant is only read at call time. Tests and the
  build both pass.

Verified:
- `node --test src/workout-log.test.js` → `# tests 70 / # pass 70 / # fail 0`
- `./check` → `check: green — lint, 23 test file(s), and the build all passed.`

Acceptance criteria:
- Fixed numbers (unit): the output is exactly `['WU · 10 kg × 10','1 · 20 kg × 8','2 · 22 kg × 8','3 · 24 kg × 6']`. The fixture uses targets 8/8/6 and WU reps 10, so these reps come from targets (see Workflow).
- Right mechanism (unit): each line's weight/reps is asserted equal to `initialSetFields` for that set.
- No history (unit): every line's weight is `''`, shown as `—`. Reps come from the targets. There are extra tests for an unfinished workout and for a set index beyond the history (no copied kg).
- Bodyweight / timed (unit): bodyweight gives `1 · 12`. Timed gives `WU · 5`, `1 · 45s`, `2 · 60s`, `3 · 60s`.
- Session override from an earlier item of the same exercise (unit): the override shows. Another exercise's key doesn't leak in.
- Shows at start (screenshot): `screenshots/req-106.png` shows Chest Press (db.json, WU + 3) with
  `WU · 10 kg × 12`, `1 · 30 kg × 12`, `2 · 35 kg × 11`, `3 · 35 kg × 9`. It sits below the fields and
  well clear of Skip/Complete.
- Gone after a set (screenshot): `screenshots/req-106-after.png` was taken after the WU was logged. There's
  no preview, and set 1's form shows 30 × 12, which matches preview line 1.

Choices the spec left open:
- Line format: `N · kg × reps`. A missing kg shows `—`, and a missing reps value also shows `—`.
- Bodyweight lines show the reps number with no unit.
- A timed set shows `Ns`, as `formatSetLine` does.
- Placement: directly under the form rather than pinned above the action bar.

## Workflow

- Spec wording: "weights and reps from that history" isn't quite what the form does. The form's reps
  come from the snapshot **targets** (`setLogSeed`), not from history reps. The preview follows the form,
  which is the spec's own mechanism rule. For a routine planned from history the two are usually the same.
- Extra change inside the scope files: `setTargetFor` was extracted alongside the duration rule so the
  target can't drift between form and preview.
- If "Previous" undoes the only logged set, `logged` is empty again and the preview comes back. In that
  state set 1's form shows the restored values, but the preview line shows the seed. This is rare, and I left it alone.
- Not verified: how it feels on a real device, and a timed exercise in the browser (covered by unit tests only).
