## Technical

**What changed**
- **Overview row "⋯"** (`views/workout/overview.jsx`): each row that isn't done gets a quiet `⋯` Button (`aria-label="Swap or skip <name>"`, class `ui-row-menu`). It opens one sheet: **Swap exercise · Skip exercise · Cancel**. Skip calls `store.skipItem` directly, so it is one tap once the sheet is open. Swap navigates to `/item/<key>/replace`. Done rows show no `⋯`.
  - `Row` (`ui/index.jsx`) now renders `action` after the link on a link row. The `⋯` sits outside the `<a>`, so it is its own tap target. No existing caller passes both `to` and `action`; I checked every `action=` caller.
  - The sheet is the req-187 one. `ui/confirm.js` gains `askChoice(message, { title, choices })`, which resolves the chosen value or `null`. `answerConfirm` still resolves a boolean for a plain `askConfirm`. `ConfirmSheet` stacks the choices above Cancel.
- **"Add exercise"**: a chevron NavLink under the list, above Note/Finish. It opens a new route `/workout/<id>/add` (`workout-add`) → `views/workout/add.jsx`. That screen is the `ExercisePicker`, multi-select, "Add N" → `store.addWorkoutItems` → back to the list.
- **Log screen** (`item.jsx`): Skip exercise (with its two-tap arm state and timer) and the Swap NavLink are removed. Remove set and Skip rest stay. The bar's Skip now reads **"Skip set"** (`ui/index.jsx` SetLogForm).
- **Swap screen** (`replace.jsx`): now `ExercisePicker` with `max={1}` and `addLabel → 'Swap'`. Back and Cancel go to the overview. A pick runs `store.replaceItem(key, exerciseId, prescription)` and then lands on the new item's log screen, as req-124 did.
- **Reducers** (trigger files):
  - `workout-log.js` `replacementItem({…, prescription})`: given a prescription, it takes `sets/targets/suggestedWeights/durations/restSec` from it. It keeps the original's role, `warmup: null`, `notes: ''` and `addedMidWorkout: true`. Without one, it builds the same item as before.
  - New `appendItemPatch(workout, item)`.
  - `state-reducers.js` `replaceItemInState(s, itemId, exerciseId, id, prescription = null)`.
  - New `itemsAddedState(s, [{id, exerciseId, item}])`: unknown exercise → skipped; nothing added → same `s`.
  - `store.jsx`: `replaceItem(itemId, exerciseId, prescription = null)` and the new `addWorkoutItems(added)`.
- **Callers of what changed:**
  - `replacementItem`: `replaceItemInState`, `itemsAddedState`, and tests req-119/125/178/186 plus skip-replace. All omit `prescription`, so their behaviour is unchanged.
  - `replaceItemInState`: `store.replaceItem`, plus tests req-124/178.
  - `store.replaceItem`: `replace.jsx` only.
  - `Row`: every caller. Only the overview passes `to` + `action`.
  - `askConfirm`/`answerConfirm`: unchanged for every existing caller.
- **No schema change, no new persisted field.** Added and swapped items use the existing `addedMidWorkout` marker. A unit test shows an added item survives `migrateState` reload byte-for-byte (not backfilled from the routine's copy), and that Finish + recalc leave the routine as it was.
- **WorkoutPill** (`currentWorkoutItem`): the code is unchanged, and it is tested for both cases:
  - Swap after a logged set → the pill points at the replacement.
  - Added item → it becomes current once the items before it are done. It stays current while it is being logged. If A is in progress, the pill stays on A.

  - A pick with no history goes through a step: **Sets** (required, a whole number ≥ 1) and **Rest (seconds)** (optional; blank → `restSec: 0`, no rest timer). Reps, kg and durations start blank.
