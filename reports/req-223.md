# req-223 — Start opens the first exercise; an "Up next" bar on each arrival, 5 s, Skip / Swap

## Technical

**What changed**
- `src/up-next.js` (new, JSX-free) — the arrival marker: `markArrival(routineId, item)`, `arrivalFor(routineId, item)` (pure
  read), `clearArrival()`, `UP_NEXT_MS = 5000`. One module-level variable: **never localStorage, sessionStorage or the workout**.
  A reload resets it, so a refresh never shows the bar.
- `src/workout-actions.js` `startOrContinue` — a **new** workout reads the plan it is about to snapshot (`config.plan`, else
  `store.getPlannedWorkout({ routineId, date: scheduledFor, scheduleSlotId })`, the same args `startedWorkoutState` builds
  with), marks `plan.items[0]` and lands on its `/log`. Empty plan → the overview, as before. Continue → `resumeTarget`, unchanged.
  `store.jsx` is not touched.
- `src/views/workout/workout-helpers.js` — shared `swapExercisePath(routineId, item)`, `skipExercise(store, item)` (the old
  rowActions body: `recordButton('skip-exercise'); store.skipItem(key)`), and `finishTarget(workout, routineId)` (the review's
  armed ? overview : /finish rule). `overview.jsx` `rowActions` now calls the first two (scope 4). The review's Finish link uses
  `finishTarget`.
- `src/views/workout/item.jsx`
  - `UpNextBar`: "Up next: {name}", "Starting in N…" (`aria-live="polite"`), Actions row: lateral **Skip** (Button) · **Swap**
    (NavLink, button look — navigation, DEC-040), forward **Start now** (Button, records `up-next-start-now`). Countdown =
    auto-complete.jsx's pattern (deadline in `useState`, 250 ms interval, `clearInterval` on unmount). At 0 it only hides.
  - `WorkoutItemLive`: `upNext` state = `arrivalFor(...) && no logged set`, read in the state initializer; `clearArrival()` in a
    mount effect (any item, so a marker whose screen never mounted can't surface later). Shown while `upNext && logged.length === 0`.
  - Skip from the bar: next is computed on `{ ...active, ...skipItemPatch(active, key) }` (the patch `store.skipItem` applies),
    then `skipExercise`, then `markArrival(next)` + `go(itemLogPath(next), { replace: true })`; none left → `finishTarget(after)`.
  - Review `Next:` link gets `onClick={() => markArrival(routineId, next)}`.
  - `WorkoutItemLog`'s markedDone → review redirect now only fires while the browser is still on that item's `/log` path
    (needed: the bar's Skip marks the item done and has already navigated in the same tap; without the guard the effect replaced
    the new route with the skipped item's review).
- `src/ui/ui.css` — `.ui-up-next` (outlined block, `--ui-line`, `--ui-radius`, existing type tokens; actions share the row).

**Choices the spec left open**
- Arrival marking: in-memory module variable (`up-next.js`), set right before navigating, read on the log screen's mount, cleared
  on any log-screen mount. Not a route query (a reload would keep it).
- Bar position: top of the log screen, under the pill / "‹ Upper Body" link, above the exercise title.
- Labels as the req's (unconfirmed): "Up next: {name}", "Starting in N…", "Skip", "Swap", "Start now". Swap is a link with the
  button look (navigation, DEC-040); Skip and Start now are Buttons; Start now is the forward (right) action.
- Skip from the bar **replaces** the history entry (the skipped exercise's log screen would only bounce to its review); Next and
  Start push as before.
- Start now records analytics `up-next-start-now`; the bar's Skip records the shared `skip-exercise` (same id as the list).

## Review round 1 (commits 907735c, d8a90ba)

### Technical

1. **nit — redirect guard on a string** (`item.jsx` `WorkoutItemLog`): it now compares the parsed route
   (`parseRoute(hashPath(location.hash))`: name `workout-item-log` + routineId + itemId), so `…/log?x=1` and `…/log/` redirect a
   done item to its review again, as main did. Test: done Chest Press opened at `…/log?x=1` and `…/log/` → its review.
2. **nit — modified click on Next leaves a marker**: the review's Next link calls `markNextArrival(e, …)`, which marks only on a
   plain left click (no meta / ctrl / shift / alt, `button === 0`). I chose this over "clear on any route change": it keeps the
   marker's one owner (the log screen's mount) unchanged. Test: each modifier and a middle click → no marker; a plain click → marked.

   draftSnap pattern), so the bar can't come back. Test: Lat Pulldown with the bar → Done (warm-up; stays on the screen) → the set
   removed through `store.patchActive({ sets: [] })` → still no bar.
