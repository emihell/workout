# req-181 — Start from a plan: days per week, fill the slots (report)

Branch `req-181` from main `d541289`. **Trigger file touched: `store.jsx`**: one new action, `applyPlan`. No other store
change. No schema change and no migration. Save writes only new routines, items, exercises and (on an empty schedule)
slots; the one exception is an archived exercise picked with "Use mine", which is restored (`archivedAt` → null), as in
req-180.

## Technical

- **Library (Change 6).** The 7 dip rows in `src/library/common.js` changed from `vertical-push` to `horizontal-push`,
  and `exercises.json` was regenerated with `node scripts/build-library.mjs` (sha-pinned source). Before changing
  anything I re-ran the build on the unchanged tables; the output was byte-identical, so the script is deterministic.
  The diff is 7 `pattern` lines, plus a comment.
- **`src/plan-templates.js`** (pure):
  - `SLOTS`: the slot names and their patterns. `PLAN_TEMPLATES`: 1–4 days, with routines and `week: [weekday, routine]`.
  - `slotFilters(patterns, library)`: the `{ ownFilter, libraryFilter }` passed to the picker. An own exercise matches
    by `libraryId` → entry → pattern, so a manual one has no pattern.
  - `slotCandidates(patterns, exercises, library, workouts)`: `{ own, staples, rest }`.
  - `planIds`: see the store bullet below.
  - `planToState(state, choices, ids)`: composes the existing reducers (`exerciseFromData`, `exerciseAddedState`,
    `restoreExerciseInState`, `routineAddedState`, `routineItemAdded`, `slotAddedState`). What it does:
    - A library entry picked in several slots becomes one record.
    - A day with nothing chosen makes no routine and no slot.
    - The week is added only when the schedule has no slots. It then sets `loopWeeks: 1`, keeps the anchor (or sets
      one via `withDefaultAnchor`), and puts every slot in week 0.
    - Routines are `{ id, name, focus: 'Machines', exercises }`, the same shape as `store.addRoutine`.
- **`routine-picker.js`**: new `filteredBrowse(catalog, filter)`, returning listable staples and the rest, A→Z. The
  picker and `slotCandidates` both use it.
- **`ExercisePicker`** changes, all backward compatible (req-180's 12 tests still pass unchanged):
  - `ownFilter` / `libraryFilter` now narrow only the empty-search view; typing searches everything (Change 3).
  - With a `libraryFilter`, the empty search shows the filtered staples and "Show N more" instead of the muscle groups.
  - New props: `onPick` (returns picks, writes nothing), `max` (1 = a tap replaces the selection), `addLabel`, and
    `lateral`.
- **`store.jsx` `applyPlan(choices)`**: one `setState` running `planToState`. The ids come from `planIds`, generated
  before the updater, and each call reuses the same ids. So an updater that React runs twice (StrictMode), or runs
  late, builds the same records. The returned `{ routineIds, scheduled }` comes from the same reducer on the current
  state.
- **Views and routes:**
  - `/routines/new` is now **two starts**: "Start from a plan" (primary) and "Blank routine" → `/routines/new/blank`
    (`RoutineNewBlank`, the unchanged `RoutineNewForm`).
  - `/routines/new/plan[/days[/r/s]]` → the single `RoutinePlan` component (`views/Plan.jsx`). It holds the choices in
    memory across its steps:
    - **days choice:** a row per split, listing each routine's slots.
    - **fill screen:** a section per routine; each slot row reads "Choose", "Skipped", or "*name · plan line*".
      Cancel / Save.
    - **slot picker:** the filtered picker, single-select, with Cancel / Skip (lateral) / Use.
    - **done screen:** shown only when the schedule already had slots: "Add them to your schedule" → Schedule, or Home.
  - Save → Home when the week was scheduled.
- **Test edits:**
  - `req-122.test.js`: the `<Actions>` count pin, 17 → 18 (the plan's Cancel / Save row).
  - `req-179.test.js:87`: now renders `RoutineNewBlank`, because the name form moved off `/routines/new`.

## Workflow

- **Spec conflict (needs Planner):** AC6 fills only Full body A's slots in the 3-day plan, then expects Schedule to show
  Mon/Wed/Fri. Change 4 says "a day with every slot skipped makes no routine and no slot", and AC4 enforces the same
  rule. I built Change 4, so AC6 as written gives **Monday only**. To see Mon/Wed/Fri, fill at least one slot in each of
  A, B and C.
- **Choices the spec left open:**
  - A slot left on "Choose" counts as skipped at Save; an explicit **Skip** is the lateral button in the slot picker.
  - Save is disabled until at least one slot is chosen.
  - Cancel on the fill screen → `/routines/new`.
  - "Blank routine" is a link to its own route, `/routines/new/blank`. That is one extra tap compared with the old
    `/routines/new` form.
  - The done screen appears only when nothing was scheduled; otherwise Save goes Home (Change 5).
  - Routines get `focus: 'Machines'`, as `store.addRoutine` does (unread, DEC-099).
- **Picker semantics changed:** `ownFilter` / `libraryFilter` now apply to the empty search only. req-180 passed no
  filters, so nothing it does changes.
- If the library fails to load in a slot, the picker shows "Could not load." and your own list without the pattern
  filter (the filter needs the library).
