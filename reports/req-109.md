# req-109 — Skip exercise / Replace exercise mid-workout (F2 + F8)

## Technical

**What changed.** No `STORAGE_KEY` or `SCHEMA_VERSION` change, and no bulk rewrite. The only new persisted
field is `addedMidWorkout: true` on a replacement's snapshot item, written only when the user replaces an
exercise.
- `src/workout-log.js`: `pushSkippedUnloggedSets` is now a separate function, moved out of
  `withSkippedUnloggedSets` unchanged. New: `skipItemPatch` (remaining sets → `skippedSet` + mark done),
  `replacementItem` (blank item: 1 set, `targets: []`, `suggestedWeights: []`, `warmup: null`, notes `''`,
  the original's role, rest passed in, unique `id` = `routineItemId`, `addedMidWorkout: true`),
  `replaceItemPatch` (skip + insert directly after), `isAddedMidWorkout`, `itemAllSkipped`.
- `src/model.js` `workoutSnapshot` (snapshot branch only). This is the whole behaviour change:
  1. `if (isAddedMidWorkout(item)) return item`. No template match (by id or by `exerciseId`) and no
     targets/weights backfill.
  2. Other items' `actualWorkingSets` drop sets whose key belongs to a mid-workout item
     (`!midWorkoutKeys.has(setItemId)`).
  3. `itemByExercise` (used to attribute key-less legacy sets) skips mid-workout items.
  If a workout has no marked item, `midWorkoutKeys` is empty and all three are no-ops.
- `src/store.jsx`: `skipItem(itemId)` and `replaceItem(itemId, exerciseId)`. Id `uid('mid')`, rest from
  `historyPrescription(workouts, exerciseId)?.restSec`, else 0.
- `src/route.js` + `workout-paths.js` `itemReplacePath`: `/workout/:r/item/:id/replace` →
  `workout-item-replace`. `App.jsx` and `views/workout/index.jsx` wire up the new `views/workout/replace.jsx`.
- `item.jsx`: on the live log screen, a row below the set preview holds **Skip exercise** (Button, two taps,
  "Tap again to skip", resets after 3 s) and **Replace exercise** (NavLink with the button look, DEC-040).
  `overview.jsx`: a done row whose sets are all skipped reads `· skipped`. `ui.css`: `.ui-exercise-actions`.

## Workflow

- Choices the spec left open: the marker is **`addedMidWorkout`**, not `adHoc`, because `adhoc-` already
  means an unscheduled routine occurrence id. The picker route is `/workout/:r/item/:id/replace`. The controls
  are a row of two quiet buttons below the preview, left to right Skip exercise · Replace exercise, both lateral,
  so the set-level Previous · Skip · Complete bar is unchanged. The picker has `‹ Back` at the top, a "Replace"
  button per row (picking writes), and Cancel at the bottom. The arm timeout is 3 s. The picker does not exclude
  the original exercise (the spec only excludes archived ones).
- Added beyond the spec: `workoutSnapshot` guards 2 and 3 above. Without them, a replacement's logged sets
  could backfill another item of the same exercise whose targets are empty.
- Skip exercise leaves the rest timer running. Per-set Skip clears it. My reasoning: the rest armed by the last real set still applies.
  Emilio may want to confirm this.
- Not verified: real-device feel of the two-tap timing, and whether the picker's Cancel (below a list of about 23
  rows) is needed next to Back.
- Follow-ups: history detail (`detail.jsx:61`) matches snapshot items by id **or** `exerciseId` (first hit wins). When a replacement is the same exercise as a later routine item, that item's row can show the replacement's role and WU tag [inferred, not run]. It works
  here, but it is fragile for duplicate exercises. Also, removing a mis-picked replacement is out of scope,
  as the spec accepts.
