# req-234 — `accounts.mjs passwd <user>`

## Technical

- `server/auth.mjs` — `setPassword(db, username, password)`: refuses an unknown or disabled user, applies `checkPassword` (≥ 6) and
  `hashPassword` (the bootstrap's scrypt), then in one transaction updates `users.password` and deletes all that user's sessions.
  Returns the number of sessions ended.
- `server/accounts.mjs` — `passwd <u>`: checks the user exists and is enabled **before** prompting, reads `New password:` / `Again:`
  with the bootstrap's `readPassword`, refuses a mismatch, then calls `setPassword` and prints
  `Password changed for <u>; N session(s) ended.` Every refusal goes through the existing `catch` → exit 1, and nothing is written.
- `readPassword` change (shared with bootstrap): with piped stdin, the old version opened and closed a readline per call, so a second
  prompt would lose the second line. Now one readline serves the whole run (one line per prompt) and is closed in `main`'s `finally`.
  Bootstrap's single read behaves as before (guards.test.mjs bootstrap test still green).
- `server/req-234.test.mjs` (new, 2 tests): the real subprocess against a `startTestServer` temp data dir, over HTTP.
  - AC1: two live sessions → `passwd` → both get 401 on `/api/state`, the old password's login is 401, the new one's is 200, and the
    printed N equals the session count before the change.
  - AC2: unknown user, mismatch, `short`, empty input, and a disabled user → exit 1 with the message, empty stdout, and the stored
    hash byte-identical. An existing session still gets 200 after the refusals.

**Receipts**
