## Workflow

- **Stale fact:** the req says the sticky bar has no background (BACKLOG req-180 follow-up). On `main`, `.ui-picker-bar`
  already has `background: var(--ui-bg)` (`src/ui/ui.css:268-275`). The new dock gives the strip and bar a single
  background, so nothing shows through the gap between them.
- **Spec vs code (open call 1):** the req's fact calls `/exercises` "every non-archived own exercise, grouped by type",
  but the screen is a drill-down: type rows with counts that link to `/exercises/type/X` (commit 1add816). I kept the
  drill-down: each section has its own type rows and counts. The type page is split into the same two sections, so the
  count you tapped matches the section you land in. I added no route parameter. The alternative was listing exercises
  inline under each section, which would undo the 1add816 decision ("instead of dumping the full lists"). I did not stop
  to ask.
- **Choices left open by the spec:**
  2. The strip shows up to 3 names; 4 or more → the first 2 and `+N`, and `+N` expands to all. Taken from the req's
     example ("Row, Incline press, +2") plus AC1 ("tick 3 → lists 3").
  3. No strip when `max === 1` (the plan slot's "Use" picker). A tap replaces the pick there, so the tick is the whole
     preview.
  4. The strip shows names only (no equipment): the own name or the library display name.
  5. A ticked row that is already in the workout reads `In this workout · <plan>`.
  6. The strip also appears in the machines-first picker (Plan.jsx) and the mid-workout Add picker, since they use the
     same component. The req allows this for the mid-workout picker ("it gets 1 only").
- Unconfirmed behaviour calls from the req were implemented as written: the section names, the "Added: …" text, and
  marked-not-blocked rows.
