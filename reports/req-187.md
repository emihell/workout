## Technical

**What changed**
- `src/routine-update-offer.js` — `routineUpdateOffer` untouched. New:
  - `offerOnFinishingSet(active, routines, item, setRecord, finishes)`: the call site's decision. When `finishes`, it is
    `routineUpdateOffer` over `withLoggedSet(active, setRecord)`, the store's own append, so the finishing set is
    included. Otherwise null.
  - `offerSheetText(offer, exercise)` returns `{ title, body, keepLabel, updateLabel }`.
- `src/views/workout/item.jsx` — `completeSet` and `skipSet` build `setRecord` once. The finishing set goes through
  `finishExercise`, which does three things in order:
  1. computes the offer;
  2. calls `markDoneAndGoToOverview`, the same as before;
  3. calls `askRoutineUpdate` only when there is an offer.
  `askRoutineUpdate` uses `askConfirm(...)` with `stayOn: '/workout/<id>'`. Update calls `store.applyRoutineUpdate(offer)`.
  Every other answer writes nothing. `store.completeSet` (rest armed) runs before any of this and is unchanged.
- `src/ui/confirm.js` + `ConfirmSheet` (`ui/index.jsx`) — `askConfirm` takes three new optional fields: `title`,
  `cancelLabel` (default "Cancel") and `stayOn`. There is also a new pure `navigationCancels(open, hash)`. A hashchange
  onto the `stayOn` path does not dismiss the sheet. Any other navigation still answers false. Existing callers see no
  change because the defaults match today's behaviour. The confirm button was already `ui-btn--primary`, so no styling
  change was needed. `ui.css` adds `.ui-sheet__title`.
- `src/views/workout/overview.jsx` — the inline `RoutineUpdateOffer` row is removed. The summary gate is now
  `autoCompleteArmed(active) && !sheetOpen`, where `sheetOpen` comes from `useSyncExternalStore` on the confirm store.
  The summary therefore mounts, and its 10 s countdown starts, only after the sheet is answered.
- `src/views/workout/auto-complete.jsx` — restored byte-for-byte to its pre-req-178 version (`740bc82~1`), plus one
  req-187 comment. It has no offer section and no countdown hold.
- `src/views/workout/routine-offer.jsx` — deleted (no callers left). `offerText` is kept: it is pure, tested in req-182,
  and has no UI caller now.

**How the hashchange trap was handled:** I didn't rely on the order of events. The sheet carries `stayOn`, so the
navigation to the overview does not dismiss it, whenever that navigation's hashchange fires. The browser receipt below
checks the hash after an 800 ms wait. It is `#/workout/sess-upper` and the sheet is still open.

## Workflow

**Choices the spec left open (behaviour, unconfirmed)**
- **Skipping the last set also opens the sheet** when earlier sets differ. The offer then carries only the logged sets,
  and the skipped one keeps the routine kg, per `routineUpdateOffer`. The spec says "Complete". Without this, an
  exercise finished by Skip would lose its offer entirely now that the inline row is gone. Skip exercise (two-tap)
  never opens a sheet.
- **Uniform lists collapse in the wording:** "You lifted 25 kg · Upper body says 20 kg" and "Keep 20 kg". Mixed lists
  read per set ("25/25/17.5"). When the routine has no kg, the body is "… · not in {routine} yet" and the button is
  **"Keep blank"**.
- **Any other navigation while the sheet is open (e.g. device Back) counts as Keep.**
- **The overview list shows under the sheet on the last exercise,** and the summary mounts once the sheet is
  answered. The summary is deferred while any confirm is open, not only this one. Nothing else can open a confirm
  there today.
- Analytics: `routine-update-apply` / `routine-update-keep` button counts.

**Deviations:** no scope added or dropped. `store.jsx` is untouched, so the reviewer trigger doesn't apply. No schema
change and no bulk write.
