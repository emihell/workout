## Workflow

- **Scope added:** the 7 "explicit unmount/re-render" files (req-218's second list) were converted too. They weren't reloads on
  purpose; they unmounted only to show the screen after Start. That needed `render().rerender` in `test-support/render.js`, which is
  additive: no existing caller changes.
- **Choice:** the converted harnesses key the screen per `mount`, so a screen never carries React state into the next `mount` of the
  same component. That keeps each test's old screen semantics; only the provider changes.
- **A test expectation of mine, corrected before commit:** the History case first expected `reps: 9`; stored reps are text (`'9'`,
  schema.md). The same case needed an effort ("Easy") so that Apply has a recalculation to write. Without one, the progression keeps
  the routine as it is.
- **No product bug found.** Every converted test passed as it stood.
- **AC4 reading:** I read "reverting the req-220 staleness fix" as "the path writes a field FIELDS does not describe", tested by a
  planted field per path. If Planner meant something else (e.g. deleting a FIELDS entry), the same script takes a different needle.
- Possible L- (Planner's call): a keyed screen swap (`h(Screen, { key: n, child })`) is the L-051 harness for tests that remount the
  same component with new props. Without the key, React reuses the instance and its state.
