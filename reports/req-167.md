1. **One comparator** (`history-queries.js`).
   - `workoutTime(w)` is `Date.parse(finishedAt)`, else the local day of `performedOn`/`date`, else NaN.
   - `compareWorkoutsNewestFirst` puts the later time first, an unreadable one last, ties by id (desc).
   - `finishedNewestFirst` sorts by it. `sortWorkoutsByDate` (History) keeps its day-key grouping and breaks ties
     within a day with it.
   - Found on the way: `workoutDateKey` turned an unreadable `finishedAt` into `'NaN-NaN-NaN'`, which sorted before
     every real date and would display as "NaN". It now falls through to `'unknown'` (sorted last, "Unknown").
2. **No finishedAt.** Migration's guarantee, pinned: `migrateState` never adds a `finishedAt`, so there's no invented
   time (DESIGN §1), and it keeps `date`/`performedOn`.
   - Such a workout is now **kept** in the priors and the prefill, placed by its date.
   - A workout with no readable time at all is still not history (an existing req-106 test,
     "an unfinished workout is not history", guards it).
3. **Work → WU** (`SetEditForm`): a WU save sends `durationSec: ''` when the set carries a stored duration, which
   `historySetFields` turns into `null`. A set without one gains no key (req-163's pin still holds).
4. **WU → Work**: the stored rpe seeds Effort only when Effort shows for the set's **own** type. So a WU/cardio set's
   legacy rpe 3 starts unset in the Work form and saves `rpe: null`. A work set keeps its own effort.
5. **Test gaps.**
   - (a) `startedWorkoutState`: a supplied plan with a slot; `scheduledFor` + slot without a plan; unscheduled.
   - (b) The **real** `StoreProvider` (req-156 harness) drives every store action once, in sequence: 30 actions, all
     22 moved reducers plus the rest. It asserts the state each produces (argument order included) and that it reached
     `localStorage`.
