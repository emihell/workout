# req-233 — link library ids on a copy of Emilio's Export

## Technical

**What changed**
- `scripts/link-library-ids.mjs` (new), shaped like `fill-routine-kg.mjs`. It has a `LINKS` table of 39 names → ids, written out explicitly, a
  `HIDDEN_OK` allowlist of exactly 3 names, and `EQUIPMENT` Kettlebell → Kettlebells. It deep-clones the input document and changes only those
  two fields. Every name and id is checked before anything changes: each name matches exactly 1 exercise, each id is in the library, no
  `mergedInto`, no `hidden` unless the name is allowlisted. It then self-checks the result: `applyBackup` counts on input and copy, and a
  field-level diff. If any field other than `exercises[].libraryId` or `exercises[].equipment` differs, it refuses. `--out` refuses the input
  by path, symlink or hard link (the same code as fill-routine-kg).
- The copy is the **raw input document** with the fields set, not the `applyBackup`-migrated state that fill-routine-kg writes. That is the
  only way "a field diff of input vs copy lists only libraryId/equipment" can hold. Import still migrates it as usual.
- `WORKOUT_LIBRARY` env var: the failure tests point the script at an edited library. The real run never sets it.
- `src/req-233.test.js` (new, 9 tests). The fixture Export holds every mapped name; the test reads the name list from the script's `LINKS`.

## Workflow

- **The spec was wrong, and I stopped.** The first dry run refused 4 of the "resolved-as-today" ids because they are hidden (Arnold Press,
  Pirate Ships, Pass Between The Legs) or hidden and merged (Dead Clean → One-Arm_Kettlebell_Clean). Planner decided to allowlist the 3 hidden
  ones and leave Dead Clean unlinked. Emilio then said "do it": Dead Clean links to its merge target. Both amendments are on `planning`
  (0ec6231, 4f1d790), unpublished, so the spec on main still says 39 with the old breakdown.
- **BACKLOG finding: the name resolver doesn't skip hidden entries.** `libraryEntryFor` (`src/exerciseLibrary.js:588-595`) returns hidden
  and merged entries by name or alias, while the picker never offers them (`src/exerciseCatalog.js:54-57`, req-143). So an unlinked
  "Kettlebell Dead Clean" resolves to a merged-away entry instead of its target. A possible fix is to follow `mergedInto` and decide
  whether a hidden entry counts. That changes how any unlinked exercise resolves, so it needs its own spec.
- **BACKLOG finding (from the spec): Biceps Curl resolves to Dumbbell_Bicep_Curl by name.** That link is now fixed in Emilio's data, but the
  resolver itself is unchanged.
- **Choice the spec left open:** the copy keeps the raw input document rather than writing migrated state (see Technical). This differs from
  fill-routine-kg on purpose.
- The import itself was not run. That is Planner and Emilio's.
