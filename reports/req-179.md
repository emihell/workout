# req-179 — Routine form cleanup (report)

Branch `req-179` from main `36ed32e`. **No trigger file touched** (`store.jsx`, `model.js`, `storage.js`,
`progress.js`, `workout-log.js`, load/migrate). No schema change, no bulk write.

## Technical

**Focus (Change 1).** Removed both `Select label="Focus"` controls and the `focus` state/threading
(`views/Routine.jsx` `RoutineNewForm`, `RoutineNew`, `RoutineEdit`; `views/Schedule.jsx` `ScheduleDayAdd`).
`RoutineEdit` now saves `{ name }` only, and `store.updateRoutine` merges (`store.jsx:71`), so a stored `focus`
stays. The display is gone at every site: Routines row, detail meta, Schedule "Add routine" row value, Today
`WorkoutInfo` (5 callers), `TodayRoutine`, `HeroRoutine`, **plus a ninth site the spec didn't list:**
`views/workout/overview.jsx:61`, where the workout preview subtitle was `[plan.focus, plan.date]` and is now `plan.date`.
`FOCUS_OPTIONS` was deleted from `ids.js` because nothing uses it now (the only other mention is the literal list in
`ui/Showcase.jsx:193`, which I left as is). `formatTargets` was deleted for the same reason.

**Role (Change 2).** A `Checkbox "Warm-up exercise"` replaces the Role select. It saves through
`savedRole(storedRole, on)` in the new `src/routine-form.js`: on → `'warmup'`, off → `'main'`, but a stored
`finisher`/`cardio` stays. `RoutineExerciseNew` now defaults to `'main'` for every type.

**Warm-up set (Change 3).** A new item saves `warmup: null`; history's warm-up set is no longer copied in. An existing
item shows `Keep warm-up set (N reps)`, ticked by default. Save sends `keep ? item.warmup : null`, which is the same
stored object and is never rebuilt.

**Per-set fields (Change 4).** `PerSetField` (a view in `Routine.jsx`) shows one field, or one field per set
("Set 1"…, count = Sets) once "Different reps / kg / duration per set" is ticked. The helpers in `routine-form.js`
(`perSetStart`, `perSetCount`, `perSetValues`, `perSetText`) join the values with `/` and pass them to the unchanged
`parseRoutineItem`, so the parser's errors and their positions are the same as before. How the switch behaves:
- It is shown only when Sets > 1, or when it is already on.
- It starts on when the stored values differ.
- Turning it on copies the single value into every set. Turning it off keeps Set 1's value.
- When Sets grows, each new field starts with the value of the set before it (the parser already repeats the last value).
- If every per-set field is blank, the result is `''` ("not set"), the same as an empty single field.

**Words.** "Rest (seconds)". Row meta shows "Warm-up set" (`ids.js`). `README.md:8` and `exchange.js` have the text
from Change 5. The `focus` line is gone from the exchange example, and "WU" no longer appears anywhere in `exchange.js`
(this includes the `sets` note, "not counting a warm-up set"). The example item keeps its `warmup: { reps: 12 }`,
since it stands for an existing item.

**Test edit (AC7):** `ids.test.js:66`: `'WU set · 3 sets …'` → `'Warm-up set · 3 sets …'`. This is the label change
in Change 4. No other existing test was changed.

- **Added:** the ninth Focus display site (`workout/overview.jsx:61`, the preview subtitle). Change 1 says "no focus
  value on any screen", so I included it.
- **Choice the spec left open, AC3's "switch off again":** I tested it as save with the switch on, reopen, switch
  off, save → `'main'`. Turning the switch on and back off **in the same visit** keeps a stored finisher. That is

  AC the other way, `savedRole`'s input would need to change.

  Rest, and other forms (`set-edit.jsx`, `ui/index.jsx`) use "Duration (s)". This is a candidate for a plain-words
  follow-up. `ui/Showcase.jsx` (optional) was also left unchanged.

  specified.
