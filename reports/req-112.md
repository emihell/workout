# req-112 — Finish no longer rewrites the routine; recalc maths goes per set (DEC-056)

Branch `req-112`, off `main` @ 4e0bf23. Not merged.

## Technical

**What changed**

- `src/store.jsx`: `finishWorkout(args)` now calls `setState((s) => finishedState(s, args))`, and
  `recalculateFuturePlans(id)` calls `recalculatedState(s, id)`. `applyProgressionToRoutines` and
  `progressionFromWorkout` are gone from the store, so the store no longer writes the routine anywhere.
- `src/workout-log.js`: new `finishedState(state, args, finishedAt?)`. It is the old `finishWorkout`
  reducer with the `routines:` line removed. It still does the rest: drops seedOverrides, runs
  `withSkippedUnloggedSets`, stores `progression`, removes the plan and clears the active workout.
  Moving it out of the store makes it testable under `node --test`.
- `src/model.js`: new `recalculatedState(state, workoutId)`, which is the old recalc reducer moved
  unchanged. `progressionForItem` now passes **every** working set in log order (skipped sets
  included) plus `item.suggestedWeights` to `recommendNextPrescription`. `core.sets` is still only
  the non-skipped sets, so the `to`/`targetsTo` fallback and the `reason` text are unchanged.
- `src/progress.js`: `recommendNextPrescription({ targets, weights, sets, exercise })` now reads
  `sets` **by position**, so `sets[i]` is work set i.
  - A skipped, null or missing entry keeps `weights[i]` and `targets[i]`.
  - Each logged set is judged against `targets[i]`.
  - Result length is `max(routine weights, last logged index + 1)`, so it never shrinks.
  - Callers without `weights` (the old dense tests) behave as before.

**Every caller, and what it does now**

| Caller | Now |
| --- | --- |
| `recommendNextPrescription` ← `progressionForItem` (`model.js`) | the only production caller; gets positional sets and the routine weights |
| `progressionForItem` ← `buildFinishProgression` (`model.js`) | builds the `progression` stored on the finished workout. Record only, nothing reads it back (`history/detail.jsx:79`) |
| `progressionForItem` ← `progressionFromWorkout` (`model.js`) | recalc input |
| `buildFinishProgression` ← `finish.jsx:39` and `auto-complete.jsx:51` | → `store.finishWorkout` → `finishedState`. **No routine write** |
| `progressionFromWorkout` ← `recalculatedState` ← `store.recalculateFuturePlans` ← `recalc.jsx` Apply | **the only routine write left**, now with per-set maths |
| `applyProgressionToRoutines` ← `recalculatedState` | only production caller (the store no longer imports it) |
| beat-last-time (`beat-last-time.js`) | uses none of these, so it's unaffected |

**Choice the spec left open.** A skipped set **before** a logged set, at an index where the routine
has no weight, now gets `0`. Example: routine weights `[]`, set 1 skipped, set 2 at 40 → `[0, 40]`.
The app already uses 0 for "no weight": bodyweight sets record 0, and `routineItemMeta` and
`storage.js:397` treat all-zero weights as none. I didn't use `null`, because `join('/')` would show
it as "/40". A skipped set **after** the last logged set adds nothing to the result.
