# req-230 — the app logs in, opens offline, and syncs with the server

Branch `req-230` on `main` `6287ef6`. Nothing live: no server started except throwaway ones on temp dirs/free ports
(the test suites, plus two manual runs on `/tmp/workout-e2e-*`, removed afterwards). `ls -d ~/dev/workout/workout-data`
→ `No such file or directory` after all runs. Tailscale not touched. `workout-mvp-v9`'s shape is unchanged (no schema change).

## Technical

### Two builds, one code base (§1)

- `vite.config.js` `syncEnabled()` → the build constant `__SYNC__`. On only with `WORKOUT_SYNC=true`;
  `GITHUB_PAGES=true` always turns it off. `npm run build:server` = `WORKOUT_SYNC=true vite build --outDir dist-server`
  (`dist-server/` gitignored). `npm run build`, `npm run dev`, `plan qa`, the smoke test and the Pages deploy are all
  sync-off.
- `src/main.jsx`: `if (__SYNC__) import('./sync/boot.jsx')… else <App />`. With the flag false the branch and its
  dynamic import are dropped from the bundle. Checked on the built files (`src/sync/builds.test.js`): the Pages bundle
  contains none of `/api/`, `Log in`, `workout-sync-v1`, `serviceWorker`, `x-workout-request`, `sw.js`, and there is no
  `sw.js` file. What the Pages build does gain is inert: `subscribeSaved` in persistence (no subscriber), a `sync` prop
  on `App`/`StoreProvider` (null), `<SyncSection />` on Settings (renders null with no engine), and `subscribeNoteSaved`
  in dev-notes (no subscriber).

### Where sync hooks in

- `src/persistence.js` `saveState` → `notifySaved(state)` after the write: one hook, not one per action. It does not
  fire while `loadUnreadable` is set (it returns before that). It **does** fire after a write that failed on quota,
  because the server copy is then the only one. A listener that throws is caught.
- `src/store.jsx` `StoreProvider({ sync })` attaches the engine while mounted. The engine takes the server's copy
  through the same `setState` as an updater on the latest state, so the result is saved like any other change.
- `src/sync/engine.js` holds all the sync logic. Everything it uses is injected (fetch, storage, timers, load/save), so
  it is tested under `node --test`. It keeps its own key `workout-sync-v1` with `{user, syncedUser, rev, syncedAt, dirty,
  notesDirty, expired}`. That key is separate from `workout-mvp-v9` and is not watched by the other-tab banner.
  - Triggers: each save (debounced `DEBOUNCE_MS = 2000`), mount (open), `online`, and `visibilitychange` (both visible
    and hidden: hidden sends anything waiting).
  - If something changed locally, the engine sends `PUT {baseRev, state}`. Otherwise it sends `GET` and takes a newer
    rev if there is one.
  - **One request at a time.** A sync asked for while one is in flight runs after it, using the rev the first one
    returned.
  - **A change made during a flight is rebased, not overwritten.** The engine runs `mergeStates(sent, local, server)`,
    the server's own merge, now shared from `src/sync/merge.js`. Local changes win; the result is then sent.
  - **Unreadable data:** `request()` is the single choke point. While `isUnreadable()` is true, nothing leaves the app:
    no sync, no login, no logout POST, no notes.
  - **401:** `expired = true`. A banner says "You're logged out on the server — log in to sync. Everything is still
    saved on this phone." with a Log in button. Local data is never touched, and no requests are sent until the user
    logs in again.
  - **Network errors / 5xx:** the engine retries on a timer at 5 s, 20 s and 60 s, then stops. A save, opening the
    app, or coming back online still retries.
  - **Oversized upload:** the body is measured in bytes before sending. Anything over `MAX_BYTES` (=
    `server/app.mjs MAX_BODY`, test-asserted) is never sent, and a 413 is treated the same way. The result is a clear
    status ("Not synced — too much data to send (N MB; the server takes 20 MB). It's saved on this phone.") with no
    retry timer. The next change that fits clears it.
- **First login (DEC-132 §1):** this applies when `syncedUser ≠ username`. The engine does `GET /api/state`. If the
  account has data (rev > 0), the device takes the server's copy (`saveState`) with no PUT. If the account is empty
  (rev 0), the engine sends one `PUT {baseRev: 0}` with the device's data, as a fast-forward. So the baseRev-0 merge
  path is never taken on first login.
- **Same user again** (after a logout or a 401): this is a normal sync, so anything made while logged out goes up.
- **Logout (DEC-132 §3):** the POST is best-effort and never awaited, so logging out works offline. `user = null`
  shows the login screen. `workout-mvp-v9` and `dirty` stay as they are.
- **Feedback notes (§9):** `saveNote` → `subscribeNoteSaved` → `notesDirty`. The next sync POSTs the whole on-device
  list as `{notes}`; the server dedupes it. The on-device list and its export are unchanged.

### UI (server build only)

- `src/sync/root.jsx` `SyncRoot` decides what to show:
  - No user on this device → `LoginScreen` (Username, Password, Log in on the right).
  - No user, but stored data unreadable → the app under its existing banner, so Import stays reachable and nothing is
    sent. `boot.jsx` calls `loadState()` first so the unreadable flag is known before choosing.
  - `expired` → the banner above, plus Log in. The login screen then has Cancel on the left.
- `src/sync/settings.jsx` adds, on Backup & data: a "Sync" header, one line (`Synced · just now / N min ago / N h ago`,
  or the spec's "Not synced yet — saved on this phone, will send when online", or the too-large / refused failure
  line), and a **Log out** button. There is no conflict banner.

### Offline open (§2)

- `src/sync/sw.js` is the template. The `vite.config.js` `serviceWorker()` plugin (server build only) writes
  `dist-server/sw.js` with the build id and the list of every built file.
  - **Install:** caches `./` plus all built files.
  - **Activate:** deletes older `workout-app-*` caches and calls `clients.claim()`. There is no `skipWaiting`, so a new
    version waits until every tab is closed and takes over on the next open.
  - **Fetch:** `/api/*`, non-GET requests and other origins pass straight to the network. Navigation is served from the
    cached `./` (cache first). Other files are served from the cache, falling back to the network.
- Registration is in `boot.jsx`.
  - **Bug found by the headless run:** a `load` listener alone never fired, because `boot.jsx` arrives by dynamic
    import after `load` has already happened.
  - Fix: register now if `document.readyState === 'complete'`, otherwise on `load`.

### Server changes (all required by the spec)

- **Same-origin app:** `server/app.mjs` serves any non-`/api` GET/HEAD from `appDir`.
  - `appDir` comes from `WORKOUT_APP_DIR`, default `<repo>/dist-server` (`config.mjs`); `start.mjs` passes it.
  - `/` → `index.html`. `assets/*` are `immutable`; everything else is `no-cache`.
  - Path traversal (including encoded `..`) and NUL bytes → 404. No auth on the app shell, since it holds no data.
- **Proxied same-origin guard:** tested with `Host: 127.0.0.1:8100`, `X-Forwarded-Host: mac.tailnet.ts.net:8446`,
  `Origin: https://mac.tailnet.ts.net:8446` → accepted; a foreign Origin → 403. No guard change was needed. What
  `tailscale serve` actually sends is [inferred]: Go's ReverseProxy sets X-Forwarded-Host to the incoming Host. It is
  not run here (rule 2).
- **Password ≥ 6 (DEC-132 §4):** `auth.mjs PASSWORD_MIN = 6`.
- **Merge moved:** `server/merge.mjs` → `src/sync/merge.js`, and `server/merge.mjs` re-exports it. The only code change
  is the equality function: `node:util isDeepStrictEqual` → `src/sync/equal.js deepEqual`, because the browser can't
  import `node:util`. The two agree on 20,000 generated pairs plus real states (`equal.test.js`), and all 54 req-229
  server tests still pass on it.
- **Revision growth (Builder's choice: prune):** `store.mjs pruneRevisions` runs in the same PUT transaction that adds
  a revision.
  - It **keeps** every revision from the last `PRUNE_DAYS = 14` days, the newest revision of each older UTC day, every
    revision with conflicts (the losing versions), and the current one.
  - A device whose base was pruned (offline for more than 14 days with unsynced changes) merges against the newest kept
    revision before it. The result is at worst extra conflicts (incoming wins, the server version is kept), never
    silent loss.
  - Rough size: about 200 kB per revision × about 40 per workout → about 30 MB rolling for 14 days, then about 1 per
    day (~70 MB/year) [inferred arithmetic].

### Choices the spec left open (for DECISIONS)

1. **Build switch:** `WORKOUT_SYNC=true` → `__SYNC__`; `GITHUB_PAGES=true` always wins; default off.
   `npm run build:server` → `dist-server/`; the server serves `WORKOUT_APP_DIR` (default `<repo>/dist-server`).
2. **Sync meta key** `workout-sync-v1`, separate from `workout-mvp-v9` (no schema change).
3. **Debounce** 2000 ms. A sync also runs when the page is hidden (sends what's waiting).
4. **With no local change, a sync is a `GET`** (no PUT of the whole doc). Right after login the app's open check makes
   one extra GET.
5. **Bounded retries** at 5 s / 20 s / 60 s for network errors and 5xx. Triggers (save, open, online, visible) always
   retry. **A 400 or 409 shows "Not synced — the server refused it: …"** and is not retried until the next change.
6. **Revision growth: prune** in the PUT transaction. Kept: the last 14 days, the newest revision per older UTC day,
   every revision with conflicts, and the current one. A pruned base falls back to the newest kept revision before it.
7. **Merge shared:** moved to `src/sync/merge.js` with a browser-safe `deepEqual` (equivalence-tested).
   `server/merge.mjs` re-exports it.
8. **"First login"** = this device never synced as this username (`syncedUser`). The same user after a logout or a 401
   gets a normal sync.
9. **Login screen** blocks the app when no user is logged in on the device, **except** when the stored data is
   unreadable. Then the app opens under its banner (Import reachable) and nothing is sent.
10. **401 prompt** is a banner over the open app with a Log in button, not a blocking screen (never block logging).
    Its copy (unconfirmed): "You're logged out on the server — log in to sync. Everything is still saved on this
    phone."
11. **Settings:** a "Sync" header, the one line, and a "Log out" button. Logout has no confirm. Relative time reads
    "just now / N min ago / N h ago / N days ago". Failure copy is mine (unconfirmed).
12. **Service worker:** cache-first, every built file precached, no `skipWaiting` (a new version on the next open after
    all tabs close — the spec's "(unconfirmed)" call). The server sends `no-cache` for `index.html`/`sw.js` and
    `immutable` for `/assets/*`.
13. **Notes** are sent as the whole on-device list (the server dedupes on timestamp + text). Notes without a timestamp
    or text are skipped.
14. **A save that fails on quota still notifies sync**, so the server gets the change the phone couldn't store.
