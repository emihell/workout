# req-228 — the test suite gives the same result on any machine locale

## Technical

**Mechanism: a test-only side-effect module, `src/test-support/locale.js`, imported by the tests that assert date text.**
It wraps `Date.prototype.toLocaleDateString / toLocaleTimeString / toLocaleString` and `Intl.DateTimeFormat` so a call
that passes **no** locale (`undefined`) formats as `en-US`; an explicit locale passes through untouched.

Why not pin `LANG` in `./check`: V8 reads the default locale from the environment once at process start and has no
runtime setter, and plain `node --test` inherits the shell's `LANG` — an env pin in `./check` would leave the hand-run
`node --test` red on Emilio's en-GB Mac. Why not pass a locale from the tests: the app functions
(`src/views/history/helpers.js:70,98,126,208`, `src/views/schedule-day.js:78`) take no locale argument, so that would
mean changing app code (out of scope). App code is unchanged: the user still sees the phone's locale.

Files: new `src/test-support/locale.js`; one import line each in `src/req-200.test.js`, `src/req-203.test.js`,
`src/req-209.test.js`, `src/req-224.test.js`. No assertion was edited. The module is not in the build
(`grep -r __req228Pinned dist` → no hits).
