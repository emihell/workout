## Technical

- `plan brief req-N [--base <ref>]` (`cmd_brief` in `plan`): finds `handoff/work/req-N-*.md` (or the folder's `README.md`) in
  the checkout it runs from, checks that `--base` resolves (default `main`), and prints the prompt: the req path, `git checkout
  -b req-N <base>`, "Read handoff/BUILDER.md first and follow it", the four mechanical lines (one line each), and the report
  shape. Exit 1 for a missing doc, a bad id, a base that isn't a ref, or no `.nvmrc`. Read-only.
- Node version: `.nvmrc` (`22.23`) resolves to the highest installed `~/.nvm/versions/node/v22.23` or `v22.23.x`
  (`nvm_node_dir`, `sort -V`). `v22.230.0` doesn't match (tested with a fake `HOME`). If nothing is installed, it prints
  `v<nvmrc>` and a warning on stderr.
- `plan closeout`: new step 2a, before the reviewer check and before any merge. It reads `reports/req-N.md` from the
  **branch** (`git show <branch>:…`, not the working tree). It refuses with exit 1 when the file is missing, when `## What I
  ran` has no fenced block with a non-blank line, or when `## For Emilio` is missing. Headings are only counted outside
  fences, as in white-sleeve. The parser is white-sleeve's split-and-scan, ported into `report_receipt_problems`. It is
  skipped on the re-run path (already merged), the same way the reviewer check is.
- Tests: 10 new scenarios in `scripts/plan-guards.test.sh`, the existing scratch two-worktree style (no new test file).

Choices the spec left open:
1. **The node_modules line prints BUILDER.md's literal path** (`~/projects/workout/workout-codebase/node_modules`). It is not
   derived from `git worktree list`. I tried deriving it with `find_worktrees`, but this machine has an extra top-level
   scratch worktree, and the derived path pointed at that scratchpad checkout [measured: the first `./plan brief 250` run
   printed `.../scratchpad/wt-wf/node_modules`]. That is a latent `find_worktrees` weakness (last non-planning top-level
   worktree wins) and is not fixed here.
2. **`## For Emilio` items are not checked for tags.** BUILDER.md asks for `[feel]`/`[device]`/`[blocked]` tags, and white-sleeve
   enforces its own tag set. The req asks only that the section exists ("may say nothing"), so I left tag enforcement out.
3. **No bypass flag** for the receipt refusal, matching white-sleeve's "no bypass". You fix the report on the branch instead.
4. **`plan brief` with a base that doesn't resolve exits 1.** The spec didn't say what should happen here.
5. The brief also prints a "Report:" line and a "Report back" line. Neither contains the four grep keywords, so criterion 1
   still counts 4.
