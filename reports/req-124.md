# req-124 — Replace lands on the new exercise

## Technical

- `src/storage.js` — new `replaceItemInState(s, itemId, exerciseId, id)`: the req-109 reducer moved out of
  `store.jsx`, logic the same, so `node --test` can reach it. When there is no active workout, or the exercise or item
  is unknown, it returns `s` itself (the same object).
- `src/store.jsx` — `replaceItem` generates `uid('mid')` before the updater, runs the reducer, and returns the id.
  The imports it no longer needs (`historyPrescription`, `itemKey`, `replaceItemPatch`, `replacementItem`) are removed.
- `src/views/workout/replace.jsx` — `pick` goes to `itemLogPath(routineId, { id: newKey })` with `{ replace: true }`.
  **Second fix, not named in the spec:** after the pick, the original counts as done (skipped), so the picker's
  existing done-bounce effect (`useEffect … go('/workout/:r')`) fired *after* the pick and overrode the navigation.
  Puppeteer caught it: the first run landed on `#/workout/r1 | Push`. A `picked` ref now stops the bounce once a pick
  has happened. The bounce is unchanged for an item that was already done when the picker opened.
- `src/req-124.test.js` (new, 3 tests): the id given to the reducer becomes the inserted item's key and that item is in
  the snapshot; a failed replace inserts nothing; a source check on the store's return and on the picker's navigation
  and bounce guard.

**Callers of `replaceItem`:** only `replace.jsx` `pick` (`grep -rn "replaceItem(" src`). Its return value was unused
before this change. `skip-replace.test.js` and `req-119.test.js` still pass unchanged. No test was edited.

**Verified**
- `node --test src/req-124.test.js` → 3 pass, 0 fail.
- `./check` → `check: green — lint, 38 test file(s), and the build all passed.`
- Puppeteer, dev server, seeded v9 state with an active workout (Chest Press, Pec Fly in the library):
  ```
  picker: #/workout/r1/item/ri-a/replace | Replace exercise
  after Cancel: #/workout/r1/item/ri-a/log | Chest Press
  items: Chest Press:ri-a, Pec Fly:mid-muedvc1v-nz3prc
  after Replace: #/workout/r1/item/mid-muedvc1v-nz3prc/log | Pec Fly
  new key in URL: true
  page errors: none
  ```
- No schema change and no migration. Only the shape of the store API changed.

**Choice left open:** if the store's replace fails (the exercise or item disappears between render and click), the
returned id matches no item and the log route shows the MissingItem screen. Before, it went to the overview. The
picker only offers exercises and items that exist when it renders, so I did not add a check before the call.

## Workflow

- The spec's Scope did not name the bounce-effect guard, but without it the change does nothing (see above). It
  stays within `replace.jsx`, a file the spec lists.
- Moving the reducer into `storage.js` follows the req-119 pattern (the delete reducers moved there). It means
  `storage.js` now appears in the diff, which may matter for DEC-057 reviewer triggers.
