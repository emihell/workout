# req-211 — "Change day" from Home moves one date only

Branch `req-211` off `main` 3256b63 (includes req-210's merge). Data lane. Code commit `f0ee25d`. This report is in the
follow-up commit.

## What is stored (for Emilio, before merge)

**Export a backup first** (Backup & data → Back up now) before you try this branch on your real data.

- **One new optional field: `schedule.moves`.** It is a list of one-date moves. Each one is `{ id, slotId, from, to }`:
  - `slotId`: which scheduled workout;
  - `from`: the date it was on;
  - `to`: the date it is on instead, that one week only.

  Both dates are `YYYY-MM-DD`.
- **Example record** (Push / Pull moved from Fri Oct 16 to Thu Oct 15; taken from the browser check):
  `{ "id": "move-mv7tkqrw-s0i397", "slotId": "slot-sess-push-pull", "from": "2026-10-16", "to": "2026-10-15" }`
- **0 existing records change.**
  - There is no version bump: the key stays `workout-mvp-v9`.
  - Loading an existing v9 store writes nothing. A test checks that the stored string is byte-identical after load.
  - A store without the field reads as "no moves". The next ordinary save adds `"moves": []` to the schedule object. No
    slot, workout or routine changes.
- Only one action writes a move: ⋯ → Change day on a day screen opened from Home.
- Removing a workout from a day also removes that slot's moves.
- An export carries the moves. On import, a broken `moves` is dropped and everything else is kept.

## Technical

**What changed**
- `schedule.js`:
  - `slotsOn(schedule, date)` applies the moves. A slot with `from = date` is left out. A slot with `to = date` is
    included, whatever its own weekday.
  - New: `scheduleMoves` (absent or non-array → []) and `moveInto(schedule, slotId, date)`.
  - `comingDays`, Home's today block and the dated day screen all go through `slotsOn`.
- `model.js`: `migrateState` sets `schedule.moves = normaliseMoves(source.schedule.moves, slots)`.
  - A non-array becomes [].
  - An entry is kept only if it is a plain object with a non-empty string `id`, a `slotId` that names an existing
    slot, and two real, different `YYYY-MM-DD` dates.
  - Only those four fields are kept.
  - The slot mapping was hoisted into a `slots` const so moves can check it. Its output is unchanged.
- `state-reducers.js`:
  - `slotRemovedState` drops the slot's moves.
  - New `slotMovedOnDateState(s, { id, slotId, date, to })`:
    - It adds `{ id, slotId, from: date, to }`.
    - A slot already moved onto `date` keeps its original `from`, and its move is replaced.
    - Moving back to that `from` removes the move.
    - `date === to` returns the same state.
- `store.jsx`: new `moveSlotOnDate({ slotId, date, to })`. The id is made outside the updater, as `addSlot` does.
- `views/Schedule.jsx` `ScheduleDay`:
  - A dated screen lists `slotsOn(schedule, date)`. The undated one lists the weekday's slots, as before.
  - On a dated screen, ⋯ → Change day opens the one-date sheet. Choosing a day writes the move and lands on that date's
    screen (`dateDayPath`, keeping `from`).
  - On an undated screen, Change day is req-207's every-week remove + add, unchanged.
  - A moved row carries "moved from Fri" (`.ui-moved`).
  - Remove on a moved row names the slot's own weekday ("Take X off Fridays?"), because Remove takes the recurring slot
    off.
  - `slotOnDay` (the slot page) also accepts a slot moved onto that week and weekday, so the moved row's name link
    opens the slot page and doesn't show "Not on this day."
- `views/schedule-day.js`: pure `oneDateSheet`, `dateDayPath` and `movedFromText`.
- `views/Today.jsx`: a Coming-up row and today's block show "moved from Fri" under a moved workout. When the date has
  two workouts, the sub-line is prefixed with the workout's name.
- `exchange.js`: no code change was needed. Export is the whole state, and import goes through `migrateState`. One
  sentence about `moves` was added to the assistant's schedule description.
- `ui/ui.css`: `.ui-moved` is a caption-size muted block line.

**Choices the spec left open**
- **"From Home" means a dated screen**, i.e. one where `dayScreenDate` returns a date. Every route into a dated screen
  starts at Home.
- **The sheet leaves out a date that already has this workout**, as req-207 leaves out a taken weekday. That avoids a
  duplicate on one date. So the sheet can show fewer than 7 days.
- **A move whose `from` equals its `to` is malformed** and is dropped. Unknown extra fields on a move are not kept.
- **A move on a past date is allowed.** The spec doesn't forbid it, and req-208's past-date row already offered Change
  day.
- **Moves left behind by deleting a workout or shrinking the loop are not pruned by those reducers.** This is
  harmless: `slotsOn` only returns existing slots, and `migrateState` drops such moves on the next load. The contract
  named only `slotRemovedState`.
- **Copy:**
  - The sheet title is "Move {name} to which day?" and its message is "Only this week — the Schedule stays as it is."
    The spec's sentence was split this way.
  - The sub-line is "moved from Fri". Both copy items are `(unconfirmed)` in the spec. `req-201.test.js` passes.

## Review fixes (commit `466e324`)

The independent review found no blockers. It raised two fixes and a nit, all done on this branch.

1. **should-fix: `slotsOn` could show a stray workout after a loop resize.**
   - A move now counts, both hiding the slot on `from` and showing it on `to`, only while its slot is genuinely on
     `move.from`. That means `loopWeekIndex(schedule, from) === slot.week` and `from`'s weekday is `slot.weekday`.
   - The check is in a new private `liveMoves` in `schedule.js`. `moveInto` uses it, and so does the slot page's
     `slotOnDay` (through `moveInto`).
   - A stale move is ignored and never rewritten on load.
2. **latent: `normaliseMoves` tightened.**
   - It keeps at most one move per `(slotId, from)`, and the last one wins.
   - It drops a move whose `to` is not in `from`'s Mon–Sun week.
   - This runs only in memory on load. The byte-identical v9 load test still passes.
3. **nit: the every-week Change day (from the Schedule) also drops that slot's one-date moves.** It removes the slot and
   adds a new one with a new id, and `slotRemovedState` drops the moves of the removed slot.

**New tests** in `src/req-211.test.js` (now `# pass 28 # fail 0`):
