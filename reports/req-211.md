## What is stored (for Emilio, before merge)

**Export a backup first** (Backup & data → Back up now) before trying this branch on your real data.

- **One new optional field: `schedule.moves`.** A list of one-date moves. Each one is:
  `{ id, slotId, from, to }` — which scheduled workout (`slotId`), the date it was on (`from`), and the date it moves
  to for that one week (`to`), both as `YYYY-MM-DD`.
- **Example record** (Upper Body's Friday moved to Thursday, week of Oct 12):
  `{ "id": "move-mgf1x2-ab12cd", "slotId": "slot-sess-upper", "from": "2026-10-16", "to": "2026-10-15" }`
- **0 existing records change.** No version bump (`workout-mvp-v9` stays). Loading an existing store writes nothing
  (test: the stored string is byte-identical after load). A store without the field reads as "no moves".
- The only thing that writes a move is you tapping ⋯ → Change day on a day opened from Home.
- Removing a workout from a day also removes its moves. An export carries the moves; an import with a broken `moves`
  drops only the moves and keeps everything else.
