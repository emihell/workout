# req-225 — Home workout sheet: exercises, Edit, Swap for today

Branch `req-225` (from `main` b85df69). Data lane: a new optional field, `schedule.swaps`. No version bump.

## Technical

### Saved state: what changes, and how many records (ask-gate #2)

- **New field:** `schedule.swaps: [{ id, slotId, date, routineId }]`, `date` 'YYYY-MM-DD'. Optional and additive.
  `SCHEMA_VERSION` stays 9 (the `moves` precedent, req-211).
- **On load: 0 records rewritten.** `migrateState` reads a missing `swaps` as `[]`. A stored v9 string without `swaps` is
  byte-identical after `loadState` (test "a v9 doc without swaps: the stored string is byte-identical after load"). The next
  save for any other reason writes `swaps: []` into `schedule` and changes no record, exactly as `moves: []` did.
- **Per Swap tap:** one entry is appended to `schedule.swaps`. **Per Back tap:** that one entry is removed. Nothing else is
  written. The slots, the routines and the workouts stay the same references.
- **Other writes that drop entries:** `removeSlot` drops that slot's swaps. `removeRoutine` (delete or archive) drops the swaps
  that swap that routine in, and the swaps of the slots it removes. An import that brings a routine back archived drops the same
  swaps.

### What changed

- `model.js`: added `normaliseSwaps(swaps, slots, routines)`, called from `migrateState`. An entry is kept only if it has a
  non-empty string id, a slot that exists, a real date, and a routineId that names an existing, non-archived routine other than
  the slot's own. If several entries share one (slotId, date), the last one wins.
- `schedule.js`: `slotsOn` applies swaps after moves. A swapped slot comes back as `{ ...slot, routineId: swap's,
  swappedFrom: own }`. Added `scheduleSwaps` and `swapOn`.
- `state-reducers.js`:
  - New `slotSwappedOnDateState`: one entry per (slotId, date); swapping to the slot's own routine removes the entry.
  - `slotRemovedState` now drops the slot's swaps.
  - `removeRoutineFromState` now drops the swaps that name the removed routine or one of its removed slots. It only does this
    when a `swaps` array is already present.
- `store.jsx`: new `swapSlotOnDate({ slotId, date, routineId })`. The id is made outside the updater.
- `exchange.js`:
  - `swaps` is documented in `FIELDS.schedule`, a new `FIELDS.scheduleSwap`, the `ASSISTANT.schedule` text and the sample state.
  - Added to `NESTING`, `scheduleOf` and `outsideCounts`.
  - `importResult` drops swaps of removed slots and swaps into a routine brought back archived.
- `views/Today.jsx`:
  - Each pending name in today's block is now a button that opens `WorkoutSheet`.
  - `WorkoutSheet` is a small content sheet in ConfirmSheet's look: the name (plus "swapped from X" when swapped), the exercise
    list, then Edit, Swap for today, Back to X (only when swapped), and Close. Escape and the backdrop also close it.
  - Swap for today switches the sheet to a list of workouts with Cancel.
  - A "swapped from X" mark shows on pending rows, on done rows and on Coming up rows.
- `views/schedule-day.js`: added `swappedFromText`, `swapChoices`, `todaySlotEditPath` and `slotScreenSlot`. `slotStart` now tags
  today's occurrence only when the routine is the one the slot stands for today.
- `views/Schedule.jsx`:
  - `ScheduleSlot` resolves its routine through `slotScreenSlot`, so the editor shows the swapped-in routine.
  - Day-screen rows show "swapped from X".
  - Remove's confirm names the slot's own routine, which is the one that repeats.
- `ui/ui.css`: added the sheet list and scroll styles, and the name button style (inherits font and colour, underlined, at
  least 44 px tall).

### Domino check: every reader of `slotsOn`, and what it sees with a swap

| Reader | With a swap on (slot, today) |
|---|---|
| Home `todays` → `todaySpots`, `TodayPending`, `TodayDone` | The swapped routine: its name, its Start, its coveringWorkout |
| `coveringWorkout` (via callers) | Keyed by the swapped routine + slot id: a workout of the swapped-in routine covers the spot; the original's does not (AC4) |
| `doneEarlier` | Walks the week through slotsOn: the swapped date counts as a spot of the swapped-in routine |
| `otherTodayOccurrences` / `doneInTodayBlock` | Key by occurrence id (slot@date) and by the resolved routine. Consistent with the above |
| `spotStartOptions` / Start → first exercise (req-223) | Same slot/date/occurrence, swapped routine id. Rendered AC9 test: `activeWorkout.routineId = sess-upper`, `occurrenceId = s-thu@2026-10-08`, hash `#/workout/sess-upper…` |
| `comingDays` | Applies a swap on a later date (only an import can create one); the Coming up row says "swapped from" |
| Day screen (dated) | Rows show the swapped routine + "swapped from"; "Change day" `taken` uses swapped ids |
| `slotScreenDate` / `slotStart` | Today's Start is tagged only for the routine the slot stands for today |
| Schedule Whole plan (`slotsForWeekDay`) | Not a slotsOn reader: always the recurring routine |
| Swapped-in routine archived or deleted later | Dropped in-session by `removeRoutineFromState`, and on load by `normaliseSwaps`. Home shows the original (AC7, both paths) |

### Choices the spec left open

- **Sheet layout:**
  - Title is the routine name, with a muted "swapped from X" line when swapped.
  - The exercise list shows each exercise name above the routine editor's own meta line (`routineItemMeta`: role, warm-up,
    `sets × reps`, kg). So it shows kg as well as sets × reps.
  - Buttons are stacked full width: **Edit** (a NavLink in the button look, since it only navigates), **Swap for today**, and
    **Back to {original}** (only when swapped). **Close** is underneath.
  - A long list scrolls inside the sheet (max 45vh).
- **Swap list:**
  - Title "Swap {name} for which workout?", line "Only today — the Schedule stays as it is."
  - Lists every non-archived routine in store (Workouts list) order, except the one shown and the slot's own.
  - **Cancel** goes back to the overview sheet. A pick saves the swap and closes the sheet.
  - No confirm on Swap or Back, because both can be undone.
- **Tap target:** the name itself is a button. It keeps the name's font and colour, is underlined so it reads as tappable, and is
  at least 44 px tall, which makes today's block about 20 px taller per name.
- **Edit route:** `/schedule/{todayWeek}/{todayWeekday}/{slotId}?from=<today's dated day screen ?from=/>`. Back goes to today's
  dated day screen, and Back again goes Home (2 taps; `navForBase` only returns to `from` when it is the day path).
- **Edit on a swapped spot** edits the swapped-in routine (spec's unconfirmed call).

## Workflow

- **A bug I found and fixed in the spec's "Edit via the Schedule slot editor":** `ScheduleSlot` resolves its slot from the raw
  schedule, so on its own it would edit the original routine. The editor's sub-screens (an exercise row, Add exercise) also carry
  no `from` (`routine-nav.js`), so a "dated from only" rule showed "Not found" one tap in. Fix: `slotScreenSlot` uses
  `slotScreenDate`'s rule (the dated `from`, else today when the slot is on today). Consequence: opening today's swapped slot from
  the **Whole plan** also shows the swapped-in routine today, even though the Whole plan row still names the original. Emilio
  may want to look at that.
- **Additions beyond scope, all display-only:**
  - "swapped from X" on today's done rows, on Coming up rows and on dated day-screen rows.
  - The day screen's Remove confirm names the slot's own routine (it said the swapped name, which is wrong for a recurring
    remove).
  - `slotStart` tagging is guarded so a Start of the slot's own routine from the Whole plan isn't tagged as today's swapped spot.
- **Latent, not built:** "Change day" on today's dated day screen for a swapped slot moves the slot, but the swap stays keyed to
  today, so on the new date the slot shows its own routine. Swapping from the day screen is out of scope. A spec should decide
  whether a move carries the swap.
- **In-session archive:** `removeRoutineFromState` now drops affected swaps immediately. The spec only required "dropped on
  load", but without this Home would show an archived routine until reload.
- **Test edits (all listed, none weakened):**
  - `src/test-support/moves.js`: `withEmptyMoves` also adds `swaps: []` to each migrated schedule. The req-158/164/165 goldens
    predate the field (L-053). It is not renamed.
  - `src/req-211.test.js` AC2: also strips `swaps` and asserts it is `[]`.
  - `src/req-181.test.js:278`: expected schedule gains `swaps: []`.
  - `src/req-214.test.js`: today's names are now buttons, so `buttons('Lower Body')[0]` hit the name instead of the
    "which workout?" sheet's choice. The pick is now looked up inside the sheet (`sheetButton`).
- **Environment:** the machine was loaded (load average 5), and one early full `node --test` run with `--test-timeout=60000`
  cancelled 12 files on time alone. Run plainly, `./check` is green. macOS has no `timeout` binary, so a per-file loop with it
  silently ran nothing.

  it from the route plus clock, or carry it in the path.
