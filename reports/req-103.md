# req-103 — routine editor: two-line exercise rows, main unlabelled

Branch `req-103`. Ready to look at, not merged.

## Technical

**What changed**
- `src/ids.js` — new pure `routineItemMeta(item)` builds the meta line
  `[roleTag] · WU set · N set(s) · kg`. It drops empty parts, so no stray `·`. Main is
  unlabelled via `roleTag` (req-93). kg shows only when some suggested weight is > 0, the
  same rule as before. I updated the `roleTag` comment, which used to say the routine
  editor still labels every role.
- `src/views/Routine.jsx:148–170` — the row body is now a `.ui-row__stack`: the name link,
  then a `.ui-row__meta` line. I moved the meta computation out of the JSX and into the
  helper. The `roleLabel` import is gone, since nothing here uses it now. Up/Down are
  unchanged: same action slot, same `moveRoutineExercise` calls.
- `src/ui/ui.css` — `.ui-row__stack` (a column flex), `.ui-row__meta` (caption size,
  `--ui-ink-2`) and `.ui-row__stack > .ui-navlink { padding-left: 0 }`. The last rule
  lines up the name and the meta on one left edge. The link keeps its 44px tap height.

**Choices the spec left open**
- Typography: the meta uses the caption token (13px) and `ink-2`, the same treatment
  as req-93's `.ui-role-tag`.
- Alignment: my first try indented the meta to match the link's padding. At 390px that
  made `kg` wrap onto a third line. Removing the link's left inset instead keeps
  every seeded row on two lines.
- A no-break space joins the weights and `kg` (`25/30/30 kg`), so `kg` can never
  wrap onto a line by itself.

## Workflow

- No scope added or dropped. There are no schema or storage changes.
- Out of scope, surfaced only: `src/views/history/detail.jsx:68` and `:120` still print
  `roleLabel(...)` ("Main") on every History detail row. That is the last place the

- Gotcha worth an `L-`: inside a Row's label, `.ui-navlink` carries a horizontal inset,
  so any second line under a navlink name starts out misaligned. Fixing that by padding
