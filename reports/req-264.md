## Technical

- **(a)** `src/routine-item-change.js`: `changedRoutineItem(item, exerciseId, workouts, exercises = [])`. A change with no
  history whose old and new records are both found and whose `planKind` differs takes `pickerItem([], to).item`'s
  `sets/targets/durations/restSec`, with `suggestedWeights: []`. Everything else on the item stays (id, notes, role,
  warmup). If either record is missing, it falls back to main's rule. The history branch is untouched.
  `changeTakesStartingPlan(from, to)` is exported for the view. `planKind` lives in `src/routine-picker.js`, and
  `pickerItem` now branches on it (same behaviour).
  `store.jsx:120` passes `s.exercises` from inside the same `setState` updater. A library pick's `addExercise` updater runs
  first in the same batch, so the new record is there when it is read.
- **(a) label**: `ExercisePicker`'s `startingLabel` now also takes a function `(plan, exercise) → label`, and a string
  works as before. `RoutineExerciseChange` (`Routine.jsx:~690`) shows the starting-plan label for a kind change and
  `CHANGE_KEEPS_LABEL` otherwise.
- **(b)** `IMPORT_CHOICES`: Keep has `primary: true`, and Replace no longer has `destructive`. `ConfirmSheet`
  (`ui/index.jsx:356`) renders `primary || destructive` as `ui-btn--primary`. No other sheet sets `primary`.
- **(c)** `routineScheduledDaysText` (`state-reducers.js:43`): for a loop longer than one week, slots are grouped by
  weekday, Mon first. A day on in every week 0..loop-1 is shown bare; otherwise there is one "Day (week N)" word per week.
  A 1-week loop takes main's code path unchanged.
- **(d)** `PICKER_GROUP_OVERRIDES = { 'own-burpee': 'Legs' }` in `routine-picker.js`, read only by `staplesByMuscle`.
- **Choices the spec left open:**
  1. Where the override map lives: `routine-picker.js`, exported.
  2. How the store hands over the records: the whole `s.exercises` array, looked up by id inside the pure function.
  3. **Wording for a day on in several but not all weeks:** each week is its own word, e.g. "Mon (week 1), Mon (week 3) and
     Fri (week 2)". I rejected "Mon (weeks 1 and 3)" because its "and" would nest inside the list's "and". The spec only
     says "keeps its week(s)". This should be recorded.
  4. The import choices use a new `primary` flag rather than reusing `destructive`, so "destructive" keeps its meaning
     for any later caller.
- **Test edits (justified):** these assertions encoded the old behaviour that DEC-155 §2 reverses:
  - `req-220.test.js:438`: was Replace = destructive; now Keep = primary and neither is destructive.
  - `req-201.test.js:163`: was `'Mon (week 1) and Mon (week 2)'`; now `'Mon'`, plus a partial-week case.
  - `req-215.test.js:219`: was `/Wed \(week 1\) and Wed \(week 2\)/`; now `/DaysWedDone/`.
- No stored shape or schema change, and no bulk write. A record is written only by the user's own Change tap.
- The reviewer has not been run (store.jsx trigger, Planner runs it).
