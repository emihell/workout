## Review round 1

Three findings, all fixed on this branch (no blockers). `workoutPosition`'s M shrinking back once the reopened original is done
again is left as is (reviewer: acceptable).

**1 (latent → fix) — a locked phone suspends the 30 s tick.** New `src/views/workout/finish-time.js`:
- `useFinishTime(active)` → `{ finish, finishedAtForSave }`. `now` refreshes on the tick, `visibilitychange` (when not hidden),
  `pageshow` and `focus`. `FINISH_TICK_MS` (30 s) moved here from finish.jsx.
- `finishedAtForSave(active, shownNow, tapNow)` (pure): if `tapNow − shownNow > FINISH_STALE_MS` (tick + 5 s = 35 s, strictly
  greater), it re-derives with the tap's time; otherwise it returns the shown time.
- `finish.jsx` uses the hook. Save does `const finishedAt = finishedAtForSave()`, then `store.finishWorkout(…, finishedAt)`. The
  separate line keeps req-152's source guard (`finishWorkout\([^)]*\)\n leaveWorkoutToToday()`) unedited.

**2 (latent → fix) — `store.finishWorkout` validates `finishedAt`.** A given value is used only if
`typeof finishedAt === 'string' && Number.isFinite(Date.parse(finishedAt))`. Anything else falls back to the save-time
`finishTimeFor`.

**3 (nit → fix) — the auto-complete summary uses the same mechanism.**
- `useFinishTime` drives its line and Duration. Stats are now derived each render from a mount-captured prior.
- Both commit paths pass `finishedAtForSave()`. The countdown path commits within 10 s, so it stores the time it shows.
- **Choice:** this changes the countdown path's stored time from the commit instant to the shown (mount) time, which is up to
  10 s earlier.
