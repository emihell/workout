## Technical

1. **Seed (Change 1).** `setLogSeed` / `initialSetFields` take a new `routineKg` input. The work-set chain is: draft >
   override (DEC-052) > **routine kg at that index (> 0)** > carry (only when the routine has none there) > blank.
   - `routineKgFor(item, setType, workIndex)` gives the snapshot's `suggestedWeights[i]` for a work set (`''` when there
     is none) and `undefined` for a warm-up. `undefined` keeps the old history path, so warm-ups stay on history
     (unconfirmed 1).
   - Both callers pass it: the log form (`item.jsx`) and `setPreview`. `grep` shows no other caller.
   - A set added with Add set takes the appended last kg (`withOneMoreSet`, unchanged).
2. **Replacement (step 2).** `replaceItemInState` passes `suggestedWeights: [history's first-set kg]`, or `[]` without
   history.
3. **Offer (Change 3).**
   - `src/routine-update-offer.js` `routineUpdateOffer(active, routines, item)` → `{ routineId, routineName, itemId,
     from, to }` or null. It compares logged, non-skipped work-set kg (> 0) with the **live** routine item, up to that
     item's set count.
   - `store.applyRoutineUpdate(offer)` finds the item by id and writes via `routineItemUpdated({ suggestedWeights })`,
     that routine only.
   - `views/workout/routine-offer.jsx` renders "You did 105/105/100 kg. Routine: 100/100/100. [Update Day A]" under a
     done row on the overview, **and on the auto-finish summary** (see Workflow).
4. **Fill (Change 5).**
   - `src/routine-kg-fill.js` `fillRoutineKgFromHistory(state, { mode, at })`: per weighted item with history kg, for
     `i < min(sets, history sets)` with history kg > 0, `to[i] = history[i]`. Mode `blanks` is option (b), dry run only.
   - `loadState` runs it after migrate and anchor. It writes the marker `routineKgFilledAt` (ISO time) and saves once.
     A marked state is returned unchanged.
   - **A blank device starts marked** (`blankDeviceState`). Without this, routines typed on a new device would be
     overwritten from history on a later reload. The marker is deliberately not in `emptyState()`, which is also the
     merge base for stored values.
   - Verified: the marker survives `migrateState` (its `...source` spread) and Export → Import. An old Export (no
     marker) imports byte-for-byte as before (`applyBackup` unchanged); the fill runs on the next load.
5. **Dry-run script** `scripts/fill-routine-kg.mjs <file>`: `applyBackup` (as an import does), then the same function
   for (a) and (b). It reads only.
6. **Docs.**
   - `.cursor/rules/history-prefill.mdc` rewritten in full (the chain, "never invented", the starting-plan exception,
     the fill).
   - `README.md`: the routine line, the completed-workout line, and a new paragraph in §Recommendation rules.
   - `exchange.js`: the summary line (it said "completed history writes next kg/reps onto the routine", which was
     already stale since DEC-056), the `suggestedWeights` field note, and line 50 (adds the offer).
   - The `handoff/` rule text is Planner's (step 8).

## Workflow

- **Added, needs a look:**
  - **The offer also shows on the auto-finish summary.** When the last exercise is done, the overview is that 10 s
    countdown screen, not the list, so the last exercise's offer would otherwise never appear. Tapping an offer there
    doesn't stop the countdown.
  - **Blank devices start marked** (see Technical 4). This is a safety fix beyond the spec.
- **Choices the spec left open:**
  - The marker is named `routineKgFilledAt`.
  - The fill covers archived routines too (they read history like any other; restoring one later gets consistent kg).
  - A position the routine didn't have yet is padded with 0 ("no weight", req-113).
  - The offer compares up to the routine item's set count (an added set's kg isn't carried back).
  - The offer's text and button are "You did … kg. Routine: … . [Update <routine name>]".
- **Import:** importing an old Export (no marker) fills on the next load, not at import. That keeps the verified import
  round-trip byte-identical.
- **Note for Planner's rule rewrite:** `CLAUDE.md` still says "prefills come only from finished-workout data for that
  same field", which is now wrong for work-set kg. DESIGN §1 needs the same change (spec step 8).
- **For Emilio (backup reminder, DEC-046):** finish or abandon any live workout before loading the new build. A live
  workout keeps its old snapshot kg (unconfirmed 6).
