## Technical

1. **Seed (Change 1).** `setLogSeed` / `initialSetFields` take a new `routineKg` input. The work-set chain is: draft >
   override (DEC-052) > **routine kg at that index (> 0)** > carry (only when the routine has none there) > blank.
   - `routineKgFor(item, setType, workIndex)` gives the snapshot's `suggestedWeights[i]` for a work set (`''` when there
     is none) and `undefined` for a warm-up. `undefined` keeps the old history path, so warm-ups stay on history
     (unconfirmed 1).
   - Both callers pass it: the log form (`item.jsx`) and `setPreview`. `grep` shows no other caller.
   - A set added with Add set takes the appended last kg (`withOneMoreSet`, unchanged).
2. **Replacement (step 2).** `replaceItemInState` passes `suggestedWeights: [history's first-set kg]`, or `[]` without
   history.
3. **Offer (Change 3).**
   - `src/routine-update-offer.js` `routineUpdateOffer(active, routines, item)` → `{ routineId, routineName, itemId,
     from, to }` or null. It compares logged, non-skipped work-set kg (> 0) with the **live** routine item, up to that
     item's set count.
   - `store.applyRoutineUpdate(offer)` finds the item by id and writes via `routineItemUpdated({ suggestedWeights })`,
     that routine only.
   - `views/workout/routine-offer.jsx` renders "You did 105/105/100 kg. Routine: 100/100/100. [Update Day A]" under a
     done row on the overview, **and on the auto-finish summary** (see Workflow).
4. **Fill (Change 5).**
   - `src/routine-kg-fill.js` `fillRoutineKgFromHistory(state, { mode, at })`: per weighted item with history kg, for
     `i < min(sets, history sets)` with history kg > 0, `to[i] = history[i]`. Mode `blanks` is option (b), dry run only.
   - `loadState` runs it **once per device** (revised after review, see Workflow). The marker is its own localStorage
     key, `workout-routine-kg-filled` (ISO time), **not a state field**, so no Import can remove it or trigger a fill.
   - The fill runs **outside** the parse/migrate `try` (`fillOnce`). A throw skips the fill, sets no marker and logs;
     it never raises the "unreadable" banner.
   - The marker is set only once the filled state is saved (`!getSaveFailed()`), so a failed save retries on the next
     load; the fill gives the same result on its own output.
   - **A blank device is marked at start** (`blankDeviceState`), so routines typed on a new device are never filled
     later.
   - `routineKgFilledAt` is removed entirely. It existed only on this unmerged branch (never shipped), so nothing needs
     to ignore it.
5. **Script** `scripts/fill-routine-kg.mjs <file> [--out <copy>]`: `applyBackup` (as an import does), then the same
   function for (a) and (b).
   - The input is only read.
   - `--out` writes a **filled copy**, keeping the backup wrapper, so an old Export can be fixed before importing.
   - It refuses when `--out` is the input file.
6. **Docs.**
   - `.cursor/rules/history-prefill.mdc` rewritten in full (the chain, "never invented", the starting-plan exception,
     the fill).
   - `README.md`: the routine line, the completed-workout line, and a new paragraph in §Recommendation rules.
   - `exchange.js`: the summary line (it said "completed history writes next kg/reps onto the routine", which was
     already stale since DEC-056), the `suggestedWeights` field note, and line 50 (adds the offer).
   - The `handoff/` rule text is Planner's (step 8).

### Review fix (blocker, Planner's call DEC-095) — commit after 740bc82
- **Blocker:** `exchange.js` `stateShape` never named `routineKgFilledAt`, and the assistant returns the whole state.
  An Export → assistant → Import round trip dropped the marker, and the next load filled again, overwriting the kg the
  assistant or the user had set (reviewer's repro: biceps imported `[20,20,20]` → after reload `[10,15,15]`).
- **Fix:** the marker is now a separate per-device localStorage key, `workout-routine-kg-filled`. It is set when the
  fill runs, or at a blank device's start, and no imported doc can trigger a fill. The in-state field is removed.
- **Accepted trade-off:** importing an old Export after the fill keeps that Export's routine kg. The offer after each
  exercise corrects it, or `--out` fixes a copy first.
- **Reviewer's latent issue:** the fill now runs outside the parse/migrate `try`. On a throw it skips, sets no marker,
  and logs `req-178: routine kg fill skipped`.
- **New tests in `req-178.test.js`:**
